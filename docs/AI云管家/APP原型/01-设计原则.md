## 1. 一屏只给一个下一步动作

详情、记录、报告、表单页**底部只有一个主按钮**，说的是"我现在该干什么"，不是"这个对象一共有哪些操作"。

- 动作跟着**状态和角色**走：待整改→去整改，待审→去审核，待确认→去确认，待签→去签字，已归档→只读（无主按钮）。
- 第二个动作进导航栏 `⋯`；**只有弹窗内**允许并列（取消在左、动作在右）。
- 列表页底部只存在**一条**：未选中时是置灰的批量条，选中时是同一条激活——不出现"批量条 + 主按钮"两层。
- 批量条是唯一例外：它表达"选中态"，不是页面主操作。

**两处例外（已定，不再讨论）**

1. **审核/确认态底部允许"决策对"并列**：`26 审核详情`、`32 维保生效确认`、`44 报告冻结审核`、`17 报告签字` 底部为 `驳回 | 通过`（或 `签署`）两个按钮。理由：这两个动作是同一决策的两侧，藏一个等于逼主管多点一次且难发现；`04` 这些页与已建画板均按此写。**代价与约束**：两按钮都定宽（96 / 132）+ gap 12 + 高 52，驳回用 `dangerBg + dangerInk`、不默认聚焦、必须进弹窗；且**这是"决策对"，不是"主操作 + 次要操作"**——页面其它位置不得再出现第二个实心主色块。
   > 本条是对 `09 §七.5`（"驳回放右上 `⋯`"）的**有意偏离**，理由与代价如上；其余页面仍严格"底部一个主按钮"。列表场景的驳回仍走底部批量条左位（`05 §4`）。
2. **批量条**是列表页的唯一例外（见上）。

**检查方法**

1. 遮住底部条，还能一句话说出"这屏要我干什么"吗？说不出 = 没有主操作或有两个。
2. 数实心主色块：一屏 >1 处即违规（审核态的两个按钮里只有一个实心，另一个是危险浅底）。
3. 追问"第二个动作为什么不能进 `⋯`"，答不出就移进去（唯一能答出的是上面的决策对）。

> 来源：`09 §七.5`（原则部分采纳、审核态有意偏离）、`09 D1`、`08 #16`

## 2. 一个对象只有一个详情页

同一种业务对象**全站只有一套详情骨架**，角色只增减动作，不做第二套界面：

| 视角 | 打卡/巡检记录详情 | 与别人不同的地方 |
|---|---|---|
| 巡检员（本人提交） | 同一套 | 无审核按钮；被驳回多「修改重提」；已通过只读 |
| 主管 / 项目经理 | 同一套 | 多「驳回」「审核通过」**两个**按钮，两者都进弹窗（原则 4） |
| 已审核通过 / 已归档 | 同一套 | 全部只读，底部无主按钮 |
| 主管自己提交的 | 同一套 | 不出现审核按钮，改一行「本人提交，不可自审」 |

- 禁止出现"执行人版详情"与"审批人版详情"两个画板、两套字段顺序、两处文案。
- 审批人在详情里看到的逐项证据，就是执行人提交时的同一组卡片（原则 5），只把可点控件变成不可点。
- 列表、通知、深链、AI 助手进入**同一页同一 URL**；不得为大屏/管理视角另做"汇总版详情"。

**检查方法**

1. 全局搜"XX 详情"块：同一对象出现 ≥2 个画板或 ≥2 条路由，即违规（本轮 `13/26/27/35` 共用一套）。
2. 同一对象在列表卡、详情、审核页的字段顺序与 pill 用词是否**逐字一致**？
3. 主管视角与执行人视角两张截图，除按钮外有没有任何一行事实不同？有即违规。

> 来源：`教训 1`、`09 C12`、`08 #61`、`08 #46`

## 3. 列表 = 多选卡 + 常驻批量条 + 明确的退出路径

所有列表页照抄同一骨架（`03-页面模板.md §1`），不按页另设计：

```
导航栏 → 筛选 tabs + 右侧筛选 → 统计行（一次）→ 全选行（AI 代勾提示挂这里）
→ 多选卡片… → 加载更多 → 底部「已选 N 条」+ 批量动作
```

- 三件套：全选（= **当前筛选结果**全选，半选可见）+ 单条勾选 + **AI 低风险默认勾选**。
- **AI 代勾是默认值，不是提交**：可以替你勾上，绝不替你提交；提交必须人点一次并在弹窗里确认（`09 §七.3`）。
- **必须能退出多选**（`09 B1`）：① 全选行左端「清空选择」；② 底部「已选 N 条」里的 N 可点 → **已选清单半屏**，可逐条取消。**没有退出路径就等于没做这条。**
- 底部条**常驻置灰、不隐藏**：未选中时压到 56 高、只显示「已选 0 条」+ 一个禁用主按钮；点置灰条给 toast「先勾选记录」（隐藏会让新用户永远不知道有批量能力）。
- 卡片左侧独立选择列（视觉 22×22，热区 48×48，列宽 48）；**整卡可点进详情**，卡内只留"这一张最常用的那一个"动作，且它吞掉点击事件、点了不进详情。
- 筛选 / 切片变化 → 清空已选 + toast「筛选已变，选择已清空」。
- 例外只有 `02 我的任务`：四类任务动作各异、批量无意义，不加选择框（审计第 7 条）。

**检查方法**

1. 不选任何一条，底部条还在吗？点了有反应吗？（应：在、置灰、给 toast）
2. 勾了 5 条之后，几步能全部取消？（应 ≤2 步，且存在已选清单）
3. AI 代勾的条数在屏上写清了吗？有没有任何路径能在无人工点击的情况下把勾选项提交？
4. 点卡片空白处进详情，点选择框只选中，点卡内快捷动作只执行——三者互不误触吗？

> 来源：`教训 2`、`09 B1`、`09 B3`、`09 B6`、`09 B10`、`09 B12`、`08 #15`

## 4. 会留下下游事实的动作弹窗阻断；可自恢复的动作给撤销；两者不许叠加

- **必须弹窗**：审核通过、驳回、签字、归档、删除/作废、批量处理、维保生效确认、派单。**页面上不放内联意见框。**
- **不要弹窗**：切筛选、清筛选、取消选择、删未提交的草稿照片、刷新列表、看大图。
- 弹窗固定写三件事：**对谁 + 几条**（标题，如「将通过 5 条记录」）、**输入**（驳回原因必填 + 常用原因 chips）、**按钮写结果**（「通过 5 条」「驳回并通知」，不写"确定/是"）。
- 通过 = 确认弹窗（备注可选、单一主按钮）；驳回 = 原因必填弹窗（未填时提示 + 按钮置灰，危险色 + 与「取消」gap ≥24、不同宽、不默认聚焦、不用主色）。
- **结果反馈分两类，不叠加**：
  - 会产生下游事实的（审核通过/驳回/签字/归档/批量处理/维保确认）→ 只给"已完成 + 去查看"，**不给撤销**（撤销要连带回滚工单池/台账/归档件）。
  - 纯本地或可自恢复的（取消选择、删草稿、清筛选、抢单认领）→ 不弹窗，给 **5s** 撤销 toast（抢单 10s）。
- 批量弹窗必须写清**条数 + 其中含异常数**，并给「查看这 N 条」入口；缺这条就是"你确定要继续吗"式空确认。
- 禁止"弹窗确认 + 再给撤销"叠加：既慢又乱，还让用户以为弹窗可跳过。

**检查方法**

1. 这个动作执行完会写别处的数据吗？会 → 必须有弹窗，且不许有撤销条；不会 → 不许有弹窗，必须有撤销条或零反馈。
2. 弹窗标题里有没有"条数 + 对象"？按钮是不是"确定/是/OK"？（是即违规）
3. 未填驳回原因时，按钮是否置灰 + 就地红字提示，而不是弹第二个提示框？
4. 危险按钮与「取消」的间距量出来 ≥24 吗？焦点默认在「取消」上吗？

> 来源：`教训 3`、`09 D1`、`09 D2`、`09 D3`、`09 D4`、`09 D5`、`09 §七.4`、`08 #54`、`08 #18`、`08 #57`、`08 #58`

## 5. 现场事实只采一次：单件必核验、整批不打卡、一页一提交

- **单件要核验**：每台设备 / 每张单件的到场与作业各一次核验（扫码 / NFC / 围栏，按点位配置可组合），核验记录带时间、坐标、方式。
- **整批 / 打包工单不打卡**：批量维保、批量整改只做**单件核验 + 逐台实时拍照**，不做整单一次打卡。
- **逐台实时拍照**：照片来自相机当场拍摄（带时间地点水印）；相册上传只允许出现在明确标了「非实时」的补充证据位。
- **不允许分批提交**：一页表单一次提交；草稿只用于断网恢复，不作为"先交一部分"的通道。
- **逐项结论沿用打卡页卡片**，字段顺序永久固定，任何页面（打卡、记录详情、审核详情、工单引用）都一样：

```
标题 → 标准 → 照片（含时间地点水印）→ 结论（正常/异常分段）→ AI 预判（一行）→ 异常观察点 → 备注
```

- 只读态 = 同样的卡片、同样的顺序、同样的信息，控件不可点、无"添加照片"位。**不允许**压成"一行文字 + 状态 pill"的摘要行——审批人要判断的就是这些字段。

**检查方法**

1. 这批单是整批打卡还是逐台核验？如果一个核验凭证覆盖了 N 台设备，违规。
2. 照片能不能从相册选？（能，且没有「非实时」标注 = 违规）
3. 只读截图与可编辑截图并排比对：字段、顺序、行数是否完全一致？
4. 有没有"提交已填的 2 项"这类部分提交入口？有即违规。

> 来源：`教训 7`、`09 C6`、`09 C11`、`08 #41`、`08 #61`、`05-全局交互约定.md §2`

## 6. UI 不写规则说明与解释

- 不写"提交后待主管审核""审核通过后才进工单池""已开启复查""还有 38 项未查才能送审""默认混合推荐""20% 抽查比例"。
- 不写配置状态与设备状态解释：`GPS 已关`、`定位权限未授予`这类话不进业务页（权限提示只出现在需要它的那个动作上，一行 +「去设置」）。
- 不写能力说明：`拍照后自动带时间水印`、`换完逐台勾选，新标签日期要拍全`——水印和强制项直接用视觉与置灰表达。
- 规则只在后台配置页出现；App 用**状态 pill + 置灰按钮 + 按钮上方阻断原因行**表达结果。
- 阻断原因 ≠ 按钮文案：按钮只说动作（「提交本点位」），缺什么分行列在按钮上方，并能定位到具体那一张卡。
- 不写信任性说教（"这不是快捷键"）、不写威胁性提示（"操作将被审计"）。

**检查方法**：屏上逐句读，凡是"解释系统怎么运作"而不是"这是什么 / 该点哪"的句子，删掉。一句都删不掉的屏才算过。

> 来源：`教训 5`、`08 #5`、`08 #11`、`08 #32`、`08 #40`、`08 #71`、`08 #78`、`09 D11`、`09 D12`

## 7. 一条右边线、一个图标槽、一组定宽按钮

- **一条右边线**：x = 卡左边界 + 342（卡宽 358 − 右内边距 16）。时间 / 单号 / 状态 pill / 数值一律贴这条线，跨卡对齐。
- 列表卡左侧的 48 选择列 + 10 列间距**从左边占用**，文字宽降到 268，**右边线位置不变**（`06 §3`）。
- 图标统一进 **22×24 固定槽**，图形 16~18 居中；短文本不设固定宽（设了就会逼出碎值）。
- 并排按钮**定宽（84 / 96 / 108）+ 固定 gap 12**，不按剩余宽度拉伸，高度 ≥48；危险动作与「取消」gap ≥24。
- 卡片骨架固定四层：标题层 → 媒体/关键字段层 → 主操作层 → 条件详情层（只在对应状态展开）。

**检查方法**

1. 拿直尺（或量像素）比三张卡右侧：时间、pill、数值落在同一条竖线上吗？
2. 本屏所有图标的外框是否都是 22×24？有没有 15 / 17 / 20 这类自由尺寸？
3. 并排按钮宽度是不是从同一组（84/96/108）里取的？有没有按 `flex:1` 拉的？

> 来源：`教训 10`、`09 B7`、`09 C2`

## 8. 一信息只出现一次

同一事实在同一屏只出现一次，重复即删：

- 顶部「逾期 2 项」与卡内「逾期 2 天」——留一处（卡内 pill 写「已逾期」不带天数）。
- 「待核验」顶部条 + 卡内 pill + section 标题「1 台设备」——留卡内 pill。
- 「共 N 项 / 已选 N 条」只出现在统计行或底部条，不同时出现。
- 指纹信息（谁、何时、何地）只写在卡片的一句事实行里，不在标题、pill、页脚三处复述。
- 同一入口不给两个去路（「更多」与「全部指标」取一；通知条右侧「更多」删掉，整条可点）。

**检查方法**：把屏上所有数字与状态词列成清单，凡出现两次的删一处；再看有没有两个控件通向同一页面。

> 来源：`教训 10`、`08 #9`、`08 #19`、`08 #31`、`08 #70`

## 9. 可达性是硬指标：分段控件、48 热区、正文 15、对比度 4.5:1

- 「正常 / 有异常」是每天点几百次的动作，用**两个等宽、≥48 高的分段按钮**（正常=绿填充、异常=红填充），不用小圆点单选/Switch，不默认选中；AI 预选要显式标"AI 判定"来源。三重编码：颜色 + 文字 + 图标。
- **所有可点区域 ≥48×48**：视觉可 22~23，热区靠透明 padding 补足，**不靠相邻重叠**扩大；相邻可点目标间距 ≥12。
- **字号只有八档：26 / 22 / 17 / 16 / 15 / 14 / 13 / 12**（另：底栏文字 11 合法；角标计数与照片水印 10 是唯一例外）。
  **正文档位 15**；14 只给时间戳、单号、计量单位；13/12 只给 pill 与卡内小注。设置里的「大字模式」把正文拉到 17、次要 13→15、行高 +2，**不新增档位**。
- **对比度**：正文 ≥4.5:1、大字与图形/控件边界 ≥3:1。实测 `#86909C` 白底仅 **3.2:1**，**不再用作正文色**；正文次要灰改 `#6B7385`（4.7:1）。`#C9CDD4`（1.6:1）只做装饰，不得做文字或可交互控件边界。
- 状态不只靠颜色：状态 pill 内必须有字，红绿之外还有文字与图标。
  > 本条规定**取代** `02-App框架与UI布局.md §7`「只用 13/14/16/18 四档」。旧四档的 18 不再使用。

**检查方法**

1. 拿色值算一遍：本屏 12~15 号灰字在白底 / 灰底上够 4.5:1 吗？（量具与实测表见 `06 §1`）
2. 逐个点位上手指：有没有一个可点东西的实际热区小于 48×48？
3. 字号只用了八档（+11、+10 例外）吗？14 号有没有被当正文用？
4. 200% 放大或系统大字号下会裁字、重叠吗？

> 来源：`教训 8`、`09 E1`、`09 E2`、`09 E3`、`09 E4`、`09 §七.7`、`09 §七.9`

## 10. 角色差异靠增删动作，不靠隐藏信息

四个角色：**巡检员 / 主管（含项目经理）/ 维保工 / 租户管理员**。每页在 `04-逐页交互清单.md` 标注可见角色。

- 界面差异只体现在"有没有这个按钮、这个 Tab、这个列表项"，**不体现在同一页少几行事实**——看得见却点不动的按钮一律不画。
- 无权限不是空态：不给入口（宫格不出现），深链进来给"无权访问 + 返回"，与"无数据"分开表达（原则 11）。
- 主管减负优先于信息完整：能合并的同类审核合并，能批量预填的不让人逐条点，但**批量通过仍需一次人工确认**。

**检查方法**：同一页四个角色各出一张图，逐行比对——除了按钮与 Tab，有没有任何一行信息只对部分角色显示？有就要么全给，要么改成按钮级差异。

> 来源：`09 E5`、`08 #1`

## 11. 空态三分：无数据 / 筛选无结果 / 无权限

三种"空"必须分开写，**禁止共用一句"暂无数据"**（`09 B9`）：

| 态 | 文案 | 动作 |
|---|---|---|
| 无数据 | 「今天暂无待审」 | 一个可做的下一步（返回 / 去工单池 / 去建点位） |
| 筛选无结果 | 「当前筛选无记录」 | 「清空筛选」（留在本页） |
| 无权限 | 「你没有查看该范围的权限」 | 返回；**不出现"去申请"这类假动作** |

- 不显示 0 当空数据；加载用与真卡同高的骨架（>3s 加一行"网络较慢"）；失败给"发生了什么 + 下一步"。
- 刷新保留旧数据 + 顶部细进度条，不清空重绘。
- 空态图形用 32 图标 + 一句说明 + 一个动作，不放大插画。

**检查方法**：把列表筛到无结果、换到无权限账号、清空数据库各看一次，三张截图的文案与动作是不是三套？共用一套即违规。

> 来源：`教训 9`、`09 B9`、`09 §七.12`、`08 #8`

## 12. 只画有依据的功能；扫一扫是常驻唯一入口

- **不做凭空功能**：每个入口、按钮、字段必须能在 `04-逐页交互清单.md` 或 `docs/品管家/` 现有设计里找到依据。找不到依据的不画（例：登录页不做"扫码登录"；主页不做"语音下单"；后台没有的能力不在 App 造入口）。
- **扫一扫常驻**：固定挂在主页顶栏右侧，全站**唯一**主入口；二级页不重复放扫码图标。
- **一个扫码页服务三种用途**（打卡 / 工单核验 / 设备查询），靠入口参数区分、扫后各自回跳，**不新建第二套扫码界面**（`05 §1`）。
- **扫码必须有兜底**：失败落 `63 扫码与核验失败`（非本点位码 / 围栏不符 / 定位失败 / NFC 未识别 / 码已作废五类），动作只给「重扫 / 输入编码 / 联系管理员」。**任何情况下不提供"免核验继续"。**

**检查方法**

1. 给屏上每个可点元素写一列"依据"（`04` 的哪一段 / 哪份方案 §），空着的那条删掉。
2. 全站数扫码入口：>1 个主入口即违规；核验/查询是不是都落在同一个扫码页？
3. 把相机与定位都关掉走一遍：能不能自愈？有没有"免核验继续"的后门？

> 来源：`教训 4`、`教训 6`、`09 A2`、`09 E5`、`08 #46`
