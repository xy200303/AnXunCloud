# 03 页面模板

五类骨架，覆盖 69 页里的 66 页（余下 3 页是登录、扫码、兜底状态，见 §6）。新建屏先选骨架，**不许另起一套**；骨架只允许"增删字段"，不允许改层序。

- 通用规则（弹窗、批量、撤销、三态、深链、离线）只在 `05-全局交互约定.md` 定义；本文只写"骨架长什么样、哪一层放什么"。
- 每节末尾的 `> 来源` 标注本轮改动依据：`09 §X` = 外部准则条目、`08 #N` = 审计缺陷号、`教训 N` = `01-设计原则.md` 文末对照表。

## 1. 列表模板（多选卡片）

用于：`02 06 08 11 14 16 18 19 20 21 24 31 33 38 45 46 58 62 69` 等所有列表页。

```
┌─────────────────────────────────────────┐
│ ←  页面名(17)                    [筛选]  │  导航栏（右侧至多一个图标）
├─────────────────────────────────────────┤
│ [全部 12] [待审 5] [异常 3]   ⌄         │  筛选 tabs（胶囊行 44 高，可横滑）
├─────────────────────────────────────────┤
│ 5 条待审 · 含异常 3 条                   │  统计行（整屏只出现一次）
├─────────────────────────────────────────┤
│ ☐ 全选 24 条    AI 已勾选 3 条  清空选择 │  全选行（半选态；AI 提示挂这里）
├─────────────────────────────────────────┤
│ ☑ │1栋1楼大厅消火栓         待审 08-14 │  多选卡：选择列 48（视觉 22×22）
│   │王强 · 5 项检查 · 异常 2 项          │  一句事实行
│   │⚠ 水带缺 1 盘               [异常]   │  要点行（一行一个，标签贴右边线）
│   │✧ AI 与巡检员一致                    │  AI 一行（有才出现）
│   │                          [通过]     │  卡内唯一快捷动作（可省，吞点击）
├─────────────────────────────────────────┤
│ ☐ │3栋B1 配电间                已驳回  │
│   │…                                    │
├─────────────────────────────────────────┤
│            已显示 8/24 · 加载更多        │  加载更多（滚动加载，不分页）
├─────────────────────────────────────────┤
│ [已选 3 条]   [批量驳回]   [批量通过]    │  底部固定条（未选中时置灰常驻）
└─────────────────────────────────────────┘
```

规则：

1. 卡片左侧选择列宽 **48**（视觉 22×22 方块居中，上下各留 12 → 热区 48×48），与标题首行同高；**整卡可点进详情**，卡内不放"看详情"。
2. 卡片只放四层：状态 pill + 对象名（标题）→ 一句事实（谁/何时/多少项）→ 异常要点（含数值）→ 可选 AI 一行。不塞次要字段、不塞导航。
3. 右侧的时间 / 状态 pill / 数量贴**同一条右边线**（卡左 + 342），跨卡对齐；选择列 48 + 列间距 10 只从左侧占用，**不移动右边线**。
4. 底部条：`已选 N 条` + 主按钮 + 次按钮，定宽 96/108 + gap 12、高 48；**未选中时常驻置灰（不隐藏）**，点击置灰条给 toast「先勾选记录」。
5. 全选 = **当前筛选结果全选**，文案写「全选 24 条」而不是「全选」；部分选中显示半选；筛选变化清空选择并 toast「筛选已变，选择已清空」。
6. 无多选例外：`02 我的任务`（四类任务动作各异，批量无意义）只保留"整卡可点 + 卡内一个快捷动作"，不加选择框。
7. **退出多选（缺一条即不算做完，`09 B1`）**：
   - 全选行左端常驻「清空选择」文字按钮，点它只清选择、不动筛选；
   - 底部「已选 N 条」里的 **N 可点** → 打开「已选清单」半屏（§1.1），逐条取消；
   - 系统返回键：多选激活时先退出多选，不退出页面。
8. **AI 低风险默认勾选**：全选行右侧写「AI 已勾选 3 条」，被代勾的卡保留 AI 一行做可辨识标记；**代勾只是默认值，绝不自动提交**——提交必须人在弹窗里点一次（`09 §七.3`）。
9. 卡内快捷动作（如「通过」）用 48 高独立按钮并吞掉点击事件：点它只执行动作、不进详情；它与选择框水平间距 ≥12。
10. 空态按 §6.1 三分（无数据 / 筛选无结果 / 无权限），不写"暂无数据"通句；加载用同高骨架；失败给重试。
11. 列表页底部只存在一条（批量条或主按钮）；toast 浮在它上方 8px，不压按钮。

### 1.1 已选清单半屏（退出多选的第二条路径）

```
┌─ 半屏 sheet（上圆角 20、把手 4×36）──────┐
│ 已选 3 条                      [清空]   │
├─────────────────────────────────────────┤
│ ☑ 1栋1楼大厅消火栓  待审 08-14   [取消] │  行可点 = 取消该条
│ ☑ 3栋B1 配电间      待审 08-15   [取消] │
│ ☑ 5栋2楼前室        待审 08-15   [取消] │
├─────────────────────────────────────────┤
│                 [ 继续选择 ]             │  关闭回列表，选择保留
└─────────────────────────────────────────┘
```

- 只列已选对象（对象名 + 状态 + 时间），不重复卡片的全部字段。
- 半屏内**不承载提交动作**：取消选择是纯 UI 动作，直接生效、给 5s 撤销 toast（`05 §4`）。
- 已选为 0 时半屏自动关闭，底部条回到置灰态。

> 来源：`教训 2`、`09 B1`、`09 B3`、`09 B6`、`09 B10`、`09 B12`、`08 #15`、`08 #20`

## 2. 记录详情模板（一对象一骨架）

用于：`13 工单详情`、`25 报告详情`、`26 审核详情`、`27 巡检记录详情`、`35 设备详情`（已建；画板现名 `28 设备详情`）、`36 承接批次详情`（待建）、`59 卷宗文档详情`（待建）。
（`32 维保生效确认` 也是这套骨架，但它属审核类，见 §4。）

```
┌─────────────────────────────────────────┐
│ ←  记录详情                       [⋯]   │
├─────────────────────────────────────────┤
│ [巡检] [待审]            C240814-03     │  身份行：类别 pill + 状态 pill + 单号（右）
│ 3栋B1 配电间                            │  对象名 17
│ 李伟 · 08-14 15:02 提交 · 5 项检查      │  一句事实（谁/何地/何时/多少）
│ ─────── 打卡 → 提交 → 审核 → 入池 → 关闭 ─────── │  状态链路（可选，只标当前步）
├─────────────────────────────────────────┤
│ 现场事实卡：打卡方式 / 定位核验 / 用时   │  kv 行，右侧同一条右边线
├─────────────────────────────────────────┤
│ 逐项结论卡（异常 x / N 项）              │  ← 模板 §3 的检查项卡（只读态）
│  ⚠ 配电箱门锁闭完好  观察点…    异常    │
│  ✓ 配电箱外观无破损  照片 1 张  正常    │
├─────────────────────────────────────────┤
│ AI 判定 异常            与巡检员一致    │  AI 结论 + 依据一行（有才出现）
├─────────────────────────────────────────┤
│ 照片证据 2 张 · 现场拍摄                │  带时间地点水印，可点开大图
├─────────────────────────────────────────┤
│ 审核进度：审核人 / 时限 / 结果           │  谁审的、何时、什么结论
├─────────────────────────────────────────┤
│ 留痕：驳回原因 / 修订次数（有才出现）    │
├─────────────────────────────────────────┤
│              [ 唯一主操作 ]              │  跟着状态与角色变
└─────────────────────────────────────────┘
```

规则：

1. **一套骨架，三种角色**（`01 原则 2`）：巡检员看同一屏，只是没有审核按钮；被驳回时底部主操作变「修改重提」；已通过全部只读、底部无主按钮。
2. 主管/项目经理在这套骨架上**只多两个按钮**：「驳回」「审核通过」，两者都进阻断式弹窗（§4），**不在页面内联意见框**；本人提交的记录不出现这两个按钮，改一行"本人提交，不可自审"。
3. 只读态 = 控件不可点，信息一个不少；**禁止压缩成摘要行**。
4. 底部主操作数量恒为 1。需要第二个动作时进 `⋯`（如"作废重出""导出"）。
5. 时间线/状态链路只表达"现在在哪一步"，不写规则说明；进度与链路不并存两套（取其一：有链路就别再放进度条）。
6. 同一对象在列表卡、本页、"审核详情"（同骨架变体）、工单/报告引用处的字段顺序、pill 用词、单号格式**逐字一致**（`09 C12`）。
7. 无权限进入：整页替换为"无权访问 + 返回"，不显示半截内容（`05 §7`）。

> 来源：`教训 1`、`09 C11`、`09 C12`、`08 #43`、`08 #61`

## 3. 表单模板（检查项 / 录入）

用于：`03 巡检打卡`、`10 工单整改`、`12 维保执行`、`21 维保登记`、`37 承接矩阵查验`、`28 巡检记录驳回重提`、`39 资料扫描`、`43 报告生成`、`30 AI 失败核查`、`53 岗位设置`、`56 修改密码`。

```
┌─────────────────────────────────────────┐
│ ←  1栋1楼大厅消防栓              [?]    │  ? = 无法检查入口
├─────────────────────────────────────────┤
│ ✓ 已核验 NFC · 距点位 6m（凭证条）      │  未核验时红条 + 表单只读 +「去核验」
├─────────────────────────────────────────┤
│ 已完成 4/6        异常 1 项待审          │  进度行（可点跳未完成项）
├─────────────────────────────────────────┤
│ ┌─ 检查项卡 ────────────────────┐       │
│ │ 灭火器压力表指针在绿区   [必拍] │      │  ① 标题 + 必填 pill
│ │ 标准：指针在绿区 0.8–1.2 MPa   │       │  ② 标准（浅色小字，13）
│ │ [照片][照片][+ 拍照]           │       │  ③ 媒体组（独立属性 photo_required）
│ │ [ 正常 ]  [ 有异常 ]           │       │  ④ 结论分段（等宽 ≥48，绿/红填充）
│ │ ✧ AI：指针在绿区，可直接确认   │       │  ⑤ AI 一行（仅异常或需确认时）
│ │ ──── 异常展开 ────             │       │  ⑥ 条件详情层（仅异常时）
│ │ 观察点 [压力不足][瓶体破损]…   │       │      chips 点选即写入备注
│ │ [备注…]                        │       │
│ └───────────────────────────────┘       │
│ ┌─ 检查项卡 ────────────────────┐       │
│ …                                       │
├─────────────────────────────────────────┤
│ 还差 2 项照片                            │  阻断原因行（不写进按钮）
│              [ 提交本点位 ]              │  主操作（阻塞时置灰）
└─────────────────────────────────────────┘
```

规则：

1. 控件由 `value_type` 决定（ok/number/date/text/enum），**卡片布局不变**；`standard` 只换文字、`photo_required`/`note_required` 只换必填。
2. 结论不默认选中；AI 预选后仍需人确认/改判，改判留痕。pending/running 时禁提交并写"还有 N 项正在识别"；`error` 不阻塞但走人工核查（`30`）。
3. 阻塞原因分行列在按钮上方，能指到具体卡；按钮文案只说动作。
4. 页面不出现分组标题（App 不显示采集分组）；卡间用 hairline 分隔。
5. 一页一次提交；**不做"分批提交/暂存部分项"**（草稿仅用于断网恢复，见 `05-全局交互约定.md §6`）。
6. **核验粒度**（`01 原则 5`、`05 §2`）：
   - 单件（一台设备 / 一张单件工单）：到场与作业各一次核验，凭证条写明方式 + 距离/坐标 + 时间；
   - 整批 / 打包单：**不做整单打卡**，改为逐台核验 + 逐台实时拍照，页面顶部是"N 台待核验"列表而不是一个总凭证条；
   - 未核验的那一台标红并锁该台，其他台可继续填；提交置灰 + 按钮上方「先核验 2 台」+ 可点到该台。
7. **拍照**：每台的照片来自相机当场拍摄（带时间地点水印）；相册上传只在标了「非实时」的补充证据位出现。不写"拍照后自动带时间水印"这类能力说明（`01 原则 6`）。

> 来源：`教训 7`、`09 C6`、`09 C7`、`09 C9`、`08 #41`、`08 #42`

### 4.1 弹窗规范表（审核类子集）

> 本节是**画审核页时手边那张表**；全量场景（含签字、维保确认、派单、停用/删除、纯告知）与统一的按钮规格在 `05-全局交互约定.md §5.1`。两处口径必须一致：新增场景先改 `05 §5.1`，再回到本表补审核相关行。

| 场景 | 标题文案 | 输入 | 按钮（左 → 右） | 后果与撤销 |
|---|---|---|---|---|
| 单条审核通过 | 「通过这条记录」+ 摘要卡（点位 / 异常数 / 提交人 / 时间） | 备注**可选**（占位"如：证据齐全"） | 取消 108 →「确认通过」238 | 记录进已审并触发入池；**不给撤销** |
| 单条驳回 | 「驳回这条记录」+ 同一张摘要卡 | 原因**必填**（常用原因 chips + 文本框，未填置灰 + 红字） | 取消 108 →「驳回并通知」238（危险色、不聚焦） | 退回执行人重提；**不给撤销** |
| 批量通过 | 「通过 5 条记录」+ 一行「其中含异常 3 条」+「查看这 5 条」 | 备注可选 | 取消 108 →「通过 5 条」238 | 逐条生效，原地刷新；有失败 → `46`；**不给撤销** |
| 批量驳回 | 「驳回 5 条记录」+ 含异常条数 + 逐条清单入口 | 原因必填（chips 共用一套） | 取消 108 →「驳回并通知 5 条」238 | 同上；**不给撤销** |
| 签字归档 | 「签署第 3 册并归档」 | 签名预览 + 册数（"共 5 册，已签 2"） | 取消 108 →「签字归档」238 | 该册转只读、不可改；**不给撤销**（§5） |
| 维保生效确认 | 「确认 3 台维保生效」 | 无（可选备注） | 取消 108 →「确认生效 3 台」238 | 写台账、更有效日期；**不给撤销** |
| 批量派单 | 「派单 6 单给 王强」 | 派单人（默认当前人）+ 说明 | 取消 108 →「派单 6 单」238 | 生成待接单；**不给撤销** |
| 删除草稿 / 清筛选 / 取消选择 | **不弹窗** | — | 直接执行 + 撤销 toast 5s | 纯本地，可自恢复 |
| 抢单认领 | **不弹窗**（首单可加一次确认） | — | 认领即生效 + 撤销 toast 10s | 未产生下游事实前可撤回 |

规则：

1. 弹窗阻断：遮罩不可点关闭，三条出口 = 顶部把手下滑 / 「取消」/ 系统返回；有输入时下滑先问「放弃已填内容？存草稿/放弃/继续」。
2. 通过 = 备注可选、单一主按钮；驳回 = 原因必填，未填时提示 + 主按钮置灰，危险按钮与「取消」**不同宽 + gap ≥24**，且**不默认聚焦、不用主色**。
3. 批量弹窗：标题必须含**条数 + 单位**，并写清**其中含异常条数**；给逐条清单入口；原因 chips 与单条共用一套词表。
4. 按钮文案写结果（「通过 5 条」「驳回并通知」「签字归档」），禁止「确定 / 是 / OK / 提交」单字按钮；纯告知弹窗才允许「知道了」且只有一个按钮。
5. 成功后：单条 → 回列表并原地更新 + toast「已通过 · 查看」；批量 → 原地刷新 +（有失败时）`46 批量处理结果`（已处理/成功/失败/跳过 + 失败明细 + 仅重试失败）。**均不给撤销**（会产生下游事实）。
6. **不叠加**：既弹窗又给撤销条 = 违规（`05 §4`）；弹窗内不再叠第二个弹窗（批量结果进独立页 `46`）。
7. 弹窗正文 ≤3 行：做什么、影响几条、两个按钮；最多一行后果句（"归档后不可修改"），不写机制说明。
8. 打开弹窗时焦点进第一个可编辑项（无输入时进「取消」），关闭后焦点回触发按钮。
9. 本人提交的记录不出现审核按钮（防自审），改为一行"本人提交，不可自审"。

> 来源：`教训 3`、`09 D1`~`09 D5`、`09 §七.4`、`09 §七.8`、`08 #54`、`08 #57`、`08 #58`

## 5. 签字模板

用于：`17 报告签字`、`41 承接带遗留签署`（待建）、`42 签后更正重签`（待建）。

```
┌─────────────────────────────────────────┐
│ ←  报告签字                              │
├─────────────────────────────────────────┤
│ 2025-08 巡检月报 · 戎安华府              │  报告身份（一期一项目）
│ 5 册 / 已签 2 册 / 待我签 3 册           │  进度（只出现一次）
├─────────────────────────────────────────┤
│ 册行：第2册 房屋本体   12页  已签 ✓      │  行可点进单册预览
│ 册行：第3册 设施设备   18页  待我签      │
├─────────────────────────────────────────┤
│ 审核路径：王强 ✓ → 张主管 ✓ → 我 ⏳      │  谁已签/谁待签（不解释流程规则）
├─────────────────────────────────────────┤
│ 我的签名：李伟（手写图）                 │  已有签名；无签名时给「去录入 54」
├─────────────────────────────────────────┤
│ [ 驳回 ]                 [ 签署通过 ]    │  两者都进确认弹窗
└─────────────────────────────────────────┘
```

规则：

1. 签字是**不可撤销**动作：不进 toast 撤销，改为确认弹窗里"看签名 + 看册数 + 看后果一句（归档后不可修改）"。
2. 册数不齐或签署主体缺项时，「签署通过」置灰，缺项**分行列在按钮上方**并可点到具体册（`40` 承接签署条件同此）。
3. 签署后该册变只读；再有内容变化必须重出新报告并全体重签（`42`），旧签名不沿用。
4. 签名素材（`54`）≠ 同意某份报告：录入页写"仅保存个人签名"，签字页才表达同意。
5. 签字/归档属"最危险、最少见"的动作：只有它和报告归档、删除归档证据用非常规确认（长按 1.5s 或输入单号后 4 位），**不推广到驳回**（`09 D6`）。

> 来源：`09 D6`、`08 #54`、`08 #55`

## 6. 三类特殊页（不套上面的骨架）

| 类型 | 页面 | 骨架要点 |
|---|---|---|
| 登录 | `23 登录` | logo + 应用名 + 企业名；账号（工号或手机号）/ 密码（眼睛切换）；主按钮「登录」；「忘记密码？联系管理员重置」；一行"或"+ 细线；微信一键登录（`#07C160`，h48）。**无验证码、无项目选择、无切换身份、无"扫码登录"**（没有这个能力就不画） |
| 扫码 | 主页「扫一扫」→ 同一扫码页（打卡 / 工单核验 / 设备查询三用途） | 全屏、无底栏；取景框 + 一行提示（"对准点位码或设备码"）+ 底部「输入编码」；识别成功直接跳，不弹"识别成功"；失败与权限被拒的落点见下 |
| 状态/兜底 | `63` 扫码与核验失败、`61` 现场保障、`62` 离线队列、`64~67` 空/加载/失败/失效 | 一个图形 + 一句话说清发生了什么 + 一个可做动作；无权限与无数据分开写（§6.1） |
| 面板 | `29` 无法检查、筛选、图片查看 | 半屏 sheet，上圆角 20、把手、单一主按钮 |

### 6.1 空态三分（所有骨架通用，`01 原则 11`）

```
┌─ 无数据 ──────────────┐  ┌─ 筛选无结果 ──────────┐  ┌─ 无权限 ──────────────┐
│      [32 图标]        │  │      [32 图标]        │  │      [32 图标]        │
│   今天暂无待审        │  │   当前筛选无记录      │  │ 你没有查看该范围的权限│
│   [ 去工单池看看 ]    │  │   [ 清空筛选 ]        │  │   [ 返回 ]            │
└───────────────────────┘  └───────────────────────┘  └───────────────────────┘
```

- 三套文案、三套动作，**禁止共用"暂无数据"**；不显示 0 当空数据。
- 筛选无结果只清筛选、留在本页；无数据给一个真正的下一步；无权限不给"去申请"这类假动作。
- 加载用与真卡同高的骨架（>3s 加"网络较慢"）；失败 = 发生了什么 + 重试/返回；刷新保留旧数据 + 顶部细进度条。
- 扫码失败单独一页（`63`）：五类原因（非本点位码 / 围栏不符 / 定位失败 / NFC 未识别 / 码已作废）+「重扫 / 输入编码 / 联系管理员」，**不提供"免核验继续"**。

> 来源：`教训 9`、`教训 6`、`09 B9`、`09 A8`、`09 §七.12`、`08 #8`
