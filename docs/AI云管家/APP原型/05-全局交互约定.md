# 05 全局交互约定

跨页一致的行为只在这里定义一次。逐页清单（`04`）只写"用哪条"，不重复解释。
来源标记：`09 §X` = 外部准则条目、`08 #N` = 审计缺陷号、`教训 N` = `01-设计原则.md` 文末对照表编号。

## 1. 扫一扫

- **常驻唯一入口**：主页顶栏右侧「扫一扫」，全站只此一处；二级页不重复放扫码图标（`教训 6`）。
- **一个扫码页服务三种目的**，靠入口参数区分，扫到后各自回跳——**不新建第二套扫码界面**：

| 目的 | 入口 | 传入参数 | 扫到后 | 兜底 |
|---|---|---|---|---|
| 打卡 | 主页扫一扫（无上下文） | 无 | 命中点位 → `03 巡检打卡` | 落 `63`，动作 = 重扫 / 输入编码 |
| 工单核验 | `10`/`12`/`13` 页面内「扫码核验」 | `purpose=wire&order_id` | 回来源页，解除单台/单件锁定 | 回来源页 + 卡内红字「未核验」，可再扫 |
| 设备查询 | 主页扫一扫（用户切"查设备"或命中的是设备码） | 无 | `35 设备详情` | 未匹配 → `63`「码不属于本小区」+ 输入编码 |

- 扫码页无底栏；识别成功直接跳，不弹"识别成功"；连续扫（`39`）在页内计数。
- **扫码页不写规则说明**：不写"必须距点位 100m 内""请使用相机拍摄"这类解释，只写一行提示"对准点位码或设备码"。
- 失败一律落 `63 扫码与核验失败`：原因分五类（非本点位码 / 围栏不符 / 定位失败 / NFC 未识别 / 码已作废），动作只给「重扫 / 输入编码 / 联系管理员」。**任何情况下不提供"免核验继续"。**
- 相机/定位权限被拒 → 页内一行说明 + 「去设置」，不进 `63`（这是权限问题，不是扫码失败）。
- 扫不出时永远有「输入编码」这第二条路（一线手套／逆光／码磨损）。

> 来源：`教训 6`、`09 A2`、`09 A10`、`09 E5`

## 2. 工单核验与执行

四条硬规则（现场事实只采一次，`01 原则 5`）：

- **单件要核验**：每台设备的到场与作业都要有一次核验（扫码 / NFC / 围栏，按点位配置，可组合），核验记录带时间、坐标、方式。
- **整批 / 打包工单不打卡**：批量维保、批量整改只做**单件核验 + 逐台实时拍照**，不做整单一次打卡；页面顶部是"N 台待核验"清单，不是一个总凭证条。
- **逐台实时拍照**：每台的照片来自相机当场拍摄（带时间地点水印），允许上传相册的只有明确的补充证据位，且标「非实时」。
- **不允许分批提交**：一页表单一次提交（`03`/`10`/`12` 同一规则）；草稿只用于断网恢复，不作为"先交一部分"的通道。

配套：

- 未核验的单台：标红并锁该台，其他台可继续填；提交时置灰 + 按钮上方「先核验 2 台」+ 可点到该台。
- 核验凭证条只写事实（方式 + 距离/坐标 + 时间），不写"围栏 100m 内可打卡"这类配置说明。

> 来源：`教训 7`、`09 C6`、`09 C9`、`08 #41`、`08 #33`

## 3. 入池与复查（UI 不解释）

- **入池全自动**：巡检异常在审核链**通过**的那一刻入池，与审核结论同一事务；没有"待入池"中间态，App 也不为此设计任何按钮或状态。
- **复查是后台开关**：是否复查由后台配置决定，App **不解释**"为什么这单要复查"、不在页面写"已开启复查"；需要复查的单出现在 `11 待我复查`，不需要的不出现。
- 纯维保工单不进复查，提交后直接进维保生效确认（`32`）。
- 通篇不出现：入池/打包/审核链节点/名单为空/阈值比例这些后台概念。

> 来源：`教训 5`、`08 #34`、`08 #35`

## 4. 批量与撤销

**选择模型**

- 三件套：全选 + 单条勾选 + **AI 低风险默认勾选**（代勾是默认值，不自动提交）。
- 全选 = **当前筛选结果全选**（滚动加载、不分页，不设"本页全选"第二概念），文案写「全选 24 条」；部分选中时全选框半选。
- 筛选/切片变化 → 清空已选并 toast「筛选已变，选择已清空」。
- 选择数只在底部条出现一次；AI 代勾提示只挂全选行右侧。

**退出多选（`09 B1`，缺一即不算做完）**

- 全选行左端「清空选择」：只清选择，不动筛选。
- 底部「已选 N 条」的 **N 可点** → 已选清单半屏（`03 §1.1`），逐条取消；半屏内不放提交动作。
- 系统返回键：多选激活时先退出多选，再退页面。

**动作**

- 底部条：`已选 N 条` + 主按钮 + 次按钮，定宽 96/108 + gap 12，高 48；**未选中时常驻置灰（不隐藏）**，点击置灰条给 toast「先勾选记录」。未选中态压到 56 高，只显示「已选 0 条」+ 一个禁用主按钮。
- 批量动作**一律先弹窗**（§5），弹窗标题写清"将通过 N 条 / 驳回 N 条"并附**其中含异常条数**与「查看这 N 条」入口。
- 批量只对**允许批量**的对象生效：低风险打卡记录、同批次同动作的维保登记、同小区同专业的派单。跨范围 → 阻断并提示拆分，**不静默合并**。
- 底部条按钮顺序固定：左「批量驳回」（描边红字）— gap ≥24 — 右「批量通过」（实心品牌蓝）；不做两个等宽同底色按钮。

**结果与撤销**

- **分两类，不叠加**：
  - **会产生下游事实的动作**（审核通过/驳回、签字、归档、批量处理、维保确认、派单）→ **只弹窗，不给撤销**。这些动作会入工单池、写台账、改归档件，撤销要连带回滚下游，成本远大于一次确认。
  - **纯本地/可自恢复的动作**（取消选择、删草稿、清筛选、抢单认领）→ 不弹窗，给 5s（抢单 10s）撤销 toast。
- 批量 → 原地刷新 +（有失败时）跳 `46 批量处理结果`（已处理/成功/失败/跳过 + 失败明细 + 仅重试失败）。成功的项不重做。
- **禁止"弹窗确认 + 再给撤销"叠加**：既慢又乱，且让用户以为弹窗可跳过。

### 4.1 撤销策略表（全站唯一口径）

| 动作 | 是否弹窗 | 是否给撤销 | 撤销窗口 | 依据 |
|---|---|---|---|---|
| 审核通过 / 驳回（单条、批量） | 是（阻断 sheet） | **否** | — | 会入池、通知执行人 |
| 报告签字 / 归档 / 作废重出 | 是（+ 非常规确认） | **否** | — | 归档件不可改，改正只能重出 |
| 维保生效确认 | 是 | **否** | — | 写台账、改有效日期 |
| 批量派单 / 改派 | 是 | **否** | — | 生成待接单、通知候选人 |
| 删除/作废有业务数据的对象 | 是（改「停用」） | **否** | — | 影响下游引用 |
| 抢单认领 | 否（首单可一次确认） | **是** | 10s | 未产生下游事实前可撤回 |
| 取消某条选择 / 清空选择 | 否 | **是** | 5s | 纯 UI |
| 删未提交的草稿、草稿照片 | 否 | **是** | 5s | 本地数据 |
| 清空筛选 / 切筛选 | 否 | 否（结果可见即所得） | — | 无破坏性 |
| 标记全部已读 | 是（写条数） | **是** | 5s | 可再标未读，无下游事实 |
| 退出登录 | 是 | 否 | — | 会话即失效 |
| 修改密码 | 是 | **否** | — | 安全动作不给撤销条 |

撤销条规则：同时只显示一条（新条顶掉旧条）；位置锚在底部批量条/主按钮**上方 8px**（`09 D8`）；检测到无障碍模式时带「撤销」的条改常驻 + 关闭按钮（`09 D7`）。

> 来源：`教训 2`、`教训 3`、`09 B1`、`09 B3`、`09 B4`、`09 B5`、`09 B11`、`09 D2`、`09 D7`、`09 D8`、`09 D10`、`09 §七.4`、`08 #15`、`08 #18`

## 5. 弹窗与半屏

| 类型 | 用途 | 规格 |
|---|---|---|
| 阻断式 sheet | 审核通过 / 驳回 / 签字 / 派遣 / 删除 / 维保确认 | 底部起、上圆角 20、顶部把手 4×36、遮罩 ~50% 黑**且不可点关闭**；三条出口：明显的「取消」+ 把手下滑 + 系统返回 |
| 半屏 sheet | 筛选、项目下拉、登记表单、已选清单、图片说明 | 同上但允许遮罩外点击关闭（不承载不可逆动作） |
| 全屏遮罩 | 签字板、图片查看、扫码 | 显式关闭按钮 + 系统返回 |

### 5.1 弹窗规范表（场景 / 标题 / 输入 / 按钮 / 后果，照填不各写一套）

| 场景 | 标题文案 | 输入 | 按钮（左 → 右，定宽） | 后果一句 + 撤销 |
|---|---|---|---|---|
| 单条审核通过 | 「通过这条记录」+ 摘要卡（点位/异常数/提交人/时间） | 备注**可选** | 取消 108 →「确认通过」238 | "通过后进入下一环节"；**不给撤销** |
| 单条驳回 | 「驳回这条记录」+ 同一张摘要卡 | 原因**必填**：常用原因 chips + 文本框 | 取消 108 →「驳回并通知」238（危险色） | "将通知提交人重提"；**不给撤销** |
| 批量通过 | 「通过 5 条记录」+「其中含异常 3 条」+「查看这 5 条」 | 备注可选 | 取消 108 →「通过 5 条」238 | 逐条生效，原地刷新；有失败 → `46`；**不给撤销** |
| 批量驳回 | 「驳回 5 条记录」+ 含异常条数 + 逐条清单 | 原因必填（chips 与单条共用词表） | 取消 108 →「驳回并通知 5 条」238 | 同上；**不给撤销** |
| 签字归档 | 「签署第 3 册并归档」 | 签名预览 + 册数（"共 5 册，已签 2"） | 取消 108 →「签字归档」238 | "归档后不可修改，改正需重出报告"；**不给撤销** |
| 维保生效确认 | 「确认 3 台维保生效」 | 可选备注 | 取消 108 →「确认生效 3 台」238 | "将回写台账与有效期"；**不给撤销** |
| 批量派单 | 「派单 6 单给 王强」 | 派单候选人（默认当前人）+ 说明 | 取消 108 →「派单 6 单」238 | "候选人将收到通知"；**不给撤销** |
| 停用 / 删除 | 「停用 1栋3楼通道消火栓」 | 原因必填 | 取消 108 →「停用并解除绑定」238 | 列出受影响对象数（"影响 3 条未完成工单"）；**不给撤销** |
| 标记全部已读 | 「将 12 条标为已读」 | 无 | 取消 108 →「全部已读」238 | 立即生效；给 5s 撤销 |
| 删除草稿 / 清筛选 / 取消选择 | **不弹窗** | — | 直接执行 + 撤销 toast 5s | 纯本地 |
| 纯告知（必须知道但无需选择） | 一句事实 | 无 | 只一个「知道了」 | 不写"确定/是" |

规则：

- 按钮布局：**主操作在右、更宽**（取消 108 + 动作 238）；危险动作（驳回/删除/作废）用危险色底 + 危险色字，与「取消」**拉开 ≥24 且宽度不同**——不能两个按钮长得一样、也不能贴在一起。
- **按钮文案写结果**（「通过 5 条」「驳回并通知」「签字归档」），禁止「确定 / 是 / OK / 提交」；只有纯告知弹窗才允许「知道了」，且此时只有一个按钮。
- **危险按钮不默认聚焦、不用主色、不被回车默认触发**；打开弹窗时焦点进第一个可编辑项，无输入时进「取消」；关闭后焦点回触发按钮。
- 必填未填：字段级红字 + 主按钮置灰，**不弹第二次提示框**。
- 弹窗内不放规则说明段；最多一行后果句（"归档后不可修改"），机制解释一律删（`09 D11`）。
- 一次只呈现一层模态：弹窗里不再开弹窗，批量结果进独立页 `46`；有输入时下滑关闭先问「放弃已填内容？存草稿 / 放弃 / 继续」。
- 语气中立：不写"操作将被审计""请谨慎操作""此操作不可恢复"单独出现（`09 D12`）。

> 来源：`教训 3`、`09 A4`、`09 A5`、`09 A6`、`09 D3`、`09 D4`、`09 D5`、`09 D11`、`09 D12`、`09 §七.8`、`09 §七.10`、`08 #54`

## 6. 离线与补传

- 弱网/断网时：表单自动存本地草稿（含已拍照片），顶部条显示「已存本地 · 待上传 N」。
- 网络恢复：自动续传，逐条变「上传中 → 已上传」；失败保留并进 `62 离线补传队列`。
- 三种状态必须可见且互不冒充：**已存本地 / 待上传 / 已上传**。
- 同机恢复必须可靠（杀进程后能回到草稿）；**不承诺换机恢复**，不在 UI 上暗示"云端已保存"。
- 提交成功的判据是服务端回执，不是"网络看起来好了"；回执前页面不显示成功态。
- 草稿是"断网恢复"通道，**不是"先交一部分"的通道**（§2）。

## 7. 三态 + 无权限态

| 态 | 表达 | 禁止 |
|---|---|---|
| 空 | 一句"为什么空" + 一个可做动作（细分见下表） | 不显示 0 当成空数据 |
| 加载 | 与真卡同高的骨架；>3s 加一行"网络较慢" | 不显示假零、不伪造上次数据 |
| 错误 | 发生了什么 + 下一步（重试/返回/联系管理员） | 不写制度说明、不只弹"失败" |
| 无权限 | "你没有查看该范围的权限" + 返回 | 不混进空态、不给假"去申请" |

**空态三分（`01 原则 11`）**

| 空的原因 | 文案 | 动作 |
|---|---|---|
| 真的没有数据 | 「今天暂无待审」 | 一个真正的下一步：返回 / 去工单池 / 去建点位 |
| 筛选条件过窄 | 「当前筛选无记录」 | 「清空筛选」（留在本页，不动其他筛选状态） |
| 没有范围权限 | 「你没有查看该范围的权限」 | 返回；**不出现"去申请"** |

- 三种空态**禁止共用一句"暂无数据"**；图形用 32 图标 + 一句说明 + 一个动作，不放大插画。
- 刷新时保留旧数据 + 顶部细进度条，不清空重绘。
- 无权限 = 入口不出现；深链进入才见无权限态。**看得见点不动的按钮一律不画。**

> 来源：`教训 9`、`09 B9`、`09 A8`、`09 §七.12`、`08 #8`

## 8. 深链与通知直达

- 深链格式 `#/pages/<域>/<页>?id=<对象ID>`；对象身份只用 ID，不用名称。
- 同一对象只有一条详情路由（`01 原则 2`）：通知、列表、AI 助手、扫码回跳全部指到同一页，不出现"审核专用详情页"。
- 通知点击 → 直达对象详情；对象已删除/已关闭/无权限 → `67 通知直达失效`（三类原因分开写），不进空白页。
- 直达后的返回：回**通知列表**（不是主页），保持原分类与滚动位置。
- 审核/签字类直达：若当前人已不是该节点候选人，显示只读 + 一行"当前节点已变更"，不给动作。

## 9. 时间、单位与数字

- 时间：当天显示 `HH:mm`，本年内 `MM-DD HH:mm`，跨年 `YYYY-MM-DD`；所有时间贴**同一条右边线**（卡左 + 342），不写在标题里。
- 剩余期限统一"还有 N 天 / 已逾期 N 天"，**只在一种位置出现一次**：顶部统计行出现，卡内 pill 就只写「已逾期」不带天数（`01 原则 8`）。
- 数值带单位（MPa / V / m³ / ℃）；越界用危险色 + 数值本身高亮，不只靠颜色（加"越界"文字）。
- 计数单位固定：条 / 项 / 台 / 册 / 单 / 份，不在同一屏混用两种说法指同一对象。

## 10. 手势与可达性

- 长按卡片 = 进入多选（等同点左侧选择框）；再点一次取消。多选激活时返回键先退多选（§4）。
- 主操作在拇指区（底栏 48 以上），首页信息控制在真机首屏内，不做长图假象。
- **所有可点区域 ≥48×48**：视觉可 22~23，热区靠透明 padding 补足；选择框视觉 22×22、选择列宽 48；相邻可点目标间距 ≥12，危险动作与「取消」≥24。
- 相机、录音、定位首次使用时才申请权限，被拒后给「去设置」，不重复弹系统框。
- 不依赖颜色单一表达状态：状态 pill 同时带文字与图标（"待审""已逾期"）。
- 设置里提供「大字模式」（正文 15→17、次要 13→15、行高 +2）与「高对比」；放大后并排按钮改上下堆叠，不裁字。

> 来源：`教训 8`、`09 C1`、`09 C2`、`09 E4`、`09 E10`、`09 §七.9`
