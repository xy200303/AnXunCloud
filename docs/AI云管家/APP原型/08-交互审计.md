# 08 交互审计（25 屏 · 74 条）

> 本文是 `docs/品管家/原型图/penpot/交互审计.md` 的归档副本，**保留原始缺陷表与结论不改**（那是审计时点的事实记录），只在末尾补 `§4 本轮状态更新` 说明哪些条目已随新画板消除、哪些仍然存在。
> 读法：要复核老画板 → 查 §2 缺陷表；要新建页面避坑 → 查 §3 共性问题；要判断"还用不用改" → 查 §4 状态表。

- 审计对象：Penpot 文件「AI云管家」/ 页面 `App 原型`，共 25 个画板（原 24 屏 + 他人本轮新增 `26 审核详情`）
- 审计时点：2026-10-25 19:50（当前 Penpot 实际画板，非 `penpot/*.png` 旧图；旧图 18/19/21/22 落后于画板）
- 审计方法：逐屏导出当前画板 SVG → 本地渲染 → 逐屏读图，并对照 `.tmp/ds/*.js` 源码确认实现口径
- 清单口径：①批量能力 ②详情可达 ③路径步数 ④入口唯一 ⑤长列表 ⑥筛选搜索 ⑦危险操作 ⑧信息重复/噪音 ⑨适老化 ⑩状态可见

> 说明：`penpot/` 目录的 PNG 是历史导出，18/19/21/22 与当前画板已不一致（22 已被重做为「社区板块」）。本轮审计一律以画板现状为准。

## 0. 结论

| 档 | 条数 | 说明 |
|---|---|---|
| 高 | 9 | 直接导致"做不了事/做错事"：无入口、无详情、无批量、危险动作无确认、数据自相矛盾 |
| 中 | 40 | 可用但费劲：双按钮入口、规则说明占屏、缺加载更多、缺批量 |
| 低 | 25 | 文案与层级噪音、图标可点区偏小、状态表述重复 |
| 合计 | 74 | 24 屏里 23 屏有至少 1 条缺陷，仅 `23 登录` 达标 |

**最严重的 5 条**

1. **14 设备台账**：128 台设备的列表，卡片既不可点、也没有任何按钮，全站不存在设备详情页 —— 台账只能"看"，查不了维保单、改不了到期日、发不起维保。
2. **19 巡检记录**：按日期分组的记录行完全不可点，没有巡检记录详情页 —— 想回看某次打卡的照片、逐项结论、AI 判定、谁审的，无路可走；审核只能挤在 18 一屏里做。
3. **04 工单池**：没有多选、没有"按筛选全选"、没有底部「已选 N 单 + 批量动作」；批量派单被固定在一条"1栋 · 维修类 2 张"的阈值卡上，用户不能自己挑单合并。
4. **17 报告签字**：单册「签」和「签全部」都是不可撤销的签字归档动作，全程零二次确认、无签名预览、无撤销窗口。
5. **03 巡检打卡**：每个检查项都要点一次「正常/有异常」，7 项 = 14 次点击，没有「全部正常」批量；现场举着手机逐条点的成本最高。

**并列高危（需同样处理）**

- **08 卷宗库**：年份写 `2026-08 / 2026-07`，与 17/20/25 的 `2025-08` 全面冲突，同一份月报在两屏显示不同年份。
- **22 社区**（他人本轮重做中）：屏上直接写「默认混合推荐；点上方方块图标切换为专属内容（图中选中：便民集市）」——纯后台配置说明进了 C 端 UI。

## 5. 复核方法（重导一屏再判）

```bash
# 1) 导出画板 SVG 并统计字形（text 数 = text-container 数 才算字形没丢）
python .tmp/ds/check_svg.py "18 打卡审核" t18
# 2) 本地渲染 PNG 目视
python .tmp/ds/render_raw.py t18
# 输出：.tmp/penpot_import/png/view_t18.png
# 3) 批量导出（注意：export_all.py 的 ALL 列表只到 25，26/27/28 未登记，需用 check_svg.py 单个跑）
python .tmp/ds/export_all.py
```

- `text` 数为 0 或与 `container` 数不等 → 字形丢了，删画板重跑（`del_boards.js` + 对应 `sNN.js`）。
- 重导后把图放进 `预览/`，并回来更新 §4 的状态（已消除 / 仍存在）。
- 画板没改过就别重判视觉——审计结论按"画板时点"记录，避免同一屏被反复翻案。
