# 09 外部准则参考

> **这是什么**：外部权威设计准则的**取证汇编 + 落到本项目画板上的翻译**。不是读书笔记。
> **怎么用**：新建或评审一屏时，先按 `01-设计原则.md` 十二条（每条带检查方法）自检，再过一遍本文 A~E 五组里与该屏相关的条目；出现"外部说 X、项目说 Y"的情形，直接跳到 §七 取结论，不重新开讨论。
> **层级关系**：`01`~`08` 是**项目内部约定**（我们的决定），本文是**外部依据**（别人验证过的规律）。两者冲突时以 §七 的取舍结论执行；§七 没覆盖的，以 `01` 为准。

### 1.2 未能直取原文的部分（如实标注）

- **m3.material.io 规范正文**：站点为 JS 渲染，抓取只取到导航壳。Snackbar / FAB 的行为以官方 GitHub 组件文档（上表 #11 #12）为准；`selection mode`、`bottom action bar` 一类条目的确切措辞请人工在浏览器核对 [m3.material.io](https://m3.material.io)。
- **w3.org 的 Understanding 文档**：对抓取返回 403。故数字与条目取自 **WebAIM 官方对照清单**（它逐条引用并链接 W3C 原文）；引用正式条款号时用 W3C 锚点，如 [2.5.8 Target Size (Minimum)](https://www.w3.org/TR/WCAG22/#target-size-minimum)、[1.4.3 Contrast (Minimum)](https://www.w3.org/TR/WCAG22/#contrast-minimum)。
- **developer.android.com**：网络不可达。上下文操作栏（CAB，标题显示"已选 N 项"）作为批量条的行为依据，出处仍记该站 [Contextual menus](https://developer.android.com/guide/topics/ui/menus#contextual)；本文只引其行为结论，不引其措辞。

### 1.3 引用纪律

1. 一条准则只写一个主出处；只有两者结论不一致时才并列，用来提示风险。
2. 有数字就写数字（44pt、4.5:1、4s），不写"要足够大""要明显"。
3. 每条"具体要求"必须能指到**具体屏号或具体数值**；指不到的，说明它还只是原则，删掉。

## 二、A 组：导航与信息架构

| # | 准则（中文） | 出处与链接 | 对本项目的具体要求 |
|---|---|---|---|
| A1 | 系统返回优先于任何自定义返回 | [Apple HIG · Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)（系统级关闭手势是用户预期） | Android 实体返回键/手势返回 = 页面左上 `←`，同一逻辑，不另写拦截。只有 L4 表单（`03`/`10`/`12`/`21`/`37`/`28`）已填时才拦一次，给「存草稿/放弃/继续填」三个出口。弹层打开时返回只关弹层，不关页面。**禁止**"再按一次退出"式拦截。 |
| A2 | 导航栏标题短，右侧至多一个动作 | [Apple HIG · Layout](https://developer.apple.com/design/human-interface-guidelines/layout)（最重要信息靠上靠起始侧；控件与内容要能区分） | 标题 ≤10 字、写通用名（"记录详情"），长标题进页面内 17 号标题；右侧只放 `⋯`/搜索/筛选之一；扫一扫只在主页顶栏出现一次（`02 §2`），二级页不重复。 |
| A3 | 重复点当前 Tab 回根并滚顶；切 Tab 保留各自路径 | [Apple HIG · Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) | 五底栏每 Tab 各维护一条栈：A→详情→切 B→回 A 仍在详情；再点 A = 回 A 根页并滚顶。 |
| A4 | 一次只呈现一层模态，不在弹层上再开弹层 | [Apple HIG · Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)（"Display only one sheet at a time"） | 确认弹窗里不出现第二个弹窗：批量结果不弹"成功/失败"二段框，直接进 `46 批量处理结果`；扫码失败原因就地显示，不再弹提示框。确实需要第二步时，先关前一层再开新的。 |
| A5 | 半屏可下滑关闭；有未保存内容时先确认 | [Apple HIG · Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)（未保存内容下滑关闭前用 action sheet 确认） | `05 §5` 已定：遮罩不可点、出口为把手下滑与「取消」。本文补两条：① 有输入时下滑先出「放弃已填内容？存草稿/放弃/继续」；② 弹层顶部必须有 4×36 把手，无把手的弹层一律算缺陷。 |
| A6 | 取消在起始侧、完成在结束侧；三者不同时出现 | [Apple HIG · Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)（Cancel 在 leading、Done 在 trailing；避免 Cancel+Done+Back 并存） | 弹窗/半屏统一：左「取消」（描边），右「动作动词」（实心，定宽 96 或 108）。多步流程（如 `43 报告生成`）只给「上一步/下一步」，不给「取消」占位。 |
| A7 | 连续、复杂、需专注的任务用全屏，不用半屏 | [Apple HIG · Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)（复杂或较长的流程应避开 sheet） | 扫码、签字、看大图、`30 AI 失败核查` 一律全屏、无底栏；登记、筛选、确认一律半屏。不允许"半屏里塞一个要滚三屏的表单"。 |
| A8 | 启动与失败不用弹窗，用页内状态 | [Apple HIG · Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)（启动不要弹 alert；可先显示缓存或占位数据 + 一句不打断的标注） | 启动断网、列表拉取失败、AI 超时都不弹框：列表区显示骨架→"上次数据 · 未联网"细条 + 重试；AI 超时在卡内显示"识别未完成 · 人工确认"（对齐 `03 §3` 的 pending/running/error）。 |
| A9 | 系统状态必须在合理时间内可见 | [NN/g #1 系统状态可见性](https://www.nngroup.com/articles/ten-usability-heuristics/) | 分档写死：<300ms 不显示 loading；300ms~1s 出骨架或按钮内转圈；>1s 出"正在做什么 + 可取消"。按钮进行态要**换文案**（"提交本点位"→"提交中…"）并禁用防重复点击（见 [Apple HIG · Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)）。 |
| A10 | 识别优于回忆：要用的信息就地可见 | [NN/g #6 识别优于回忆](https://www.nngroup.com/articles/ten-usability-heuristics/) | 驳回原因 chips、异常观察点 chips、上次筛选、上次备注模板，全部常驻在输入位**旁边**，不藏进"常用语"二级弹层；不让一线记编码，扫不出码时给「输入编码」（已在 `02 §2`）。 |
| A11 | 让人随时知道"我在哪、从哪来" | [NN/g #1](https://www.nngroup.com/articles/ten-usability-heuristics/) + [Apple HIG · Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)（层级列表持续高亮所选行） | 详情页身份行写清归属（类别 pill + 状态 pill + 单号）；从筛选后的列表进详情再返回，必须保持筛选与滚动位置，不回默认排序（`02 §3` 已定，这里要求把"保持"写进验收）。 |

## 三、B 组：列表与批量

| # | 准则（中文） | 出处与链接 | 对本项目的具体要求 |
|---|---|---|---|
| B1 | 多选是一种"模式"，必须能明确进入和退出 | [Apple HIG · Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)（"people must enter an edit mode before they can select table items"） | 我们选了常驻选择列而非隐藏的编辑模式（见 §七.2），代价是必须补"退出"：全选行左端给「清空选择」；底部「已选 N 条」里的 N 可点 → 已选清单半屏，可逐条取消。**没有退出路径就等于没做本条。** |
| B2 | 选中反馈不能只靠底色 | [WCAG 1.4.1 不能只用颜色传达信息](https://webaim.org/standards/wcag/checklist) | 选中卡 = 2px 品牌蓝描边 + 复选框实心勾 + 行底色微变，三者同时；取消选中要把三者都还原，不能留描边。 |
| B3 | 批量状态与批量动作必须带数量 | [Android · Contextual menus（CAB 标题显示已选条数）](https://developer.android.com/guide/topics/ui/menus#contextual) | 底部条固定「已选 N 条」（`05 §4` 已定）；进确认弹窗后标题必须写"将通过 5 条记录"（数量 + 单位）。数量写在标题里，不写在按钮上（按钮只写动作）。 |
| B4 | 一屏只有一条常驻底部条，批量条替代主操作而非叠加 | [Material · Snackbar（须锚定在底部栏之上，不得遮挡）](https://github.com/material-components/material-components-android/blob/master/docs/components/Snackbar.md) + [FAB 只承载一个主操作](https://github.com/material-components/material-components-android/blob/master/docs/components/FloatingActionButton.md) | 列表页底部同时只存在一条（`05 §4`）：未选中→置灰的批量条；选中→同一条激活。**不出现"批量条 + 主按钮"两层。** toast 浮在这条之上 8px，不压按钮。 |
| B5 | 批量动作前给出可核对的明细，不能只报总数 | [NN/g · 确认框第 3 条"要具体"](https://www.nngroup.com/articles/confirmation-dialog/) | 批量通过/驳回的弹窗里：一行"将通过 5 条 · 其中含异常 3 条"，下给「查看这 5 条」入口（`05 §4` 已要求入口，这里要求**至少显示条数与异常条数**）。缺这条就等于"你确定要继续吗"式空确认。 |
| B6 | "全选"的语义必须写清范围 | [NN/g #2 贴合真实世界](https://www.nngroup.com/articles/ten-usability-heuristics/) | 全选 = 当前筛选结果全选（`05 §4`），文案写「全选本页 24 条」而非「全选」；筛选变化 → 清空选择 + toast「筛选已变，选择已清空」。不引入"本页全选"第二个概念。 |
| B7 | 行内文字要短、能扫读、右缘对齐 | [Apple HIG · Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)（"Keep item text succinct"，必要时只列标题） | 卡片只留四层（标题/一句事实/一行要点/可选 AI 行）；时间、状态 pill、数值全贴 330 右边线；要点行一行一条，超长换行，不省略到看不见关键值（如"水带缺 1 盘"不能只留"水带…"）。 |
| B8 | 长列表滚动加载，到底要明说 | [NN/g #7 灵活高效](https://www.nngroup.com/articles/ten-usability-heuristics/) | 保持"已显示 8/24 · 加载更多"的滚动加载；触底自动加载必须有 48 高的「没有更多了」结束行，不允许静默到底（一线会反复下拉找剩余项）。 |
| B9 | 三种"空"要分开：无数据 / 筛选无结果 / 无权限 | [NN/g #1](https://www.nngroup.com/articles/ten-usability-heuristics/) + [WCAG 3.3.1 错误识别](https://webaim.org/standards/wcag/checklist) | 无数据：「今天暂无待审」+ 返回；筛选无结果：「当前筛选无记录」+「清空筛选」按钮；无权限：「无权访问」+ 返回（`01 原则 10`）。三套文案三套动作，禁止共用一句"暂无数据"。 |
| B10 | 小控件靠热区补足，不与相邻动作抢触摸 | [WCAG 2.5.8 目标 ≥24×24（AA）](https://www.w3.org/TR/WCAG22/#target-size-minimum) + [Apple 44×44pt](https://developer.apple.com/design/human-interface-guidelines/buttons) | 选择框视觉 22×22，**热区 48×48**；复选框与卡内快捷动作水平间距 ≥12；选择列宽按 48 留（见 §七.9），不要把热区压到卡片文字上。 |
| B11 | 危险与安全的批量动作在空间上分开 | [Apple HIG · Alerts（destructive 用红色语义样式）](https://developer.apple.com/design/human-interface-guidelines/alerts) | 底部条固定顺序：左「批量驳回」（描边、红字）— 右侧留 ≥24 — 右「批量通过」（实心品牌蓝）。不做两个等宽并排、同底色的按钮。 |
| B12 | 整行可点与行内动作必须互不误触 | [WCAG 2.5.8](https://www.w3.org/TR/WCAG22/#target-size-minimum)（相邻目标 24px 圆不得相交） | 整卡点击进详情；卡内那一个快捷动作（如「通过」）用独立 48 高按钮并吞掉点击事件，点它**只**执行动作、不进详情。 |

## 四、C 组：详情与表单

| # | 准则（中文） | 出处与链接 | 对本项目的具体要求 |
|---|---|---|---|
| C1 | 可点区域 ≥44×44 pt，我们取 48 | [Apple HIG · Buttons（"a hit region of at least 44x44 pt"）](https://developer.apple.com/design/human-interface-guidelines/buttons) + [WCAG 2.5.5（AAA 44×44）](https://webaim.org/standards/wcag/checklist) | 所有按钮、分段控件、chips、图标按钮热区高 ≥48；视觉可小（图标 23），但热区不得靠重叠扩大。 |
| C2 | 相邻可点目标留白，危险动作离得更远 | [WCAG 2.5.8](https://www.w3.org/TR/WCAG22/#target-size-minimum) + [Apple HIG · Layout](https://developer.apple.com/design/human-interface-guidelines/layout)（控件之间要留足空间） | 并排按钮 gap 12（`01 原则 7`）；危险按钮与「取消」≥24；卡片内快捷动作与下一张卡的选择框 ≥16。 |
| C3 | 标签常驻，不用占位符充当标签 | [NN/g #6 识别优于回忆](https://www.nngroup.com/articles/ten-usability-heuristics/) | 备注、数量、日期等输入，字段名写在框上方且输入后**不消失**；占位符只放示例（"如：水带接口松动"），不放字段名。 |
| C4 | 必填与格式要求写在标签上 | [WCAG 3.3.1](https://webaim.org/standards/wcag/checklist)（必填项与限定格式须在标签内说明） | 检查项卡用 pill 标「必拍」「必填」（`03 §3`）；驳回原因框标题写「驳回原因（必填，选一个或自己写）」。不允许只在提交后才告知漏项。 |
| C5 | 错误就地、说人话、给下一步 | [NN/g #9](https://www.nngroup.com/articles/ten-usability-heuristics/) + [NN/g 老年用户研究（错误提示措辞含糊、位置易被忽略）](https://www.nngroup.com/articles/usability-for-senior-citizens/) + [WCAG 3.3.3 错误建议](https://webaim.org/standards/wcag/checklist) | 红字贴在**出问题的那个字段下方**（不是页顶横幅），形如「水带照片还没拍 —— 点这里去拍」并可直接跳转；禁止错误码、禁止只有红色三角不说话。 |
| C6 | 不让人重复录入同一信息 | [WCAG 3.3.7 Redundant Entry（2.2 A 级）](https://webaim.org/standards/wcag/checklist) | 同一会话内楼栋、点位、设备、上次备注模板自动带出且可改；驳回重提（`28`）带出上次全部结论与照片，只标出被驳回项，不要求整页重拍。 |

| C8 | 二选一用分段控件，不用下拉或小圆点 | [NN/g #2 贴合真实世界](https://www.nngroup.com/articles/ten-usability-heuristics/) + [NN/g #7](https://www.nngroup.com/articles/ten-usability-heuristics/) | 「正常 / 有异常」保持两个等宽 ≥48 分段（`01 原则 9`）；不允许改成 Switch 或小 radio；不默认选中，AI 预选要显式标"AI 判定"来源。 |

## 七、与本项目冲突时的取舍（结论已定，不再讨论）

> 读法：**外部怎么说 → 本项目怎么做 → 代价**。执行以"本项目怎么做"为准，不要各自发挥。

| # | 冲突点 | 外部准则 | **本项目结论** | 依据与代价 |
|---|---|---|---|---|
| 1 | 系统返回 vs 自定义返回 | Apple：系统关闭/返回手势是用户预期，不应被自定义拦截 | **系统返回优先**：返回键 = 页面 `←`，同一逻辑。仅 L4 表单已填时拦一次（存草稿/放弃/继续）；弹层打开时返回只关弹层。禁止"再按一次退出" | 用户对"返回"的心理模型来自微信/抖音，改一次就多一次求助。代价：每个表单页要做"是否有未保存输入"判断。 |
| 2 | 批量条：常驻 vs 选中后才出现 | Apple：多选要先进入编辑模式（入口是隐藏的）；Material CAB：选中后才出现上下文条 | **常驻，未选中时置灰禁用，不隐藏**；`05 §4` 的"置灰或整条隐藏"按本条收敛为**置灰**。点击置灰条时给一句 toast「先勾选记录」，不是毫无反应 | 隐藏会让新用户永远不知道有批量能力（NN/g #6 识别优于回忆）。代价：占屏高——未选中时压到 56 高、只显示「已选 0 条」+ 一个禁用主按钮。 |
| 3 | AI 低风险默认勾选 vs 选中必须是人的显式动作 | Apple：选中应是人的显式动作 | **保留默认勾选**（业务要效率），三条硬约束：① 全选行写清「AI 已勾选 3 条」；② 提交必经一次人工确认弹窗；③ 被代勾的项在卡上留下可辨识标记（AI 一行） | 默认勾选把"漏审"风险转成"错审"风险，靠确认弹窗兜。代价：这条确认弹窗**不可省**，不能为省一次点击改成"再点一次即提交"。 |
| 4 | 阻断式确认 vs 可撤销 | Apple/NN/g：能用撤销就别用弹窗；Material：snackbar + 撤销是标准解 | **分两类**：会产生下游事实的（审核通过、驳回、签字、归档、批量处理）→ 只弹窗、**不给**撤销；纯本地的（取消选择、删草稿、清筛选）→ 不弹窗、给 5s 撤销。**禁止**"弹窗确认 + 再给撤销"叠加 | 审核通过会入工单池，撤销要连带撤销下游事实，成本远大于一次确认。叠加两者既慢又乱。 |
| 5 | 底部单主按钮 vs 并列双按钮 | Material FAB：一个主操作；Apple：一屏 1~2 个 prominent 按钮 | **页面底部恒为 1 个主按钮**，第二动作进 `⋯`；**只有弹窗内**允许并列（取消左、动作右）。批量条是例外之一（表达"选中态"）；**审核/确认态的"决策对"是例外之二**（`驳回 / 通过` 并列，见下） | 与 `01 原则 1`、`03 §2` 一致。**本轮修正**：审核不把「驳回」藏进 `⋯`——`26/32/44/17` 底部为 `驳回 / 通过`，两按钮定宽 + gap 12、驳回危险色不聚焦、都必须进弹窗，页面别处不得再有第二个实心主色块（`01 原则 1` 例外 1）。列表场景的驳回仍走批量条左位（B11）。代价：这几页不满足字面上的"底部一个主按钮"，靠"决策对"与"主操作 + 次要操作"的区分兜住。 |
| 6 | 五底栏（M3 建议 3~5 且可隐藏不适用项）vs 固定五 Tab | Material NavigationBar：3~5 项，可隐藏不适用的 | **固定 5 Tab，不按角色隐藏**；角色差异只体现在 Tab 内的宫格入口与页面动作 | 隐藏 Tab 会让"这 App 能干什么"不可预期，换班共用账号时更易误判。代价：维保工看到用不上的「卷宗库」，可接受。 |
| 7 | 字号：外部建议正文 ≥16 vs 项目正文 14~15 | Apple 默认正文 17pt；NN/g：中年起就需要更大字 | **正文下限提到 15**（14 只用于时间戳/单号等辅助信息），设置里给「大字模式」把正文拉到 17；**八档字号表不变**（26/22/17/16/15/14/13/12），只改"哪档当正文" | 使用距离 30~50cm、老花镜、机房光线差。代价：现有画板若用 14 当正文需改；不为它单独返工，改版时顺手改。 |
| 8 | 危险按钮位置（Apple 危险在 trailing vs 中文习惯右下确认） | Apple：主按钮在 trailing，Cancel 在 leading | **取消在左、动作在右**；但危险动作**不上主色、不默认聚焦**，并与取消拉开 ≥24 | 位置统一比"危险放哪边"更重要；危险感靠颜色与间距表达，不靠换位置。 |
| 9 | 触控目标：24（WCAG AA）/ 44（AAA、Apple）/ 项目 48 | WCAG 2.5.8 最低 24；2.5.5 与 Apple 44 | **取 48**；小控件（22 选择框、23 图标）靠**热区补到 48**，视觉尺寸不变 | 用户手部精细动作下降，常在戴手套、单手、走动中操作。代价：列表卡左列按 48 留宽（视觉仍 22），已画板左内边距需 +13。 |
| 10 | 半屏遮罩：可点关闭 vs 必须显式取消 | Apple：sheet 通常可下滑/点外部关闭；项目定为遮罩不可点 | **遮罩不可点关闭**（`02 §3`、`05 §5`），但必须有**三条**退出路径：明显的「取消」+ 把手下滑 + 系统返回 | 一线在确认弹窗误触遮罩会丢输入；三条出口保证不被困住（NN/g #3 用户控制与自由）。 |
| 11 | 加载提示的时机 | Apple：按钮内转圈即可；NN/g：及时反馈 | **<300ms 不显示**（避免闪烁）；300ms~1s 骨架；>1s 进度 + 可取消 | 弱网下闪一下又消失的 loading 会被当成"卡了一下"，反而降低信任。 |
| 12 | 空态：大插画 vs 纯文字 | Material 常见大插画空态；适老化研究倾向少装饰多说明 | **32 图标 + 一句说明 + 一个动作**，不放大插画 | 插画占屏且不解释原因；40~60 岁用户要的是"为什么空、点哪能继续"。代价：视觉上不如插画"高级"，接受。 |

### 8.2 评审一屏时的 12 个硬问题（有一条答不上就不算过）

1. 这一屏按系统返回/手势返回会发生什么？会丢输入吗？
2. 唯一的下一步动作是什么？第二个动作为什么不能进 `⋯`？
3. 有没有任何一个可点东西的热区小于 48×48？
4. 选中/异常/正常这些状态，除颜色外还有文字或图标吗？
5. 12~13 号的次要灰字在白底上够 4.5:1 吗？
6. 空的时候是"无数据""筛选无结果"还是"无权限"？选了哪一套？
7. 这个弹窗是"严重后果"还是"可撤销"？如果是后者，为什么不用撤销条？
8. 弹窗里有没有"确定要继续吗"或机制说明？
9. 按钮文案是动作结果（「通过 5 条」）还是「确定/是」？
10. 加载超过 1 秒时，用户看得见"在做什么"并能取消吗？
11. 200% 放大或系统大字号下，这一屏会裁字、重叠吗？
12. 有没有哪个字段只能滚轮选、只能手打、或必须重复录入？
