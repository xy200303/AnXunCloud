# AI云管家 · App 原型文档

App 端（uni-app + Vue 3）原型的**唯一施工依据**。设计画板在 Penpot，本文档集负责把"画板上为什么这么画、每页怎么点、哪些还没画"讲清楚，让下一个人不必重新推理一遍。

- Penpot 文件：<https://penpot.etvec.cn>，文件「AI云管家」/ 页面 `App 原型`，一屏一画板。
- 生成脚本：`.tmp/ds/*.js`（设计系统 `ds2.js`，注入方式见 `docs/品管家/原型图/penpot/README.md`）。
- 本文档集**不复制画板源码**，只做规范、清单、交互与审计；画板改动以 Penpot 实际内容为准。
- 外部依据（Apple HIG / NN-g / WCAG / Material 取证 + 取舍结论）在 `09-外部准则参考.md`；**本文档集的每条硬规则都能追到 09 的条目号或 08 的缺陷号或本轮教训编号**。

## 三、怎么用这份文档

**要新建一屏**

1. 在 `07-页面清单.md` 找到编号与优先级，确认它还没有画板。
2. 在 `04-逐页交互清单.md` 读该页的六段（入口 / 首屏 / 点哪 / 弹什么 / 空态失败态 / 角色）——这是验收口径，不是建议。
3. 按 `03-页面模板.md` 选骨架（列表页必须套"多选卡片 + 退出多选的两条路径 + 底部已选 N 条"，审核页必须带阻断弹窗），按 `06-视觉规范.md` 取值。
4. 建完在图里自检 `01-设计原则.md` 十二条（每条都有检查方法），再回填 `04` 与 `07` 的"已建 + 画板名"。

**要评审一屏**

按 `01` 十二条逐条过（答不上"检查方法"就不算过）；跨页问题查 `05`；老画板的已知缺陷查 `08 §4.2`/`07 §4.5`，不要重复报同一条；外部依据有争议时查 `09 §七`。

**要改既有页**

先读 `08-交互审计.md` 里该屏的缺陷条目与 `07 §4.5` 的返工项，改完在该条备注"已消除"并在 `04` 更新交互描述——两份文档同一次改，不允许只改画板。

## 四、维护约定

- 编号只增不改，`05` 永久留空，不复用；新页从当前最大号往后连续编号。
- 画板名 = `NN 页面名`，与 `04`/`07` 的页面名逐字一致（含空格与全/半角），否则脚本与导出对不上。
- 一屏多状态（识别中 / AI 改判 / 遮罩弹窗）优先做**同屏变体或独立小画板**（如 `26a 通过确认`），不新占编号；只有需要独立验收的（无法检查面板、AI 失败核查、驳回重提）才升为独立编号。
- 本文档只描述界面与交互，不写接口、不写数据库字段、不写实施排期（那三样在 `docs/品管家/` 的 01~14 与 `backend/`）。
- **新增/修改一条硬规则**：先改 `01`（规则 + 检查方法 + 来源），再改受影响的具体文件（`03`/`05`/`06`），最后在 §五 登记口径——不允许只在某一页悄悄改。

## 五、已知口径冲突（本文档已定，不再反复讨论）

整理时发现原文档之间互相矛盾，本文档集按下列口径定稿，逐条依据见各文件：

1. **字号**以 `06-视觉规范.md` 的 `26/22/17/16/15/14/13/12` 为准，**取代** `02-App框架与UI布局.md §7`「只用 13/14/16/18 四档」。底栏 `11` 合法（只在底栏文字）。
2. **扫一扫**在主页顶栏右侧固定入口，见 `02-信息架构与导航.md`；`02-App框架与UI布局.md §1`「放一级页面导航栏左上角」按本文执行。
3. **详情页只有一套骨架**：`26 审核详情` 与 `27 巡检记录详情` 共用同一骨架、按角色增减动作，不设"执行人版/审批人版"两套界面，见 `03-页面模板.md §2`。
4. **设备详情编号冲突**：画板现名 `28 设备详情`，但 `页面清单.md` 把 `28` 给了「巡检记录驳回重提」、设备详情是 `35`。本文以 `页面清单.md` 为准（`28`=驳回重提、`35`=设备详情），**建议把该画板改名为 `35 设备详情`**；本轮不动画板，`04`/`07` 均已标注此冲突。
5. **工单入池**按全自动：审核链通过即入池（与审核结论同一事务），不再由主管手工打包——按本轮既定决策执行，`04-工单系统设计.md §1`「本期保持不自动成单」及 `10` 号文档相应待确认项按此收口，见 `05-全局交互约定.md §3`。
6. **审计原文以画板为准**：`penpot/交互审计.md` 中"清单一节引用的 PNG 是旧图"的说明仍成立，`08` 只在结论处补"已建/未建"标注。
7. **外部准则与内部约定冲突**按 `09-外部准则参考.md §七` 的取舍执行。落地到本文档集的：批量条未选中时**置灰常驻不隐藏**；会产生下游事实的动作（审核/签字/归档/批量）**只弹窗不给撤销**；**正文下限 15**（14 只用于时间戳/单号/单位）；危险按钮与「取消」**gap ≥24**。
8. **多选必须能退出**（`03 §1`、`05 §4`）：全选行「清空选择」+「已选 N 条」点进已选清单逐条取消。只做"能进不能退"的多选算未完成——本条是对 09 B1 的采纳，代价是列表页多一个文字按钮与半屏。
9. **AI 低风险默认勾选保留**，但三条硬约束不可省：全选行写「AI 已勾选 3 条」、提交必经人工确认弹窗、被代勾项在卡上留 AI 一行（`09 §七.3`）。
10. **核验粒度**（`05 §2`）：单件必核验（扫码/NFC/围栏按配置）；整批/打包单不打卡、只逐台实时拍照；不允许分批提交。与 `AGENTS.md §4.5`「承接查验不集中打卡」同向。
11. **扫一扫常驻且唯一，三用途共用一个扫码页**（`05 §1`）：打卡 / 工单核验 / 设备查询靠入口参数区分；失败落 `63` 五类原因 + 三条动作，**永不提供"免核验继续"**。
12. **对比度入硬规则**（`06 §1.1`）：正文 ≥4.5:1、图形/边界 ≥3:1。`#86909C`（白底 3.2:1）**降为图标/大字/水印色**，正文次要灰改 `ink3d #6B7385`（4.7:1）；状态 pill 改"浅底 + 深字"（`okInk`/`warnInk`/`dangerInk`）；`#C9CDD4` 只做装饰。
13. **几何口径校准**（`06 §3`）：卡内容宽 **326**（旧文写 330，按 358−16×2 校准）；右边线 = 卡左 **+342**；选择列 **48**（视觉 22）、列间距 10 → 列表卡文字宽 **268**。改选择列必须同批改文字宽，否则破"一条右边线"。
14. **空态三分**（`03 §6.1`、`05 §7`）：无数据 / 筛选无结果 / 无权限，三套文案三套动作，**禁止共用"暂无数据"**。
15. **不做凭空功能**（`01 原则 12`）：每个入口必须能在 `04` 或 `docs/品管家/` 找到依据，找不到不画（例：登录页不做"扫码登录"）。
16. **审核/确认态底部允许"决策对"并列**（`01 原则 1` 例外 1）：`26/32/44/17` 底部为 `驳回 | 通过`，两按钮定宽 + gap 12、驳回危险色不聚焦、都必须进弹窗。**这是对 `09 §七.5`（"驳回放右上 `⋯`"）的有意偏离**：理由是两个动作是同一决策的两侧，藏一个会让主管多点一次且难发现；代价是这几页不再满足字面上的"底部一个主按钮"，因此**页面其它位置不得再有第二个实心主色块**，列表场景的驳回仍走底部批量条左位。
