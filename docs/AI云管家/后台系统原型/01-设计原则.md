# 01 设计原则

> 后台专属 10 条，全部可直接照做。评审图与写代码都按这十条挑错；与其他文档冲突时以本文与 `README.md §五` 为准。
> 依据：`13-后台管理系统设计.md §0/§7/§9`、`14-权限与岗位模型.md §1.5/§3.2`、`frontend/src` 现有实现（Element Plus）、后台原型 README 的"已踩过的坑"。
> App 端**十二条**在 `../APP原型/01-设计原则.md`（每条带检查方法），**不通用**——手机是"一屏一个下一步"，后台是"一屏看清一批、就地办完"；但**弹窗与撤销两分法、空态三分、对比度**三条两端同口径。

## 1. 后台是超集，但不复制 App

App 能办的管理动作后台必须有等价入口，**反向不成立**（`13 §0`）。因此：

- 审核、签字、确认类动作后台要有，但用的是**表格 + 批量 + 抽屉**，不是把 App 的卡片流搬过来。
- App 侧做不了的（流程编排、版式编辑、批量导入、能力与密钥）后台**独有**，不因为"手机也能用"而砍参数。
- 同一能力在两端只有一套业务规则、一套权限点、一套审计口径。

## 2. 信息密度优先，一屏看一批

后台的价值是"横向比较 + 批量处置"，不是"看得舒服"。

- 默认 **1440×1440 视口下首屏可见 12~15 行表格**；不放大留白、不卡片化列表。
- 表格列按"能决策"取舍：对象标识 → 状态 → 时间 → 责任人 → 异常/风险 → 操作。**同一屏不出现两列表达同一事实**。
- 长文本（合规标准、驳回原因）进抽屉，不在表格里折三行。
- 数值右对齐、单位随列头写一次（`MPa` / `台` / `册`），不逐行重复。

## 3. 列表页五件套，缺一不算完成

所有列表页固定骨架，**不按页另设计**：

```
页头（标题，必要时右侧主操作）→ 筛选区（行内 el-form，≤6 项，超出收「更多筛选」）
→ 工具栏（主操作 + 批量动作 + 导入导出 + 刷新）→ 表格（表头全选/半选 + 骨架行 + 分页）
```

- 表头选择框 = **当前筛选结果全选**，弹确认写清"将选中 N 条（不是本页 N 条）"；筛选变化清空选择并说明。
- 分页默认 20，可选 **10 / 50 / 100**，**上限 100 是服务端口径**（`09 §5.2`）；超 1000 行走虚拟滚动。
- 行内动作 ≤3 个直接显示，多的进「⋯」下拉；危险动作永远在最后且带 `type="danger"`。

## 4. 详情抽屉优先，整页只给复杂编辑器

- 默认 `el-drawer`：列表详情 **480~620px**、需要左右对照（问题照片 vs 整改照片）**760px**、模板版式与批量录入才整页。
- 抽屉的价值是**保留列表上下文**：遮罩要淡（`rgba(0,0,0,.3)`），关闭后回到原行、原筛选、原滚动位置。
- **不弹多层**：抽屉里不再叠第二个弹窗；必须二次确认时用抽屉内联确认区或 `el-popconfirm`。
- 建改一律抽屉/弹窗，**不跳页创建**（`docs/品管家/后台原型/README.md` 统一口径）。

## 5. 配置页必须当场回答"配完会怎样"

`14 §3.2` 的硬要求：配置页不回答结果，用户就得去别处验证，断链永远看不见。

- 右侧（或抽屉下半部）**实时显示有效结果**：每个审批环节的候选人数、断链标红 + 就地修复入口、配置来源（继承自上级 / 本级覆盖 / 未配置）。
- 保存前给**影响范围**（"将影响 3 个小区、12 条未送审记录"），不是保存后才报错。

## 6. 危险操作一律阻断 + 说清后果

停用、删除、作废、撤销 token、批量通过/驳回、归档、重出报告——**先确认，再执行**：

- 确认框写三件事：**对谁**（对象 + 条数）、**会怎样**（后果一句）、**能否撤销**（"不可撤销"必须出现）。
- **有业务数据的对象不做删除**，改「停用」并提示影响（`13 §9.4`）。
- **按钮文案写结果**：`通过 5 条` / `驳回并通知` / `签字归档`，禁止只用「确定 / 是 / OK」（`09 D4`）。
- 危险按钮用 `type="danger"`，与「取消」不同宽、物理分开（**间隔 24**）、**不默认聚焦、不被回车默认触发**。
- **撤销两分法**（`09 §七.4`，与 App 同口径）：会产生下游事实的动作（通过/驳回/签字/归档/批量/维保确认）**只弹确认框、不给撤销**；纯本地动作（清筛选、取消选择、删草稿）**不弹框、给 5s 撤销 toast**。两者**不许叠加**。
- 审批、签字、归档、确认类**不做乐观更新**：等服务端确认再改 UI（`13 §9.4`）。

## 7. 权限是"能不能做"，范围是"能看到哪些"

按 `14`：**角色给权限点，任职行给范围，节点绑角色决定能不能审这条**。

- 无权限 = **入口不出现**（菜单不渲染、按钮不渲染），不留禁用态；深链进入给独立 403 态。
- 数据范围为空（项目级角色无任职行）**fail closed**：给"你没有查看范围内的数据"+ 指向谁能开，**不显示空表当"没有数据"**。
- 候选人身份自带该条记录的读权限（"能审必能看"），不再叠一层主管标志判断。
- 不设"审批类权限点"：菜单可见性由"角色是否被任一节点绑定"推导，别在权限树里塞审核签字项。

## 8. 批量只用一次确认 + 结果四分

- 批量动作串起来：勾选 → 一次确认（写清 N 条 + 逐条清单入口）→ 执行 → **已处理 / 成功 / 失败 / 跳过**四个数分开。
- **不把"处理完成"写成"全部成功"**；失败给明细、导出、**仅重试失败**，已成功的项不重做（`13 §9.3`、`07`）。
- 长任务走 River 持久状态，刷新不丢；离开页面停止轮询。
- 跨范围/跨小区的批量**直接阻断并提示拆分**，不静默合并。

## 9. 字号只有五档，间距只用 8 的倍数

- 字号 **20 / 16 / 14 / 13 / 12**（页面标题 20、区块标题 16、正文与表格 14、表格内次要 13、辅助 12）；看板大数 28 是唯一例外。
- **对比度是硬要求**（`09 E2`，实测表见 `../APP原型/06-视觉规范.md §1.1`）：正文 ≥4.5:1、图形/边框 ≥3:1。表格内 12~13 号次要文字若用 `#86909C`（白底仅 **3.2:1**）不达标，改用 `#6B7385`（4.7:1）；`#C9CDD4`（1.6:1）只做装饰，不做文字与控件边界。
- 间距一律 **8 的倍数**（8 / 12 是 8+4 唯一例外档 / 16 / 24 / 32）；不出现 3、5、7、9、10 这类碎值。
- 表格行高 **48**、表头 48、工具栏高 32（`small` 按钮）、标签条 40、顶栏 50、侧栏 220（收起 64）。
- 颜色只走 `06-视觉规范.md` 登记的 token，组件内不写裸色值，**禁止 emoji 当图标**。

## 10. 一屏一态、一事实一次

- **一张原型 = 一个屏幕状态**：列表与详情分开、不同 Tab 各一张、弹窗必须真浮在遮罩上；不纵向堆叠多页（`docs/品管家/后台原型/README.md`）。
- 同一事实一屏只出现一次：`共 24 条` 只在分页区出现，不在标题、统计条、页脚各写一遍。
- 空态分四类，文案与下一步都不同：**无数据 / 筛选无结果 / 无权限 / 配置缺陷**（`13 §9.2`）；再加一类**请求失败**——就地重试，不整页报错。**禁止用一句"暂无数据"糊过四种情况**；筛选过窄还要给「清空筛选」。
- 原型里**不写规则说明段、不写配置解释、不写"点击查看"**；规则写文档，界面只表达结果。
- **页头不写重复功能的一句话副标题**；说明设计意图、操作教学、技术实现的文字不进入界面。时间、状态、数量、来源、错误原因和必要表单约束可以保留。
