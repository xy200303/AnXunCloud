# 02 信息架构与导航

> 定"哪一页属于哪一层、从哪进、回哪去、谁能看见"。逐页细节在 `04-逐页交互清单.md`，跨页交互规则在 `05-全局交互约定.md`。

## 1. 页面骨架（1440 视口）

│ 深色 #1F ├────────────────────────────────────────────────────────────────┤
│ 2D3D     │ 标签条 40：[工作台 ×][小区列表 ×][批次详情 ×] … 关闭其他 / 全部        │
│          ├────────────────────────────────────────────────────────────────┤
│ Logo 56  │ 内容区：底色 #F5F6F8，内边距 24；页头（标题 20 + 必要时右侧主操作）│
│ 菜单     │        → 筛选卡 → 表格卡（工具栏 + 表格 + 分页）                     │

| 区域 | 尺寸 | 规则 |
|---|---|---|
| 侧栏 | 220（收起 64） | 深色底 `#1F2D3D`，分组可折叠，`unique-opened` 只展开一个分组；收起后只留图标 + 悬浮提示 |
| 顶栏 | 高 50 | 左侧折叠钮 + 面包屑；右侧五项固定顺序：简洁模式开关 / 租户切换（仅超管且租户数 >1）/ 全屏 / 消息（未读角标）/ 用户下拉（个人中心、修改密码、退出登录） |
| 标签条 | 高 40 | 打开即加标签、同路径不重复；`工作台` 固定不可关；右键关闭其他/全部；详情页加载后可用业务名替换标签名（如"字典数据-通用状态"） |
| 内容区 | 最小宽 1200 | 页头与卡片间距 16；表格卡内边距 16；分页右对齐、上间距 16 |

**面包屑即层级**：`一级 / 二级 / 当前对象`（如 `模板中心 / 检查项模板 / 消火栓箱巡检模板`）。抽屉打开**不改变面包屑**（抽屉是行内状态的展开，不是新页面）。

## 3. 角色与可见性

角色按 `14 §1.3.1` 内置九个，UI 在项目上下文显示为「岗位」：

| 角色 | `scope_level` | 可见深度 | 后台可见范围 |
|---|---|---|---|
| 超级管理员 `super_admin` | platform | — | 全部菜单；**执行操作必须先选目标租户**（顶栏切换器），平台管理全开 |
| 租户管理员 `tenant_admin` | tenant | — | 本租户全部小区；除平台管理外全开 |
| 项目经理 `project_manager` | project | 全项目 | 任职小区：看板、小区设置、巡检/工单/承接、模板只读、报告、审批流程只读 + 项目覆盖 |
| 品质主管 `quality_supervisor` | project | 全项目 | 同上，偏巡检审核与报告 |
| 工程主管 `engineer_supervisor` | project | 全项目 | 设备台账、维保生效确认、工单 |
| 巡检员 `inspector` | project | 仅本人 | **后台无执行侧菜单**（执行在 App）；仅巡检记录/我的任务只读（有权限点时） |
| 维保工 `maintainer` | project | 仅本人 | 设备台账只读、维保记录 |
| 楼管员 `building_manager` | project | 仅本人 | 责任楼栋（`building_ids`，**分派筛选，不是权限边界**） |
| 消控值班 `fire_duty` | project | 仅本人 | 值班相关只读 |

矩阵规则：

- `●` 可进；`○` 只读；`—` 无入口（深链进入给 403 态）。
- **无任职行的项目级角色 = 无范围**（fail closed），列表为空时给"你没有查看范围内的数据"，不显示假空表。
- 审批类页面（`96` 审核、`92` 工单审核、`80` 签字）**不靠权限点**：是否为该记录当前节点候选人是唯一判定，候选人身份自带读权限（`14 §1.5.3`）。角色未被任一节点绑定时，这些入口推导为不显示。
- 平台管理整组只对超管渲染；租户侧同名菜单（岗位/审批流程/AI 配置）用**同一组件 + `scope` prop**，不在前端写两套。

## 4. 简洁模式（面向低配置使用方）

顶栏右上「简洁模式」开关，默认开，选择存本地：

- 打开时隐藏 `/system/roles`、`/system/posts`、`/system/sign-assets`、`/system/review-flow`、`/system/brand` 与 `/platform` 整组。
- 它是**纯展示层过滤**，不拦路由直达、不改权限；用于少配错，不用于当权限用。
- 原则：简洁模式消失的入口必须仍能通过深链或平台侧到达，不能造成"配不了"。

## 5. 层级与返回

| 层 | 形态 | 回退方式 |
|---|---|---|
| L1 | 一级菜单落地页（列表/看板） | 切菜单或标签 |
| L2 | 列表 + 抽屉详情 | 关闭抽屉 → **回原行、原筛选、原页码、原滚动位置** |
| L3 | 整页编辑器（模板版式、批量录入、小区向导、批次详情） | 面包屑上级 或 标签条关闭；**有未保存改动时拦截并给"保存草稿/放弃/继续编辑"** |
| 弹窗 | 新建/确认/导入 | `取消` / `×` / `Esc`；危险确认框只给显式按钮 |

- 后台**不用"← 返回"按钮**：回退靠面包屑与标签条，列表页不出现返回箭头。
- 抽屉内不做页面跳转；需要换对象时关闭当前抽屉再开新的（避免抽屉套抽屉）。
- 标签条关闭最后一个页签回到 `工作台`（固定 affix）。

## 6. 入口与出口对照

| 从哪里发起 | 完成后去哪 | 为什么 |
|---|---|---|
| 新建/编辑（抽屉、弹窗） | 关闭 → 列表原地刷新并**高亮该行** | 不跳页、不丢筛选 |
| 审核通过 / 驳回（96、93、80） | 抽屉关闭 → 行状态就地更新；批量则留列表并给结果条 | 审批类不做乐观更新，以服务端回执为准 |
| 报告生成（80b） | 关闭弹窗 → 列表新增一行（`pending_review`）+ 该行显示生成进度 | 长任务走 River，刷新不丢 |
| 批次新建（72） | 弹窗关闭 → 自动进入 `84 批次详情`（分工） | 建完必须马上分工，避免"建了没人管" |
| 模板新建（53） | 创建完成 → 进 `41 条目编辑器` | 新建模板后继续核对标准检查项 |
| 批量动作（74/75/91/96/97） | 原地刷新 +（有失败时）结果面板列出失败明细 | 成功不跳页，失败给明细与仅重试失败 |
| 断链/配置缺陷修复（77/82/83） | 就地修复后回该行，断链标记消失 | 修复路径必须闭环，不能"告警了没处改" |

## 7. 深链与直达

- 深链格式 `#/<模块>/<页>?id=<对象ID>&tab=<Tab>`；对象身份只用 ID，不用名称。
- 通知点击 → 直达对象抽屉（打卡记录 → 96 抽屉、工单 → 92 抽屉、报告 → 80 抽屉、批次 → 84、断链告警 → 77/83 对应 Tab）。
- 直达失效三类分开写：**对象已删除 / 已关闭或归档 / 无权限**，不进空白页、不静默回列表。
- 审核/签字类直达：若当前人已不是该节点候选人，抽屉只读 + 一行"当前环节已变更"，不给动作按钮（与"无权限"区分）。
