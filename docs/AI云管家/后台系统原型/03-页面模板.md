# 03 页面模板

五类骨架覆盖全部 43 条：**每个页面以"列表（§1）或看板（§5）"承载入口，细节由详情抽屉（§2）/配置页（§3）/审批流（§4）承载**；其中 7 条是整页编辑器、向导、对话等特殊页（§6），不套列表骨架。**新建页先选骨架，不许另起一套**；骨架只允许"增删列与动作"，不允许改层序。
全部用 Element Plus 组件表达（不写自定义组件名），取值见 `06-视觉规范.md`。

## 1. 列表页模板（后台主力，34 页）

用于：`74 75 76 79 79b 79c 79d 79e 79g 79f 80 80b 80c 81 91 92 93 94 96 97 98 99 100 102 103 104 105 106 107 108 109 40 42 70 72`（其中 `92 / 79b` 以列表行为入口开抽屉）。

```
┌ 页面标题（20）                                                     [主操作] ┐
├──────────────────────────────────────────────────────────────────────────┤
│ el-form inline：小区▾ 状态▾ 时间范围▾ 关键字🔍 …（≤6 项）  [查询][重置][更多筛选⌄] │
├──────────────────────────────────────────────────────────────────────────┤
│ [批量动作1][批量动作2][导入][导出]   已选 3 条 · 同小区同专业          [⟳刷新][列设置] │
├──────────────────────────────────────────────────────────────────────────┤
│ ☐ │ 对象标识        │ 状态 pill │ 时间       │ 责任人 │ 风险/异常 │ 操作        │
│ ☑ │ 1栋3楼通道消火栓 │ 待打包    │ 10-23 16:40│ 李敏   │ 水带破损  │ 详情 打包 ⋯ │
│ ☐ │ 3栋B1 配电间     │ 进行中    │ 10-23 15:02│ 王强   │ 逾期 2 天 │ 详情 改派 ⋯ │
│ …（骨架行 10 条，首屏 12~15 行）                                          │
├──────────────────────────────────────────────────────────────────────────┤
│                                          共 24 条  [20/页⌄] ‹ 1 2 ›  跳至 □ │
└──────────────────────────────────────────────────────────────────────────┘
```

规则：

1. **筛选区立即可用**：首屏加载时筛选与表头先出，表格出骨架行，不用整页 spinner 盖住（`13 §9.1`）。
2. 表头选择框 = 当前筛选结果全选，点它先给确认（"将选中 24 条，不是本页 20 条"）；部分选中 → `indeterminate` 半选。
3. **必须能退出多选**：工具栏「已选 3 条」可点 → 「已选清单」弹层（逐条移除 + 一键清空）；再给一个常驻「清空选择」。筛选/切页变化 → 清空已选并提示。批量动作前必须一次确认，标题写清条数（"将通过 24 条"），确认框里给逐条清单入口。
4. 行内动作 ≤3 个直出，其余进「⋯」；**危险动作（停用/作废/删除）永远在下拉最末**且 `type="danger"`。
5. 对象标识列可点（整行可点也行）→ 开抽屉；表格行**不画"查看"按钮占位**。
6. 空态插 `el-empty` 于表格位置，**不隐藏筛选与工具栏**（否则用户以为页面坏了）；文案按 `05 §9` 分 **无数据 / 筛选无结果 / 无权限 / 配置缺陷** 四类（+ 请求失败就地重试），筛选过窄必须给「清空筛选」。
7. 分页固定右下；切换分页/排序只遮罩表格区，**保留滚动位置**。
8. 需要"列很多"的页（97 设备台账、103 设备接入）配「列设置」抽屉，勾选显示列并存本地，不动数据权限。

**特例**：`95 任务监控`保留卡片列表（监控要按任务看进度条与角标，表格塞不下），但**筛选区、工具栏、分页、批量规则与本节完全一致**。

## 2. 详情抽屉模板

用于：`92 工单详情 760` / `96 打卡详情 620` / `80 报告详情 620` / `79b 添加供应商` / `77 83 小区设置 760` / `81 权限配置` / `91d 工单设置`。整页详情只有 `84 / 84b`（批次详情要左右对照类别与签署表）。

```
                                    ┌ el-drawer 620 / 760 ─────────────────┐
                                    │ 标题（对象名）              [⋯][×]    │
                                    │ ─────────────────────────────────────│
                                    │ 身份行：类别 pill · 状态 pill · 单号   │
                                    │ 一句事实：小区 · 提交人 · 时间 · N 项  │
                                    │ el-steps 状态链路（可选，5 节点）      │
                                    │ ── 区块标题 16：现场事实 ──────────── │
                                    │ el-descriptions :column=2             │
                                    │ ── 区块标题 16：逐项结论（异常 2/5）── │
                                    │ 问题照片 ┃ 整改照片（左右对照）       │
                                    │ ── 区块标题 16：审核进度 ──────────── │
                                    │ ● 已完成 王强 10-23 16:40             │
                                    │ ○ 待处理 当前节点：打卡复核           │
                                    │ ─────────────────────────────────────│
                                    │           [次操作] [主操作（唯一）]    │
                                    └──────────────────────────────────────┘
```

规则：

1. **一对象一骨架**：执行人、审批人看同一抽屉，差异只是"有没有主操作按钮"；审批人看到的证据与执行人提交时完全一致，不压缩成摘要行。
2. 区块顺序固定：**身份 → 事实 → 证据 → 结论/AI → 流程 → 留痕 → 操作**；新内容只加区块，不改顺序（`CheckinDetailDrawer.vue` 现结构即此）。
3. 抽屉底部操作区**最多一个主按钮**；第二个动作进「⋯」或工具栏，不并排两个竞争性主按钮。
4. 抽屉内**不再弹窗**：需要理由时用抽屉内联 `el-input` + 校验（驳回原因、改派原因、关闭原因），提交时整体确认。
5. **审核 / 签字 / 归档 / 维保确认 / 批量处理**这类会写下游事实的动作，提交前必须有**一次确认**（`el-messagebox` 或确认条）：标题写"通过这条记录 / 通过 24 条"、理由必填项就地校验、按钮文案写结果（`通过` / `驳回并通知` / `签字归档`），危险按钮 `type="danger"` 与「取消」间隔 24、不默认聚焦（`01 §6`）。**这些动作不给撤销**；纯本地动作（清选择、删草稿）不弹框、给 5s 撤销提示。
6. 抽屉宽度只有三档：**480 / 620 / 760**；超过 760 的内容说明它该做成整页。
7. 关闭抽屉**必须**回到原行、原筛选、原页码、原滚动位置。

## 3. 配置页模板（配完要能当场验证）

用于：`77 83 小区设置`、`81 岗位权限`、`90 巡检规则`、`91d 工单设置`、`101 企业品牌`、`79c 能力绑定`、`79d 助手与 Agent`、`79e 配额`、`107 系统配置`、`102 社区运营`。

```
┌ 配置标题 · 作用域（租户默认 / 本小区覆盖）        [来源: 继承自租户默认][恢复默认] ┐
├───────────────────────────────────────────────┬───────────────────────────────┤
│ 左：配置项（el-form label-width 140）           │ 右：实时结果面板（宽 320，随改随算）│
│  开关 el-switch / 数字 el-input-number          │ ── 生效结果 ──                 │
│  下拉 el-select（可能多选）/ 文本域 el-input     │ 打卡复核：2 人候选 ✓           │
│  子表 el-table（类型级配置逐行）                 │ 月报审批：**0 人 → 断链** [去加人] │
│                                                │ 签署：未配置 [去配置]           │
│ [取消] [保存]                                   │ ── 影响范围 ──                 │
│                                                │ 保存后将影响 3 个小区 / 12 条记录 │
└───────────────────────────────────────────────┴───────────────────────────────┘
```

规则：

1. **右侧结果面板是硬要求**（`14 §3.2`）：候选人数、断链标红 + 就地修复、配置来源（继承 / 覆盖 / 未配置）三样都要有。
2. 分层配置**必须显示有效值与来源**：本页覆盖 → 标"本租户覆盖 + 恢复默认"；未配 → 标"继承自上级（值=xxx）"；留空即回落，不用 NULL 占位。
3. 键值型配置（107）用表格 + 三列固定：`可被下级覆盖` / `密钥` / `来源`；密钥类**只显掩码**（`sk-****abcd`），不回显明文。
4. 保存前给影响范围；**审批、签字、归档相关配置保存要写明"影响未送审记录数"**。
5. 校验就地反馈到字段；保存中按钮 `loading` + 禁用，失败保留已填内容。

## 4. 审批流模板（复用 `ReviewFlowEditor.vue`，不另设计）

用于：`82 审批流程配置`（租户默认 + 小区覆盖入口）、`83 岗位编制·流程与签字`（同一设计器在小区内的入口，只改绑定与签署方式）。

```
┌ 从平台预置重置  作用范围 [租户默认(全部小区) ▾] ＋为某小区建覆盖      名单预览按[小区▾] 保存 ┐
├ 链路切换 el-tabs：打卡审核链 │ 维保登记审核链 │ 报告审核链 │ 工单审核链 │ 承接查验审核链 ┤
│  开始 → ◎ AI 初判（AI 闸门）→ ◎ agent 预审 → ◉ 打卡复核（品质主管·任一人）            │
│         ↑↓✕  实际审核人：李敏、周强                                                    │
│  ⊕ ← 连线上加号：插入环节（人工 / AI 闸门 / agent 预审）       ↑↓✕ [改绑岗位▾]            │
│  ◉ 维保生效确认（工程主管）  当前无人能审 → **挂起并告警，不自动跳过** [去配人员]            │
│  ◉ 月报审批（项目经理）  跨小区报告解析各地项目经理 → 结束                                 │
│  AI 环节三分支泳道：on_pass→下一环节  on_abnormal→转人工  on_review→goto:N（仅向后·仅人工）  │
└ 保存前校验：职责名 / 绑定岗位 / goto 目标 / 断链 → 不通过则阻断 ─────────────────────────┘
```

规则（与 `ReviewFlowEditor.vue` 现有交互一致，**不换成自由画布**）：

1. **垂直链 + 连线「⊕」插入**，环节增删后序号自动重排；`goto` 只能向后跳到人工环节，不建环、不建不可达节点。
2. 环节**按职责命名**（打卡复核 / 维保生效确认 / 月报审批），**不按角色命名**；环节直接绑岗位，绑错只改绑定不改名字（`14 §1.5.1`）。
3. **名单预览内联在环节卡内**（实际审核人姓名），顶部按小区切换预览；候选 0 人 = 断链，标红 + `去配人员` 直达 `77`，**不自动跳过**；空名单三态文案分开：`unconfigured` 未配置岗位 / `no_member` 岗位无在职成员 / `skipped` 已跳过。
4. 小区覆盖显示"覆盖租户默认"，并提供"恢复继承"；**增删环节与改职责名回 `82`**，小区层只改绑定与签署方式。
5. 五条链并存但**一次看一条**（el-tabs）；`83` 抽屉只显示已实现的**三条**（打卡 / 维保 / 报告签字），待建链不出现（`README §五.10`）。
6. 编辑要提示"修改只影响之后进入链的记录，在途记录按进入时的快照走"；`报告签字流程` 不支持 AI 环节与跳转，只有职责名 + 绑定岗位 + 签署方式（任一 / 全部）。

## 5. 看板模板

用于：`78 运营看板`（含覆盖率/及时率/巡更达成率/绩效四个统计子页）。

```
┌ 问候条：早上好，李伟 · 戎安华府 · 3 个小区在管                       [期间▾] ┐
├ 告警区（有才出现，3 类）：断链 2 个小区 · 配置缺陷 5 个点位 · 队列积压 12 条     │
├ 三张环形进度下钻卡：今日任务完成 82% │ 打卡审核通过 95% │ 整改闭环 68%（点卡下钻）│
├ 近 7 天趋势（折线）                              各小区今日执行（条形，升序，<100% 标橙）│
├ 执行动态时间线（谁在几点提交了什么）                          待办告警（逐条可点去办）│
└ 顶部子页标签：概览 / 覆盖率 / 及时率 / 巡更达成率 / 绩效                          ┘
```

规则：

1. **按小区分行、不取平均**（`13 §8`）：合计行在底部且标明范围（"3 个小区合计"）；垫底项自动排最前。
2. **只管一个小区的账号不显示横向对比区**，不制造噪音。
3. 每卡独立加载与重试，一卡失败不拖垮整屏；**失败不显示假零**，显示「—」+ 重试。
4. 口径标注：现场已提交 ≠ 审核通过，统计说明写在卡片副标题里，不写在页脚。
5. 收费率/报事类模块未上线前，生产看板不展示对应指标，不用演示数值冒充真实经营数据；原型也不将其画成已可用能力。
6. 图表走现有 `Echart.vue` 异步组件 + `empty-text` 空态；颜色用 `CHART_COLORS`，不新造色。

## 6. 特殊页（不套上面骨架）

| 类型 | 页面 | 骨架要点 |
|---|---|---|
| 整页编辑器（模板条目） | `41` | 顶部模板信息条 + 条目表格（排序/项名/值类型/必拍/合格标准）+ 底部 `保存草稿 / 发布启用`；新增条目走右侧抽屉表单。**只管检查标准，不管输出属性** |
| 整页向导 | `59` 新项目上线、`43` 批量录入 | `el-steps` 横向三步；每步可暂存草稿；最后一步给校验结果与"必填未填"清单。向导不弹窗，不用 `el-dialog` |
| 整页详情 | `84` 批次详情、`84b` 报告与签署 | `84` 展示类别进度；`84b` 用单表展示签署状态，配置统一回 `82 / 83`，不与检查结果、快照和签署说明堆叠 |
| 对话页 | `64` PC 助手 | 全屏单会话消息流（思考过程折叠 + 结果卡 + 写操作确认条）+ 底部输入区；**不用左栏会话列表、不弹系统弹窗**，写操作在消息内出确认条 |
| 平台专属（约束，不是新骨架） | `104~109` | 仍是"列表 + 抽屉"；额外硬约束：平台操作**必须显式指定租户**（顶栏切换器或弹窗内选择），不隐式落到默认租户 |

### 6.1 空态插槽（四类，插哪儿）

空态的**文案与规则**只在 `05 §9` 定义一次；本节只说"插在哪个位置"，避免每页各想一遍。

| 模板 | 空态位置 | 保留什么 | 不做什么 |
|---|---|---|---|
| 列表（§1） | 表格位置整块 `el-empty` | 筛选区、工具栏、分页容器 | 不隐藏筛选、不显示假零、不缩成一行小字 |
| 详情抽屉（§2） | 区块级空态（如"无照片证据"） | 其他区块与底部操作 | 不整抽屉替换成空态（除非对象已被删除 → 给"已删除/已关闭"） |
| 配置页（§3） | 子表/结果面板空态 | 左侧配置项 | 不把"尚未配置"写成"没有数据"——配置缺陷要单独一类 |
| 审批流（§4） | 环节卡内 `no_member` 提示 | 链体其余环节 | 不自动跳过、不把断链渲染成空环节 |
| 看板（§5） | 卡片内 `empty-text` + 重试 | 其他卡片与期间选择 | 不整页空白、不显示假零 |
