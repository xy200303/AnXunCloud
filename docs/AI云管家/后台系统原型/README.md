# AI云管家 · PC 后台原型文档

后台（PC 管理端）原型的**唯一施工依据**，与 App 端文档集 [`../APP原型/`](../APP原型/README.md) 并列。当前交付为 **HTML 静态原型**：保留旧版 41 页精修并新增 `79g 配额`，再按简化方案移除 `90`、`80c`、`93`、`91d`、`102`、`103`、`109`，共 43 页。旧目录与 App 原型不修改。

- 可编辑正文：`fragments/*.html`；菜单、标题与面包屑：`fragments/meta.json`。
- 完整静态页面：`src/*.html`，直接用浏览器打开即可评审。
- 逐屏 PNG：`预览/html/*.png`，视口 **1440×900**，输出为 2 倍图。
- 画廊：`index.html`；渲染与校验脚本：`render.py`、`verify.py`。
- 共享精修样式：`assets/refine.css`。`预览/v2/` 仅为此前 Penpot 试验遗留，不属于当前交付。
- 真实实现：`frontend/src`（Vue 3 + Element Plus，**不另起工程**）。原型不证明接口、权限或交互功能已经实现。

## 三、使用与维护

全量渲染与校验：

```bash
python "docs/AI云管家/后台系统原型/render.py"
python "docs/AI云管家/后台系统原型/verify.py"
```

单页渲染可传编号或完整图名，例如 `.../render.py 78`、`.../render.py 91d`。

修改页面时：

1. 在 `07-页面清单.md` 确认编号与图名，在 `04-逐页交互清单.md` 读该页验收口径。
2. 先读对应 `frontend/src/views` 实现，按 `03` 选骨架、按 `06` 取值。
3. 只编辑 `fragments/*.html` 与 `fragments/meta.json`；`src/` 和 PNG 由 `render.py` 生成，不直接改。
4. 保持一屏一态，不放设计批注、规则说明段和低对比度小字。
5. 重新渲染并跑 `verify.py`，同步 `04`、`07`、`08` 的状态与结论。

## 四、既定决策

1. **后台不复制 App**：列表用筛选区 + 表格 + 行内动作 + 批量选择 + 分页；审核用表格与抽屉，不用 App 卡片流。
2. **详情用抽屉**：只有复杂编辑器、批量录入与向导用整页；一屏只表达一个抽屉或弹窗状态。
3. **权限配置 = 抽屉 + `el-tree`**；审批链复用 `ReviewFlowEditor.vue` 的约束结构交互，不换自由画布。
4. **工单只做一次主管审核**：整改提交后进入待审核，主管通过即闭环；不设复查、复查任务或 `91d` 工单设置。共享审批链集中 `82`，项目覆盖集中 `83`，业务页只展示执行状态。
5. **模板三层分开**：L1 检查项模板、L2 资产字段方案、L3 输出模板；承接查验内容模板独立。
6. **报告只写册数不写册号**：承接查验按类别名显示，册号待定，不硬编码 1~6。
7. **角色即岗位**：系统与平台只有「岗位」一个菜单；范围由任职行决定，审批节点直接绑角色。
8. **视觉语言用 Element Plus**：主色 `#2B5AED`，深色侧栏 + 白顶栏 + 灰底内容区。

## 六、边界

本目录交付的是静态 UI 原型。空态、加载、失败、无权限、按钮动作、接口、数据库、租户隔离、候选人判定与签字归档仍需在真实实现阶段验收，不以 HTML 或 PNG 作为完成证明。
