# 11 承接查验业务流程说明（甲方对齐稿）

> 本文把承接查验的完整业务流程、角色分工和后台配置一次说清，供双方逐条对齐确认。
> 技术设计细节以 [05 承接查验设计](05-承接查验设计.md)、[08 模板系统设计](08-模板系统设计.md) 为准；本文与它们冲突时，以本文的业务口径为准并回写 05/08。

## 1. 业务定位与交付物

承接查验是新物业接管小区时的**集中性交接检查**：把移交方（建设单位/原物业）的资料、房屋、设施设备等逐项核查一遍，留下事实记录，产出正式台账报告，作为交接依据。

按甲方口径，承接查验台账分三类：

| 类别 | 适用场景 | 母版现状 |
|---|---|---|
| ① 物业机构更迭承接查验 | 换物业公司时的交接 | 已有六册母版：物业资料、房屋本体、设施设备、室外场地、物业用房、地下车库 |
| ② 新建物业承接查验 | 新建房屋交付前排查 | **母版尚未提供，待甲方补充**；未提供前系统不臆造其册号与表型 |
| ③ 物业分户验收 | 户内专项核验（一户一档） | 已有母版：分户验收记录表（入户门/土建/室内门窗/厨卫/水电表/强弱电）+ 楼栋汇总表 + 问题照片表 + 水电表底数 |

六册的册号只有部分能证实（房屋本体第2册、设施设备第4册、地下车库第6册；物业资料文件名第1册但封面留空；室外场地、物业用房、分户台账册号留空），正式编号在签署前由甲方确认。

## 2. 角色与分工

| 角色 | 在承接查验里做什么 |
|---|---|
| 租户管理员 | 可查看本租户全部小区，可为任一小区创建查验批次 |
| 项目经理（批次负责人） | 为自己管辖的小区创建批次；确定查验对象、成员与分工；处理问题清单里的签署例外（带遗留交接）；组织审核与签署 |
| 查验人员 | 项目内部员工或外聘临时人员，人员不固定；由项目经理按批次统一分派。外聘人员用批次级临时授权，不写入长期编制 |
| 审核人 | 审核查验记录与问题事实；不能审核本人提交的内容 |
| 签署主体 | 查验人、审核人签章（通用签章页）；移交方、接收方签署（资料清单）；新建/机构更迭的一式叁份执件主体不同，按批次配置，不固定"三方" |

分工分两大类：**资料核查**与**现场查验**。现场查验可按楼栋/单元逐栋划分，也可按类型划分（园林绿化、康乐器材、供水供电设施设备等）。项目经理可手工分派，也可选**随机分派**：系统按成员、分工范围和对象数量自动分配，结果可预览调整。

## 3. 完整流程（以接手新项目为例）

### 3.1 后台一次性准备（管理员，电脑端）

1. **查验内容配置**（品质管理 → 承接查验 → 查验内容配置）：维护"查什么、检查什么项目"——按册/台账维护类别与专项，专项下维护检查项或清单行。例如室外场地册下 8 个专项：园林植物、硬质景观、康乐设施、排水设施、环卫设施、标识标牌、室外照明、灌溉系统；分户台账 6 个类别：入户门、土建工程、室内门窗、厨房卫生间、水电表、强弱电。资料、钥匙、园林等清单按行配置名称、规格、数量与缺项规则。
2. **签署主体配置**：本批次的查验人、审核人、移交方、接收方及授权凭据；确需业委会/社区见证时另行明确身份。
3. **账号与授权**：内部查验人员用现有账号；外聘临时人员建批次级临时授权。

查验内容与日常巡检的检查项**分开维护**（承接查验很多内容平时不查），但复用同一套表单、拍照、AI 能力，不用重复建设。

### 3.2 创建查验批次（项目经理）

项目经理在 App/电脑端"承接查验"新建批次：选小区、选台账类别（机构更迭/分户验收；新建类待母版）、圈定查验对象（资料集合、楼栋/单元/房屋、区域、设备）。批次自动带出对应类别结构。

![承接查验批次列表](../APP原型/预览/v2/19%20承接查验.png)

### 3.3 任务分工（项目经理）

在批次详情里分派成员：资料核查给谁、现场查验按楼栋或按类型分给谁；可选随机分派后预览调整。普通查验人员只看到自己的查验范围，不看全量分工。

![批次详情与任务分工](../APP原型/预览/v2/53%20承接批次详情.png)

### 3.4 现场执行（查验人员，App）

**不需要点位打卡**——承接查验是集中性动作，不套巡检的打卡/围栏/频次规则。

**资料核查**：逐行核对名称、规格、数量，标记已移交/缺项/待补；扫描资料时 AI 先提取名称/编号/日期/页数/签章/数量生成待确认内容，人工核对后才算移交。缺页、无签章、编号日期不一致自动进入人工审核。

![资料清单查验](../APP原型/预览/v2/29%20承接查验清单.png)
![资料扫描预登记](../APP原型/预览/v2/56%20承接资料扫描预登记.png)

**现场查验**：**逐项看，但只登记有问题的**。查验人一项项看过，正常项不拍照、不留逐条记录；发现问题的项才：拍照 → **人工选择问题类别**（AI 做不到专项识别，类别必须人选）→ AI 辅助标出问题点 → 人工确认事实。查完按楼栋/册显式确认"已逐项查验完毕"。

![现场矩阵查验](../APP原型/预览/v2/54%20承接矩阵查验.png)

### 3.5 问题清单与审核

问题自动汇入批次问题清单，保留来源、位置、类别、照片与说明。AI 的建议必须人工确认才算事实。批次查完后统一送审；驳回由原查验人修订重提，保留修订记录。

**问题只进报告**：不选责任方、不填整改期限、不进工单池、不做整改跟踪。后续是否维修由甲方线下或报事流程自行安排。

![问题清单](../APP原型/预览/v2/55%20承接问题清单.png)

### 3.6 报告生成、签署与交接

全部审核通过后，系统冻结事实并生成待签报告（六册/分户台账按母版版式：已覆盖的无问题项默认为 √，问题项为 × 并附问题照片表）。签署主体逐一签署后归档，签后全部只读。

**带遗留交接**：问题不必全部处理完才交接，但每项须事实证据完整、风险与安全措施明确、接收方明确接受并附在签署文件中；重大安全风险无获批措施时阻断交接。由项目经理在问题清单的"特殊处理"集中完成。

签后发现错误：负责人申请更正、非原申请人批准、旧件不改、新文件关联旧件、重新审核并全体重签。

![报告预览与签署阻断](../APP原型/预览/v2/40%20承接查验签署.png)
![带遗留交接](../APP原型/预览/v2/57%20承接带遗留签署.png)

## 4. 甲方已确认的关键口径（汇总）

- 台账分三类；机构更迭六册与分户台账母版已提供，新建类母版待补充。
- 承接查验不打卡；查验人员不固定，可外聘，项目经理统一分派，可随机分派。
- 现场逐项看，**只记录有问题的**；问题拍照后**人工选择类别**，AI 不做专项识别。
- 不选责任方、不填整改期限；问题只进报告，不进工单、不做整改跟踪。
- 签字主体按批次配置，不固定三方；一式叁份执件主体按新建/机构更迭区分。
- 签后只读；纠错走申请-审批-重签，旧件不覆盖。

## 5. 仍需甲方确认

1. **新建物业承接查验母版**：提供后按实际册号与表型配置。
2. **六册与分户台账的正式册号**：目前多份封面册号留空。
3. **签署主体构成**：各批次实际由哪些单位/代表签署，是否有见证方。
4. **分户台账覆盖范围**：是否所有批次都必须出分户台账，还是仅涉及户内核验的批次。
