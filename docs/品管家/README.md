# AI云管家改造方案评审入口

> 状态：补齐评审稿。**不是已上线说明，也不是已经通过全部技术验证的施工结论。**
> 本轮仅整理设计、原型和甲方使用说明；不执行业务代码改造、生产数据清理、提交或推送。
> 目标：甲方确认业务和交付效果后，按领域一次性破坏性改造；不维护旧接口、旧表结构、双写和旧 PDF 引擎的兼容路径。

## 1. 已明确的边界

- 模块化单体，领域有自己的写模型和公开契约，不提前拆微服务；未来设备接入、AI 提供者和 SaaS 有扩展接口，但不虚构已实现能力。
- **检查项模板**只管检查要求、合格标准、输入与证据要求；巡检和承接的设备检查可共享定义，业务记录、审批和查验清单仍各归本领域。
- **输出模板**是独立系统设置：甲方 DOCX 母版提取版式 + DSL 数据绑定，Go 填充 OOXML，再经受控转换生成 PDF。不把输出表头、行模式塞进检查项模板。
- 台账字段方案、XLSX 导入映射、PDF 版式不是一个大杂烩配置。可以复用验证和映射能力，业务字段及数据来源仍明确分开。
- 已提交记录保留检查要求与结果的事实快照；不为“新时间重出旧报告”增加历史模板版本体系。重出使用当前输出配置生成**新报告**，原归档文件不覆盖。
- 巡检五册按供水、供电、消防器材、消防系统、特种设备分类输出；内部复用渲染器，不等于把甲方报告合并成一张大表。最终分类和表映射须甲方确认。
- 五 Tab：AI助手 / 主页 / 卷宗库 / 社区 / 我的。主页常用与概览，全部功能并入主页分区卡（每组「更多 ›」进该板块全部内容）；通知不占 Tab，主页滚动通知条进通知列表；扫码左上；我的纯个人列表。PC 沿用现有后台结构，不另造一套菜单壳。
- 巡检异常审核通过后入池；维保确认通过后写正式流水和日期。提交、审核完成、报告归档是三个不同事实。

## 3. 仍需甲方确认的事项

这些是业务决策，不应由开发人员用代码默认值偷偷决定。**登记表统一在 [10 验收与需求追踪 §2](10-验收与需求追踪.md)**，含决策事项、确认前的保守默认口径与受阻的期次/文档；本文与 08 §10 不再各维护一份清单——两份清单必然漂移。

哪些卡住期1、哪些仅在期2 出表前需要结论，以该表"受阻范围"列为准。同类型多套检查项模板的计划级选择已纳入本期，不再推迟为兼容例外；异常入池时机已统一为审核通过，不再把"未入池阻止巡检员下一次提交"列为待定交互。

## 4. 技术门禁（当前均不能视为通过）

1. 用甲方真实 DOCX 覆盖清单/矩阵/循环列、跨页表头、长文字、照片、空册、签章样例，验证 Go OOXML 生成和固定转换环境；对照人工批准的 PDF 基线。
2. 为检查项实例、事项来源、批量幂等、事件消费、报告文件建立唯一约束和事务测试；崩溃/超时/重复消息/并发抢单验证。
3. 租户和项目越权负测，文件下载鉴权，上传与 OOXML 安全，后台任务显式租户范围；现有安全薄弱点不能仅靠前端隐藏解决。
4. 按约定数据规模压测列表、筛选全选、提交、照片和报告队列。设计预算不是压测结果。
5. 备份恢复演练、停写窗口、强制升级和新旧环境切换演练。破坏性改造不等于无备份直接删库。

这些在业务实施期完成。本轮原型截图、说明书导出和 ZIP 校验只证明评审材料可用，不证明上述门禁已通过。

## 5. 文档治理与交付

- `docs/归档/` 是历史材料，不作为新实现依据；原始需求和甲方母版保留，不继续随意删文档或测试素材。
- `docs/需求规格说明书.md` 中未被明确替代的安全、离线、本人历史、通知、导入导出、备份需求继续跟踪，见 10；旧三 Tab、旧向导和旧 PDF 引擎已由本目录替代。
- `docs/接口文档.md`、`docs/数据库设计文档.md` 尚是现状资料，实施时必须同步真实接口与迁移；本轮不把建议字段冒充已建表。
- 评审包应包含 01~10、本文、说明书 DOCX/PDF、原型 PNG/索引及开发约束。包内不放账号、令牌、运行日志或客户原始数据。
- 甲方确认业务只是实施前置条件；完成代码后仍需按 10 验收，不把静态原型确认等同上线批准。
