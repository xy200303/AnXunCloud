# AI云管家 App 静态 UI 原型评审索引

> 本目录是 **App（移动端）静态评审图，不是已实现功能或业务验收证明**。数据、身份、照片占位与状态均为演示；按钮主要用于表达规则，少量页面链接便于对照。业务规则以方案 02/03/04/05/07/08 为准。
> **PC 后台原型在 [`../后台原型/`](../后台原型/README.md)**，本目录不再收录 PC 页面。

## 统一口径

- App 五 Tab 固定为：AI助手 / 主页 / 卷宗库 / 社区 / 我的。扫一扫在左上角，没有右上角“＋”通用入口。通知不占 Tab，主页滚动通知条进通知列表页；社区 Tab 是生态接入枢纽与服务集市：物料资源（物资遴选+外包服务商比价履约）、智慧产品（自研/三方 SaaS/硬件即开即用）、便民集市（物业审核后推送）、邻里交互（审核后展示）；默认混合推荐流，点板块图标切专属内容，规划中随业主端开放。AI助手 Tab 是微信式对话页（无输入时左侧语音/文字切换、右侧加号；输入文字后左侧隐藏、右侧加号 + 发送按钮；语音状态"按住 说话"长按录音松开发送）：可命令 AI 完成工作，系统增删查改封装为工具供 agent 调用（沿用接口鉴权），回答按 response 流 Markdown 流式渲染，思考过程与工具轨迹可展开。卷宗库是所有台账报告的统一归档（最近查看 + 八大分类），归档件只读。
- 主页（布局参考甲方原平台，样式用本系统，**白底卡片式驾驶舱**）：顶部项目行（定位图标 + 戎安华府 + 等 3 个项目 + 下拉）→ 浅蓝滚动通知条（喇叭 + 公告 + 更多，进通知列表）→ **2×2 指标卡**（报事报修 86 件/完结率 95%、物业收费 120 万/维保率 100%，配迷你走势线与语义色数值；卡底注明"详情分：项目概况、客户服务、财务经营、品质保障"）→ **最近使用**（我的任务/欠费查询/巡检督查/抢单池/任务调度/岗勤管理/巡检台账/编辑站，圆形浅底图标 + 红色角标）→ **智管/智控/智创**分组卡（圆形语义色图标、角标、更多 ›；组内放已有常用功能并对齐甲方名称：巡检督查含我的任务/巡查打卡/打卡审核/巡检记录，岗勤管理含用户管理/岗位设置/人员分配；规划中未建设的功能收进「更多 ›」页）。统一为白卡片 + 轻投影，标题 22px 加粗，不设渐变头与中央悬浮按钮。原工作台功能目录并入主页分区卡，不再占 Tab；管理能力不塞进"我的"。
- **宫格图标按业务分区上色**：巡查维保=蓝、工单整改=橙、品质管理=绿、管理中心=紫；同一功能在主页和更多页用同一个颜色。**颜色不承担"是否可用／是否危险"的含义**（否则灰底被误读成禁用、红底被误读成危险），红色只留给状态角标。同一屏内图标互不重复。
- **任务入口只有两类**：「我的任务」（派给我的巡检/整改/维保执行）与「工单池」（抢单/派单/管理）。不再出现今日任务、我的工单、维保登记等多个执行入口。
- **决策性选项一律不预设默认值**：维保方式、本次涉及设备、工单池散件均为空选。这几处都有不可逆的外部后果（算错到期日、未核对就成单），"最可能的选项"不等于"默认选项"。到期设备只做筛选，不等于授权作业（07 §3）；承接查验不在查验卡片上选择责任方。
- **结论选择用分段控件**（两个等宽 44px 按钮，正常=绿／异常=红），不用小圆点单选：这是老年巡检员每天点几百次的最关键操作，视觉权重要与重要性匹配。AI 未出结果时该项置灰禁用，不做成"看着能点、点了没反应"。
- **检查项卡片用严格分层**：名称 + “拍什么/怎么判”提示 → 图像组 → 结论分段 → 仅异常时展开观察点/备注；参照 `07-表单式巡检页.png`。不把已完成项折叠成只剩状态的摘要行，也不退回左右缩略行。
- **消火栓与灭火器点位分开**：按实际安装位置分别建点、分别打卡拍照，不合并成复合点位一次打卡（两者不一定在一起，前期建点麻烦也照分）；灭火器压力/日期等专项抽查按设备逐台拍照，本就独立。
- **阻塞原因不写进按钮文案**：按钮只说动作（"提交本点位"），"还差什么"与"在等什么"分行列在按钮上方——要等和要做是两件事。维保按钮写"提交，待主管确认"，不写"提交维保"。
- **工单池不是基层日常入口**：工单池是抢单入口，只显示当前人有资格抢的单；主管派单/改派/批量派单在派单管理。可处理/整改中/待复查是筛选状态；工单类型含巡检整改、承接转单、维保执行；维保生效确认单不进工单池。列表页不暴露 issue/order 两层模型。
- **基层执行只有「我的任务」一个入口**：巡检任务、派给我的整改工单、派给我的维保执行工单在同一列表；不包含我自己去抢的单。「我的任务、巡查打卡、附近点位、手动补巡」放在全部功能的“任务执行”跨域分区；记录、计划、审核、确认才回到品质管理/管理中心。
- **维保触发与聚合**：计划/到期维保按 `next_due_date - assign_lead_days` 生成 `work_type=maintenance` 工单，已逾期由每日扫描即生成；聚合粒度与批量登记一致（同小区/同设备类型/同动作/同到期周期或施工批次一张工单，逐台为 item）。纯维保工单执行提交后直接进维保生效确认，不再安排一次工单复查；确认认可维保有效即回写日期。
- **报告卡只显示下一步动作**：生成中看进度/重试失败册，待审核去审核，待我签去签字，已归档查看/下载；完整状态机收进详情时间线。生成报告明细范围三档：全部明细 / 仅异常明细 / 正常代表样本+全部异常；汇总口径始终用全量已审核事实，代表样本必须在封面和页眉标明。
- 承接查验普通路径只到提交审核：不选择责任方；带遗留交接、签署例外是负责人“特殊处理”入口，不在普通查验卡片长期占位。
- 照片区恒定三列等分，拍第三张不出现 2+1 残缺网格；未拍第一张时不并排显示空的"＋"槽。
- 移动端沿用 uni-ui 交互习惯、品牌蓝与大字号；PC 沿用 Element Plus 后台侧栏、面包屑与标签壳。结构图标用 SVG；状态配文字，主要触达不小于 44px。字号只用 13／14／16／18 四档，间距按 4/8px 节奏。
- PC 抽屉遮罩很淡：抽屉式编辑的价值就在保留上下文，重遮罩会把价值抵消。判定参数只有一处来源——上下限落列、标准原文由其自动生成且仅用于展示，不并排放两个可编辑的判定输入。
- AI 逐项并行；pending/running 阻止提交。失败先重试/重拍，仍失败须人工结论与原因并强制审核，不能默认为合格；重拍只认最新请求，迟到结果不覆盖。异常仅审核通过后入池。"无法检查"面板必须先说清影响哪几项、可切换整点位或单项，不可选的原因置灰。
- 维保从设备列表选单台/多台登记；“我的登记”追踪待确认、已驳回、已确认。确认通过才回写台账，驳回改完重提仍待确认。
- 五册月报（含空册）全部生成后冻结预览文件集，再审核，全链通过后签章归档；失败单册可重试，不混同“PDF 服务未启用”环境降级。冻结件及归档件不覆盖，重出新报告。
- 检查项模板与输出模板完全分开。直接新建空白检查项模板，复制仅可选；点位类型不是设备类型。L1 配检查项与标准，L2 配资产字段，L3 配输出版式/分组；查验资料清单独立于设备 L2。
- 承接六类别不是连续第1~6册：物业资料仅文件名第1册（封面留空）；房屋本体第2册；设施设备第4册；室外场地、物业用房册号未定；地下车库第6册。六册之外另有物业分户查验台账（一户一档，按区/栋装订，册号留空）。正式编号签署前须确认。
- 承接不选责任方、不填整改期限：交接前问题默认属移交方需处理事项；签署主体按原件及批次配置，不固定“三方”。遗留须事实/措施/接收方接受齐全；重大风险无获批措施阻断。
- 遗留不必全部处理完才交接，但事实/争议说明、风险措施、接收方接受文件须齐；重大风险无获批措施阻断。问题不进工单池，本模块不做整改跟踪。
- 签后记录/责任/文件只读；遗留接受文件随报告归档，不改原事实。纠错走负责人申请、非原申请人批准、新文件关联旧件、重新审核和全体重签。

## 源文件与重渲染

- 唯一可编辑正文：`fragments/*.html`；标题、导航：`fragments/meta.json`。
- 渲染器：`backend/.tmp/render_protos.py` **按目录分流**：本目录出手机页（390×844，长图加首屏折线），`../后台原型/` 出 PC 后台页（1280×800）。共用样式读取 `backend/.tmp/proto_css.css`，补充规则在渲染器中。`src/*.html` 与同名 `*.png` 是派生产物，不直接改。
- 在项目根目录运行 `python backend/.tmp/render_protos.py`，**一次渲染两个目录**。需现有 Python Playwright 与本机 Chrome（脚本内配置路径）；不自动安装依赖。脚本使用真实 Chrome，逐页校验元数据、HTML 链接、PNG大小与尺寸，异常立即失败。
- 移动端 CSS 宽390，最低高844，正文过长自动长图，2倍输出宽780；PC 宽1280、最低高800，2倍输出宽2560。长图用于评审完整内容，**图上那条橙色虚线是真机首屏边界（844px），线以下在手机上需要滚动** —— 加这条线是因为长图会让人误以为"一屏能看完"，首页信息架构这类问题在无标注长图上看不出来。
- 本轮仅静态图与规则对齐；不证明 API、AI、幂等、权限、PDF转换或签字归档已经实现，也不代替 Word/PDF黄金样本回归。
