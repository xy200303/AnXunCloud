## 设计系统（.tmp/ds/ds2.js，Penpot 原生）

**不写绝对坐标**，全部用 Penpot 自动布局（flex）搭建：容器定 padding / gap / alignItems，
子元素用 `horizontalSizing: fill|fix|auto` 决定撑满还是自适应，改文案改字号不会错位。

## 排版权式（重画前必读）

- 内容区含左右 16 内边距（可用宽 358）；卡片内边距 14，**卡内文字宽固定 330**，右侧状态/时间/单号/数值一律贴 330 右边线。
- 并排按钮固定宽（84 / 96 / 108）+ 固定 gap（12），不按剩余宽度拉伸；可点区 ≥48，筛选用 44 高的胶囊行。
- 图标统一进 22×24 固定槽（`iconSlot`），短文本不设固定宽。
- 卡片骨架固定四层：标题层 → 媒体/关键字段层 → 主操作层 → 条件详情层（只在对应状态展开）。
- UI 不写配置说明与规则标注（不写"GPS 已关""已开启复查"），规则只在后台。
- **登录页（23）只有账号密码 + 微信一键登录**：账号 = 工号或手机号，密码右侧眼睛图标切显示/隐藏，主按钮「登录」，下方「忘记密码」只提示联系管理员重置（不做自助找回）；账号密码与微信一键登录之间用一行浅灰「或」+ 两侧细线分隔，微信按钮微信绿 `#07C160`、h48、图标+文字居中（App 端微信开放平台 AppID 待申请，原型只表达入口）。**不设短信验证码、不在登录页选项目、不设切换身份、不展示租户 pill**（租户是后台概念）——项目切换在主页顶栏下拉（登录后切换，不重新登录）。页头只保留 logo + 应用名 + 企业名。
- **定宽多行正文用 `para()`**（按估算行数显式给高度）：Penpot 不会重排折行文字的高度，直接用 `txt(..., {w})` 会把下一行压掉。

## 统一列表交互规范（所有列表页照此，不再逐页另设计）

甲方反馈 App 列表类交互不合格（卡片堆按钮、批量与单条割裂、没有多选）。以下 6 条是**硬约束**，新建列表页或改既有列表页一律照抄这套骨架，不按页另定。

1. **列表 = 多选卡片列表**：每张卡左侧有选择框（触屏上等于长按进入多选），**卡片主体（除选择框与卡内快捷动作外）整块可点进详情**。不做"卡里只有一排按钮、点不进去"的结构。
2. **卡片只放决策所需信息 + 状态标签**：对象名/点位 + 一句事实（谁、何时、多少项）+ 状态 pill + 异常/待办要点。不塞次要字段、不塞导航、不把按钮当内容。
3. **底部固定操作条**：`已选 N 条` + 一个主按钮（批量通过 / 批量驳回 / 批量派单）+ 一个次按钮，按钮**定宽 + 固定 gap、高度 ≥48**；**未选中时主按钮置灰或整条隐藏**，不做"没选也能点"。
4. **选择能力三件套**：全选 + 单条勾选 + **AI 低风险项默认勾选但不自动提交**。全选 = 当前筛选结果全选（列表是滚动加载、不分页，不另开"本页全选"这个第二概念）；部分选中时全选框显示半选态。AI 代勾只在**全选行右侧**给一行提示（`AI 低风险 3 条已勾选`），不占底部操作条——选择可以默认，提交必须人点。
5. **批量与单条并存**：卡内保留轻量快捷动作（如「通过」），与底部批量动作同时存在。既不能只有批量（单条要能就地决策），也不能只有单条（列表必须能批量）。卡内只留"这一张最常用的那一个"动作，其余进详情。
6. **卡片可点 = 有明确详情入口**：整卡可点即可，右侧箭头可省（右侧边线要留给时间/数量/状态 pill）；**不写"点击查看"这种废话**，也不在卡里再加"详情"按钮。

列表页统一骨架：

```
导航栏 → 筛选 tabs + 右侧筛选 → 统计行（5 条待审 · 含异常 3 条） → 全选行 → 多选卡片… → 底部固定操作条
```

- 选择框在卡片**左侧独立一列**（22×22，与标题首行同高、22×24 图标槽对齐），卡内正文右移后仍贴卡片右边线；右侧的时间/数量/状态 pill 在**所有卡片同一条右边线**。
- 卡内异常要点一行一个：`⚠ 要点（带数值）` 左对齐 + 观察点标签贴右边线；AI 结论单独一行（✧ 图标 + 一句），不并入要点。
- 统计行、全选行各只出现一次，底部操作条不重复统计与 AI 提示。

已按本规范重做的列表页：`18 打卡审核`（多选 + 底部 `已选 N 条` / 批量通过 + 批量驳回，整卡可点进 `26 审核详情`）。

## 生成脚本与分批重建

画板由 `.tmp/ds/*.js` 生成：`python .tmp/ds/run.py .tmp/ds/<脚本>.js`（`run.py` 会把 `ds2.js` 注入代码前面）。

按画板分组分文件，**每个文件控制在插件 120 秒内**（一次 2~3 屏为宜）：

| 脚本 | 画板 |
|---|---|
| `s02.js` | 02 我的任务（基层唯一执行入口，四类任务） |
| `s03.js` | 03 巡检打卡 |
| `s0405.js` | 04 工单池（文件名沿用，05 已并入 02，本文件只建 04） |
| `s0607.js` / `s0809.js` | 06 通知 · 07 我的 / 08 卷宗库 · 09 AI助手 |
| `s101112.js` | 10 工单整改 · 11 待我复查 · 12 维保执行 |
| `s131415.js` | 13 工单详情 · 14 设备台账 · 15 岗勤管理 |
| `s1617.js` | 16 承接查验 · 17 报告签字 |
| `s18_23.js` | 01 主页 · 18~23 |
| `s2425.js` | 24 承接查验清单 · 25 报告详情 |
| `s2627.js` | 26 审核详情（27 预留） |
| `cleanup_legacy.js` | 一次性旧画板清理（`05 我的工单` / `23 登录与切换身份` / `Page 1` 旧主页），不进构建流程 |
| `del_boards.js` | 按名字只删指定画板，配合 `built()` 做单屏重建 |
| `check_svg.py` | 导出画板 SVG 并统计 `<text>` / `text-container`，判断字形是否丢 |
| `render_raw.py` | 把导出的 SVG 本地渲染成 PNG（不依赖 Penpot 做目视检查） |

- **Penpot 插件单次任务上限 120 秒**，超时后浏览器会节流标签页，文字会丢掉字形（导出 SVG 里没有 `<text>`）。屏数多的文件要拆开跑：`s1314151617.js`（5 屏）已拆成 `s131415.js` + `s1617.js`，`s101112.js` 原带的 02 已拆成 `s02.js`。
- **构建脚本末尾不要切换页面**：建完画板立刻 `openPage` 切到别的页再切回，会让新画板的自动高度塌成 0（导出报 `height="0.01"`）或文字丢掉字形。旧画板清理已从 `s18_23.js` 拆到 `cleanup_legacy.js`，单屏重建用 `del_boards.js` + `s18_23.js`，**一次只重建 1 屏**。
- `s18_23.js` 另有 `built()` + `setPluginData('build', BUILD)` 标记：**已建好的画板会跳过**，分批重跑不会重复施工。改内容后把 `BUILD` 版本号 +1（整体重建）或先用 `del_boards.js` 删掉要重建的画板再跑（只补缺的那几屏）。
- 其余文件每次跑都会按画板名先删后建，重跑即重建，不需要 BUILD。
- 判断画板是否真的重建成功：`python .tmp/ds/check_svg.py "<画板名>" <tag>`，`text` 数与 `container` 数相等才算字形没丢（为 0 说明丢了，删掉重跑）；要目视检查就接着 `python .tmp/ds/render_raw.py <tag>`，图在 `.tmp/penpot_import/png/view_<tag>.png`。
- 标签页被浏览器挂起（MCP 报 `suspended by the browser`）时，隔 20~30 秒重试即可，醒来后一次只跑一个文件。若报 `frozen by the browser` 且长时间不恢复，先确认 Penpot 是否掉登录态（标签页可能停在登录弹层）。
