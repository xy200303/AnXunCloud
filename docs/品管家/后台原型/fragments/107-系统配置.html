本期改动（13 §4.2.1）：tenant_config 并入 sys_config 更名 config，用 scope(platform/tenant/project) + scope_id 两列 NOT NULL 跨层，唯一键 (scope, scope_id, key)。键值型与结构型从此同一形态。
「可被下级覆盖」「密钥」两列是本期从代码搬到数据的——原先硬编码在 TenantService 的白名单与"密钥类 ai.* 永不下放租户"规则，后台看不见、改要发版；现在是 allow_tenant_override / is_secret 两列。
这两列连同 name/config_group/remark 是键级属性，用 CHECK 锁在 platform 行（写在租户行上自相矛盾：「租户自己说租户不许覆盖」谁赢？），租户侧只读并显示「不可覆盖」。
回落逻辑收口为一处：现有三处各写一遍（ConfigService.Resolve、TenantService.GetConfig、品牌页占位）。写路径已是"行存在=有覆盖"（存空值即删行），Resolve 里的 value != "" 是冗余防御、不是 bug；收口时两端须同改，否则"清除覆盖"会静默变成"覆盖为空"。
AI 分组整组移出：14 个 ai.* 键里，供应商/模型/绑定进 ai_provider/ai_model/ai_task_binding 三张结构化表，业务规则进「巡检规则」，此处只留 ai.enabled 与全局并发上限这类单值。
