# 审批链与数据权限一致性根治方案（2026-09-16）

> 触发问题：「我可以看到记录但是没有权限审核」「配置了巡检员全部签字却直接跳过」「审批链总是缺少这个缺少那个」。
> 本文档先给根因，再给根治方案与实测矩阵。目标：**可见即可审、可审即可见、空名单不卡死、配置时可见谁审**。

## 一、根因分析（代码层确诊，非猜测）

### 根因 1：可见性与可操作性是两条独立演化的判定轴，无一致性保证

- **可见性（DataScope）**：`middleware/datascope.go ApplyCommunityFilter`。超管→租户内全部；非超管→租户边界 + 角色 data_scope 上限；project 档可见项目 = `ManagedProjectIDs`（编制中挂「项目经理 或 is_supervisor 主管级」岗位的项目）。**每请求实时推导**（auth.go Auth 中间件逐请求 buildIdentity，编制变更即时生效，无快照过期问题——已排除此嫌疑）。
- **可操作性（名单授权）**：`community/service SlotAuthorized`。超管/租户管理员放行；其余须为「当前环节槽位 → 绑定岗位 → 项目编制在职成员」（SlotUserIDs，三级回落：项目→租户→平台默认）。

两条轴互不知道对方存在，于是两类必然错位：

| 场景 | 机理 | 实例 |
|---|---|---|
| 看得到、不能审 | 主管级岗位 → 数据范围含该小区；但当前环节槽位名单不含此人 | 本次实测：消防（fire)任务被维度槽位截胡（见根因 2），用户是安全主管+项目经理 |
| 能审、看不到 | 非主管级岗位被绑进环节名单 → SlotUserIDs 含此人；但 ManagedProjectIDs 不含该项目 → 列表 `1=0`，收到通知却查不到记录 | 任意「组长/专员」类非主管岗位绑进审核环节即触发 |

### 根因 2：汇报线维度槽位静默截胡（本次「人在链里却被拦」的直接原因）

`ResolveReportLineSlot`：patrol_type 非空时，只要维度槽位 `patrol_report_line.<type>` **任一级存在绑定**就路由过去，不看项目里有没有人。平台种子默认绑定：`fire→engineering_supervisor`、`equipment→engineering_supervisor`、`environment→environment_supervisor`、`building→service_supervisor`（seed.go:619-642，开通租户时复制到租户级）。

后果：管理员在「环节分工」配置了**通用汇报线**，但 fire/equipment 类任务实际走了「工程主管」维度槽位——项目里没人挂工程主管 → 名单空 → 除了超管/租户管理员谁都审不了。全程无任何提示。

### 根因 3：空名单语义三条链不一致，且会死锁

- **报告链**：空候选环节自动跳过（App 显示「无候选人，已跳过」）——行为合理但跳得无声无息。
- **打卡/维保链**:`WalkFlow`（flow_service.go:108）落定人工环节时**不检查名单是否为空**，记录停在空名单环节 = 永久死锁（谁都签不了，也不自动推进）。
- 「岗位留空 = 显式跳过」的设计语义，在打卡链上实际效果是死锁而非跳过。
- 在途兜底（Pass 的 overEnd 越界保险丝）只覆盖「流程变短」，不覆盖「名单变空」。

### 根因 4：「巡检员」候选人三个出处

报告链巡检员确认环节只认「当月有任务的巡检员」（monthInspectorIDs），补生成历史月报告/当月任务还没生成时候选为空 → 整个签字环节被跳过（本次「配置了全部签字却跳过」的直接原因）。与编制内的巡检员岗位（patrol_execute 槽位）完全不通。

### 根因 5：列表不表达可行动性

待审核列表只按小区+状态过滤，用户要点进去操作了才被 40304 拦下。（本轮已加 `can_audit`/`current_step_name` 透出 + App 端「待授权人处理」展示，**尚未提交**。）

## 二、根治方案

### P0 判定收口（核心，消灭双轴错位）

1. **统一候选人解析入口**：新增 `communitysvc.StepVoters(db, communityID, patrolType, step) → {UserIDs, Slot, Source, EmptyReason}`。所有「这个环节谁能审」只走这一个入口：Pass/Reject/BatchPass、提交路由通知、AI 闸门下游、抽查、can_audit、PC 配置预览。EmptyReason 三态：`skipped`（显式跳过=岗位留空）/ `unconfigured`（无任何绑定）/ `no_member`（有绑定但项目内无在职成员）。
2. **待审核列表默认「我可审」**：列表接口加 `mine` 参数（默认 1）= 数据可见 ∧ 当前环节我可签；`mine=0` 看本数据范围全部（非可审项按本轮的 can_audit 标注「待授权人处理」）。App/PC 待审核 tab 默认 mine=1。**从此「待审核」=「等我审」，不会再有点了被拦**。
3. **「能审看不到」根治**：审核/待办类查询的可见范围从 ManagedProjectIDs 加宽为 **StaffProjectIDs（任意岗位的在职编制项目）∪ ManagedProjectIDs**——我是某项目环节名单成员的前提是我挂在该项目编制内，用在职编制项目做可见性并集即可全覆盖，且仍受租户边界约束、安全无损。仅审核/待办查询加宽，其他业务列表口径不变。

### P1 空名单语义统一（消灭死锁与静默跳过）

4. **WalkFlow 增强**：落定人工环节前走 StepVoters；名单为空（不论哪种 EmptyReason）→ **自动跳过该环节继续走**，并写操作日志 + 通知项目管理员「环节 X 名单为空已自动跳过，请检查环节分工配置」。与报告链口径一致。显式跳过（岗位留空）从「死锁」修正为真正的「跳过」。
5. **在途单自愈**：Pass/Reject/闸门推进时同样按 4 的规则跳过空名单环节（含当前停在空名单环节的存量记录——推进动作发生在下次有人触单时；另提供一次性脚本把卡在空名单环节的在途单批量推进）。
6. **巡检员候选口径**（本轮已改，含进本方案）：当月任务巡检员 → 空则编制内巡检员岗位成员（patrol_execute 槽位名单）→ 仍空才跳过。预览与生成固化同口径。
7. **批量通过只推进我可审的**：BatchPass 逐条按 StepVoters 判定，不可审的跳过并在响应里报告 `passed/skipped` 数量与原因，不再整批报错或静默。

### P2 配置显性化（防再犯：把隐性问题摆在配置现场）

8. **PC 岗位编制-各审批流程 tab**：每个环节下方直接渲染 StepVoters 解析结果——最终名单（姓名）+ 来源（项目级/租户级/平台默认/编制兜底）+ 空名单红字警示（「该环节当前无人能审，将自动跳过」）。管理员保存前就能看到「到底谁审」。
9. **环节分工 tab**：维度槽位（消防/设备/环境/楼栋线）行内注明命中规则——「有绑定且项目内有成员才生效，否则回落通用汇报线」，并显示当前解析去向。

### P3 实测矩阵（做完必须逐项实测，接口级脚本 + 关键路径真机/浏览器）

| # | 用例 | 预期 |
|---|---|---|
| 1 | 单人多岗（安全主管+项目经理）审 fire 类任务记录 | 可审（维度无成员回落通用）✅本轮修复点 |
| 2 | 项目内有人挂工程主管 → fire 记录 | 走维度槽位，工程主管可审，其他人 mine=1 不可见 |
| 3 | 通用+维度都无人 | 自动跳过+通知管理员，不卡死 |
| 4 | 环节岗位留空（显式跳过） | 自动跳过，不卡死 |
| 5 | 非主管级岗位绑进审核环节 | 待审核列表可见且可审（能审必能见） |
| 6 | 主管级不在环节名单 | mine=1 不显示；全部视图可见但标「待授权人处理」，按钮不拦（前置表达） |
| 7 | 改流程配置后在途单 | 按提交时快照审完（现有语义回归验证） |
| 8 | 编制/岗位变更 | 下一请求即生效，不需重新登录（逐请求 buildIdentity 回归验证） |

## 四、终版调整：三岗位模型 + 维度槽位机制整体拆除（2026-09-16 甲方口径）

甲方组织极简：**物业经理 / 安全主管 / 巡检员**三种岗位。维度槽位（多业务线汇报线）是大组织设计，对甲方是纯伤害（fire→工程主管 的平台默认绑定静默截胡通用汇报线配置）。终版从「删默认绑定」升级为「**拆机制**」：

1. **删除维度槽位路由**：`ResolveReportLineSlot`/`reportLineSlotFor`/`FlowStepSlot` 全删，环节槽位就是配置值本身，不再按巡查类型分叉；`duty_slot.go` 字典衍生逻辑删除；4 个静态维度槽位常量与目录条目删除。
2. **种子收敛三岗位**：post_dict 平台模板只留 project_manager/safety_supervisor/inspector；duty_binding 默认只留 patrol_execute→inspector、patrol_report_line→safety_supervisor、project_review→project_manager 三条。
3. **迁移 00056 清存量**：删所有 `patrol_report_line.%` 维度绑定（平台/租户/项目级——无人显式配过）；删未被 project_staff/duty_binding 引用的非三岗位 post_dict 行。
4. **空名单统一跳过**（P1 落地形态）：新增 `WalkFlowSkipEmpty`（纯函数可测，名单解析以闭包注入）：落定人工环节名单为空 → 自动跳过并记录，调用方通知项目/租户管理员「环节名单为空已自动跳过」；三链（打卡/维保/报告）同口径。维保链 Confirm/Reject 补 SlotAuthorized 名单制（与其他链统一）；BatchPass 改逐条判定、可审推进、不可审跳过并报告数量。
5. **配置显性化**（P2 落地形态）：新增 `GET /communities/:id/flow-preview?flow_code=` 返回每环节最终名单+来源+空态原因；PC 岗位编制弹窗各审批流程 tab 直接渲染「谁审」，空名单红字警示。


## 五、终版补充：一致性在「配置时」保证，不引运行时加宽机制（2026-09-16 甲方拍板）

> 甲方明确：**不为对齐引入一套自己的运行时过滤/绑定机制**（越权风险、管理混乱、职责不清）。
> 因此 P0 第 2 条（mine 参数默认过滤）与第 3 条（可见范围并集加宽）**作废**，替换为：

1. **配置时可见性校验（能审必能看的「看」前置到配置现场）**：新增 `middleware.UserCanSeeCommunity`（与登录态 buildIdentity + CheckCommunity 同口径：超管可见；租户不一致不可见；data_scope=all 可见；project 档看编制推导可见项目；self 档不可见）。`flow-preview` 逐 voter 透出 `can_see` 与环节级 `hidden_count`；PC 审批链编辑器把不可见成员标红「（不可见）」并给出警示行，保存后立即刷新预览。不硬阻断保存——配置自由度保留，问题显性化。
2. **报告链候选人天然可见**：报告详情对 self 档的签字候选人/巡检员按单据实例放行（getWithScope 参与者授权），故报告链 voter 不标红。
3. **在途单当前环节空名单自愈**（P1 第 5 条落地形态）：Pass/BatchPass/维保 Confirm 判定当前人工环节名单为空时，授权回落汇报线（SlotPatrolReportLine），走链从**本环节**起自动跳过（WalkFlowSkipEmpty 语义复用），不再卡死等管理员。
4. **巡检记录列表（CheckinList）透出 `can_audit`**：与 Pass 同口径（快照优先、越界/AI 停放/空名单自愈回落汇报线），PC 巡检记录待审核 tab 按 `can_audit` 隐藏通过/驳回按钮与多选框，显示「待授权人处理」；审核列表（review_list）的 can_audit 判定同步对齐自愈口径。
