# 巡检与台账优化方案（9.14 实测反馈）

> 来源：2026-09-14 戎安华府现场实测后甲方反馈。本文档为优化方案的完整定稿，作为后续开发依据。
> 关联文档：《红色物业AI智能巡检增强方案》《设备台账与维保周期管理设计方案》《专项巡检与专项检查报告设计方案》《汇报线与审批链扩展设计方案》。

---

## 一、实测反馈汇总

### 1.1 现场巡检操作（App 端）

甲方现场演示目标流程（灭火器巡检原话）：

1. 拿手机靠近（NFC 卡），弹出该灭火器信息；
2. 打开灭火器箱，对准灭火器正面拍照；
3. 系统自动识别照片内灭火器的数量、压力情况；日期、压力无法识别也不要紧，默认判定为正常即可；
4. 巡检时抽检 2%：对准压力及日期近距离拍照；
5. 全部检查完成后，系统自动汇总全部数据，生成灭火器巡检报告。

配套意见：

- 现场操作一定要简单，员工只需拍 1~2 张照片，多了就复杂；
- 打开箱体拍一张整体照片即可识别枪头、水带、手报等，不需要对每个检查项单独拍照；
- 每个设备拍一张照片即可，除非特殊异常（破损、整体缺失等）加拍一张并说明问题，每点位最多 3 张；
- 检查项条目需要修改（现状逐项必拍不合理）；
- 不是每个消火栓箱都配灭火器，点位应支持多选模板组合；
- 贴近卡片后操作界面显示不明了；
- 贴 NFC 卡后落下的仍是"点位签到页"，还要再点一次，很不好——**贴卡就应直接进入检查**；只有从任务列表手动进入的点位，才需要自己点「NFC 签到」完成到场校验；
- 拍照识别很慢；
- 实测操作下来费时间、啰嗦、不方便（逐项拍照、逐项点「AI 读标签」、逐项等结果）；
- 日期识别也很慢（灭火器生产日期/维保日期逐具点读标签、同步等待）；
- 抽检策略：灭火器压力、日期抽检 2%；防火门、应急灯、安全出口指示牌、手报（手动报警按钮）、喷淋头、烟感等**每月抽查**；
- 设置的流程需要调整。

### 1.2 台账与报告（PC 端）

- 消防设备（器材类）台账分三类管理：灭火器（箱）、消火栓（箱）、指示牌等；
- 灭火器、消火栓要精准细致，指示牌等不用太细致；
- 台账先单独做、最后整合，导出时筛选特化——整个台账项目很多，但按单项筛选后显示出来的少；
- 每种设备需要记录的内容不一样（如灭火器要记录维修、换粉）；现有台账模板太复杂，历史台账本身也不标准；
- 甲方提供模板：
  - `docs/模板/消防设备灭火器换粉台账.xlsx`：设备档案（项目名称/所属设备系统/设备分类/点位信息/换粉日期）；
  - `docs/模板/物业消防设施（器材类）月度巡检报告.pdf`：官方月度报告版式（8 页）。

## 二、总体设计

两条主线：

- **点位多模板组合 + 整组拍照 AI 一次识别** —— 解决现场操作繁琐、识别慢；
- **类型化台账（一套数据，多套视图）** —— 解决台账字段差异化、导出特化。

员工常态操作收敛为一句话：**贴卡 → 拍 1 张 → 确认 → 下一个点位**，单点位不超过 10 秒。

## 三、点位多模板组合

### 3.1 现状

一个点位只能挂 1 个检查项模板（`inspection_point.template_id` 单值），无法表达"消火栓箱 + 灭火器"这类组合点位。

### 3.2 设计

点位 ↔ 模板改为**多对多**（新增 `point_template` 关联表）。管理员配点位时勾选若干**原子模板**自由组合。原 `template_id` 字段在迁移中把存量数据搬入关联表后**直接删除**，不留双写、不留旧代码路径（开发期不做向后兼容，避免遗留垃圾）。

| 原子模板 | 检查项（对齐官方报告明细表列） | 精细度 |
|---|---|---|
| 消火栓箱 | 箱门、水带、枪头、接口、水压、周围遮挡 | 精准 |
| 灭火器 | 压力、瓶体、喷管、铅封、有效期 | 精准 |
| 应急疏散类 | 应急照明、疏散指示、安全出口标示、防火门、卷帘门、消防通道 | 粗放 |
| 报警喷淋类 | 手报按钮、烟感、喷淋头（外观完好、无遮挡/破损/缺失） | 粗放 |

模板同时携带**巡检频次属性**：日常巡检（消火栓箱/灭火器，走常规打卡计划）或**每月抽查**（应急疏散类、报警喷淋类，见 §4.5），频次在模板/点位组合上可配。

组合示例：

| 点位类型 | 模板组合 |
|---|---|
| 纯消火栓箱 | [消火栓箱] |
| 带灭火器的消火栓箱 | [消火栓箱] + [灭火器] |
| 纯灭火器点位（2 具共箱） | [灭火器] |
| 通道 + 灭火器 | [应急疏散类] + [灭火器] |

打卡时把组合模板的检查项**合并成一张清单**；检查项快照机制（打卡时复制模板项内容）使历史记录与模板调整天然隔离，不受影响。

### 3.3 PC 配置改动

- 点位表单：模板单选 → **多选**；
- 模板维护页：加「拍照模式：整组 1 张」标识。

## 四、整组拍照与 AI 识别

### 4.1 拍照策略

**不管组合了几个模板，一个点位默认只拍 1 张整体照**（打开箱门拍箱内全貌）。

第 2 张照片只在两种情况出现：

1. **抽检命中**（见 §4.4）：补拍压力表/日期标签特写；
2. **发现异常**（箱门破损、设施缺失等）：加拍 1 张异常特写 + 文字说明，并选择 上报待处理 / 现场已处理（沿用现有处置闭环）。

每点位上限 3 张（1 整体 + 最多 2 异常/抽检特写）。

### 4.2 AI 一次识别多项

一拍多项：1 张整体照 + 该点位组合出的全部检查项 → **一次 AI 调用**返回逐项结构化判定：

```json
{
  "count": 2,
  "items": [
    { "item": "箱门", "result": "normal" },
    { "item": "水带", "result": "normal" },
    { "item": "枪头", "result": "abnormal", "reason": "未见枪头" },
    { "item": "压力", "result": "unrecognized" },
    { "item": "有效期", "result": "normal", "value": "2027-03" }
  ]
}
```

- **数量比对**：`count` 与点位绑定设备数比对，少了判「缺失」异常；
- **宽松判定**：压力/日期读不出 → **默认正常**，不拦员工、不要求重拍；数据侧记 `unrecognized` 标记（不计异常、不进审批），月报统计「AI 未识别率」供管理者评估照片质量；
- 点位未挂灭火器模板时提示词不含灭火器项，AI 不硬找；
- 存疑（`review`）项交审批链 AI 闸门复核（现有机制），不卡现场；
- **逐项「AI 读标签」按钮取消**：生产日期/维保日期识别合并进这一次整组调用，员工不再逐具点读、逐项等待——这是消除"操作啰嗦、识别日期慢"的关键改动。

### 4.3 识别提速

| 措施 | 说明 |
|---|---|
| 合并调用 | 一点位一次请求（最大提速头），替代逐项/逐张串行；日期识别随之并入，不再有单独的"读标签"等待 |
| 全异步 | 拍照即创建识别 job 并放行，员工继续下一点位；结果轮询/推送回填；提交不阻塞，未返回项标「识别中」由 AI 闸门兜底 |
| 图片压缩 | 拍照后本地压至长边 1280 再上传 |
| 模型分级 | 初判用快速档模型，仅存疑样本走强模型复核；日期类小图裁剪识别走快速档 |

### 4.4 抽检 2%（任务级抽样：灭火器压力/日期）

- 打卡任务生成时按类型**随机抽样**（比例可配，0=关闭；甲方口径 2%）；
- 命中点位打卡页提示：「本次为抽检点位，请对压力表和日期标签补拍 1 张近照」；
- 抽检特写走高置信识别：压力/日期必须给出结论，读不出进存疑，由审批链 AI 闸门复核；
- 目的：防"拍了就算"的形式化巡检，同时不给 98% 的点位增加负担。

### 4.5 每月抽查（可配置的抽查计划：防火门/应急灯/指示牌/手报/喷淋头/烟感等）

与 §4.4 的任务级抽样是**两套并行机制**：2% 抽检管"每次巡检中的精读比例"，抽查计划管"低频设施按月覆盖"。

抽查做成与**巡检计划同级的可配置计划对象**（复用现有计划模型，新增「抽查」计划类型），PC 端按小区维护，可配置项：

| 配置项 | 说明 | 缺省 |
|---|---|---|
| 抽查比例 / 固定数量 | 二选一：按点位池百分比（如 20%）或固定 N 个 | 20% |
| 点位范围 | 按模板类型（应急疏散类/报警喷淋类）/楼栋/自定义点位组圈定抽查池 | 该小区全部粗放类点位 |
| 生成日 | 每月几号自动生成当月抽查任务 | 1 日 |
| 完成期限 | 当月任务截止日 | 月末 |
| 执行人 | 按岗位/指定人员，沿用计划的派单逻辑 | 同日常巡检 |
| 抽取策略 | 纯随机 / 优先最久未查（推荐，保证滚动全覆盖） | 优先最久未查 |
| 连中保护 | 同一点位相邻两月不重复抽中 | 开 |

- 抽查打卡与日常巡检**同一条链路**（贴卡 → 整组拍照 → AI 识别 → 提交审批），员工无感差异；
- 抽查结果汇入月报「本月检查汇总表」与分项明细 4.3（应急灯等粗放表）；
- PC 台账可查每点位「最近抽查日期」，超期未查自动进入下月优先池（「优先最久未查」策略的数据基础）；
- 计划停用即不再生成抽查任务，历史抽查记录保留可查。

### 4.6 照片归类

整体照自动挂到它覆盖的所有检查项（一份存储、多处引用）；异常特写挂对应异常项；抽检特写挂压力/有效期项。报告按 点位 → 检查项 归档取图。

## 五、App 交互流程重排

### 5.1 两条进场路径（贴卡直达 vs 手动签到）

**路径 A：NFC 贴卡（主推，一步到位）**

```
贴近 NFC 卡
  → 读卡成功即完成签到（NFC 记录本身就是到场凭证，不再落"签到确认页"）
  → 直接进入该点位检查页：第一步就是拍整体照
  → 拍完可立刻走去下一点位（AI 异步识别）
  → AI 结果回填检查项，员工「确认 / 改判」
  → 异常项：加拍特写 + 说明 + 选 上报待处理/现场已处理（现场已处理拍处置照，复用现有免异常照逻辑）
  → 全部点位完成 → 提交 → 审批链（AI 闸门 → 人工环节）→ 报告
```

**路径 B：任务列表手动进入（需手动完成 NFC 签到）**

```
任务列表点进点位
  → 进入检查页，但顶部显示「未签到」条，拍照/检查项可先填
  → 到设备旁点「NFC 签到」按钮贴卡 → 校验卡号属于本点位 → 解除「未签到」
  → 未签到的点位不允许提交（防不到场补录）
```

设计依据：贴卡动作本身即唯一性与到场证明，中间再插一页签到确认纯属多余点击；手动路径保留 NFC 校验是为了堵住"不到场在宿舍补录"的口子。

### 5.2 要点

- 贴卡直达检查页时，顶部保留一行点位信息条（点位名/楼栋楼层/绑定设备数/今日状态），信息可见但不挡操作；
- 拍照与走动并行，不为 AI 等待；
- 消火栓箱、灭火器、应急类拍法完全同构，员工学一次就会；
- NFC 不可用的机型（iOS 老机型等）回落到路径 B 的扫码签到。

## 六、类型化台账（一套数据，多套视图）

### 6.1 设计

设备表保持「固定主字段 + `extra` jsonb 口袋」不变，新增**类型字段方案**配置（按设备类型定义四样内容）：

| 配置项 | 灭火器（精细） | 消火栓箱（精细） | 指示牌等（精简） |
|---|---|---|---|
| 列表列 | 编号/点位/规格/换粉日期/到期/状态灯 | 编号/点位/配置/水压试验/状态 | 编号/位置/类型/状态 |
| 表单字段 | 含换粉、维修厂家等专属字段 | 含箱体配置、水压试验 | 通用几列 |
| 导入模板列 | 精简模板（对齐甲方换粉台账） | 精简模板 | 极简模板 |
| 导出列集 | 项目名称/所属系统/设备分类/点位信息/换粉日期 | 按类型定 | 通用集 |

- 专属字段存 `extra`，零表结构变更；高频字段后续可提为索引列；
- 未配方案的类型走通用默认集。

### 6.2 维修/换粉走流水，不堆台账列

换粉、维修是重复事件，归位到维保流水（`equipment_maintenance`）：

- 维保类型扩展：`换粉 refill`、`水压试验 hydro_test`（现有 repair/ledger_fix 旁加）；
- 台账「最近换粉日期」「下次换粉到期」由流水**聚合显示**，点击钻取完整历史；
- 换粉到期接入现有临期/逾期预警灯（灭火器 5 年首修、之后 2 年周期等规则按类型可配）。

### 6.3 台账页与导入导出

- 台账页顶部**类型页签**（全部/灭火器/消火栓箱/指示牌…），切换即切换列集+筛选项+表单——"单独每一项筛选显示出来的少"自然达成；
- **导出**：按类型一个 Excel 多 sheet（各 sheet 列集特化）；筛选单类型时只出该类型，灭火器导出即甲方换粉台账版式；
- **导入**：统一为按类型的精简模板（灭火器模板即甲方换粉台账版式）；列名宽松映射（「换药日期/换粉时间」均识别为换粉日期），未识别列照旧入 `extra` 口袋零丢失。旧 27 列大全表导入代码直接删除——甲方历史文件用对应类型的模板重新整理导入，不为旧格式留兼容代码。

## 七、月度巡检报告对齐官方版式

以甲方《物业消防设施（器材类）月度巡检报告.pdf》为准改版现有月报 PDF：

1. **封面**：项目名称/检查月份/设施类别/管理单位/报告日期/盖章位；
2. **编制说明**：NFC 打卡 + 人工核查 + AI 识别三重核验表述；
3. **签字审批栏**：巡检人 → 安全负责人 → 物业经理三级签字，从 `report_review` 审批链读取实际审核人；
4. **本月汇总表**：设施类别 × 总数/正常/完成率/存在问题/整改完毕/整改完成率；
5. **分项明细表**：4.1 灭火器（压力/瓶体/喷管/铅封/有效期）、4.2 消火栓（箱门/水带/枪头/接口/水压/周围）、4.3 应急灯等粗放表——列即原子模板检查项，AI 判定结果直接对列填充；
6. **问题清单及整改台账**：日期/问题/照片/处理情况/整改后照片/检查人——复用异常照 + 处置照成对输出；
7. **附件**：分项巡检照片电子档（按设备唯一编号归档）。

单次巡查粒度同步提供**实时查阅版**（每点位：整体照 + 各项判定 + 异常特写），App/PC 可看可打印。

## 八、实施分期

| 期 | 内容 | 解决的反馈 |
|---|---|---|
| **P1** | 点位多模板组合；整组 1 张拍照；AI 合并识别 + 全异步 + 压缩提速；类型化台账（类型页签/差异化列集/按类型导出，灭火器导出即换粉台账） | 检查项繁琐、识别慢、台账复杂 |
| **P2** | NFC 贴卡直达检查页（签到合一，去掉签到确认页）；手动进入走「NFC 签到」解锁提交；拍照优先交互重排；抽检 2% 抽样器；抽查计划（复用巡检计划模型加「抽查」类型：比例/数量、点位范围、生成日、期限、执行人、抽取策略可配）；维保流水扩 refill/hydro_test + 换粉到期预警 | 贴卡仍落签到页、界面不明、流程调整、每月抽查、换粉记录 |
| **P3** | 月报 PDF 对齐官方版式（封面/三级签字栏/汇总/分项明细/整改台账/照片附件）；单次巡查报告实时查阅 | 报告生成与打印 |

实施原则：
