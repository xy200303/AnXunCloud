# 物业巡检管理系统 接口文档

> 版本：v1.0
> 适用范围：Go（Gin）后端 / Web 管理后台（Vue3 + Element Plus）/ 微信小程序巡检端
> 配套文档：`docs/物业巡检管理系统方案.md`（功能与架构以该文档为准）、`docs/UI-UX设计方案.md`
> 说明：本文档在方案第六章接口清单基础上扩展补全，字段命名与方案第五章数据库设计一致，JSON 字段统一蛇形命名。

## 一、通用约定

### 1.1 BaseURL

| 端 | BaseURL | 说明 |
|---|---|---|
| Web 管理后台 | `https://{host}/api/admin` | 管理端全部接口 |
| 微信小程序 | `https://{host}/api/mp` | 巡检端全部接口 |

- 全站 HTTPS；请求与响应均为 `application/json; charset=utf-8`（OSS 回调除外，见 §1.7）。
- 路径参数以 `{id}` 表示，为 UUIDv7 字符串（全系统主键自 v2 起为应用层生成的 UUIDv7；JSON 中所有 ID 字段均为 string）。

### 1.2 鉴权方式

- 采用 JWT（access + refresh）双令牌，登录/刷新接口下发：
  - `access_token`：有效期 2 小时，用于业务接口鉴权；
  - `refresh_token`：有效期 7 天，仅用于刷新接口，服务端结合 Redis 会话校验，登出即失效。
- 请求头统一为：`Authorization: Bearer <access_token>`。
- 小程序端兼容 `X-Token: <access_token>` 请求头（与 `Authorization` 二选一，同时存在时以 `Authorization` 为准），便于部分小程序网络库使用。
- 免鉴权接口：登录、刷新 token、微信 code 换登录态、OSS 上传回调（服务端间，走回调验签，见 §3.4）。
- 权限校验：除登录态外，后台接口按 RBAC 中间件校验**权限点**（如 `system:user:list`），并校验**数据权限**（`data_scope=custom` 的角色仅能访问 `community_ids` 范围内的小区数据，越权返回 `40302`）。各接口的"权限点"栏标注所需权限点；标注"登录即可"表示仅需有效登录态。

### 1.3 统一响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 业务码，`0` 表示成功；非 0 见 §1.5 错误码表 |
| message | string | 提示文案，可直接展示给用户（中文） |
| data | any | 业务数据；失败时为 `null` |

- 业务错误同时返回匹配的 HTTP 状态码（如 401/403/404），`code` 以本文档错误码表为准，前端判断一律使用 `code`。

### 1.4 分页约定

**请求参数**（query string）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| page | int | 否 | 页码，默认 `1` |
| page_size | int | 否 | 每页条数，默认 `20`，最大 `100` |

**响应结构**（`data` 内）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "total": 128,
    "page": 1,
    "page_size": 20
  }
}
```

### 1.6 时间与坐标格式

- 时间：统一 `YYYY-MM-DD HH:mm:ss`（东八区，如 `2026-08-05 08:32:11`）；日期：`YYYY-MM-DD`；月份：`YYYY-MM`。服务端时间（`checkin_time`、`created_at` 等）以后端落库时间为准；`client_time` 为小程序端原始时间，格式同上。
- 坐标：GCJ-02（火星坐标系），`longitude`/`latitude` 为 float64（度），`distance_to_point` 单位为米（int）。
- 枚举字段在文中给出取值表；可配置枚举（点位类型、异常类型等）以字典管理数据为准。

### 1.7 文件上传约定（OSS STS 直传 + 回调）

照片不走应用服务器，小程序直传 OSS，后端只存 URL。时序：

```
小程序 ──① POST /api/mp/upload/sts ─────────▶ 后端
            （申请临时凭证，声明 scene/文件类型）
后端   ──返回 STS 临时凭证 + 直传策略（含回调配置）──▶ 小程序
小程序 ──② 直传照片到 OSS（FormData，携带 callback 参数）──▶ OSS
OSS    ──③ 服务端间回调 POST /api/mp/upload/callback ──▶ 后端
            （后端验签 → 打水印 → 写文件记录 → 返回 {"Status":"OK"}）
小程序 ──④ 轮询/重试后提交业务接口（携带 file_key）────▶ 后端
            （后端校验 file_key 已回调落库且属于当前用户）
```

约定：

- 一次 `POST /upload/sts` 可申请多个文件的上传策略；凭证有效期 `expire_seconds`（默认 3600s）。
- 对象键（`file_key`）规则：`{scene}/{yyyyMM}/{uid}/{uuid}.{ext}`，`scene` 取值：`checkin`（打卡照片）、`workorder`（工单处理照片）、`avatar`（头像）。
- 小程序直传后，以 `file_key` 作为业务接口（打卡提交、工单反馈）中的照片引用；后端校验该 key 已收到 OSS 回调，否则返回 `43106`。
- 打卡照片由后端在回调中叠加水印（点位名称、时间、GPS 坐标、巡检员姓名），生成 `watermarked_url`；列表展示用水印缩略图，查看器加载原图（私有读，URL 带签名，有效期 15 分钟）。
- 单文件 ≤ 20MB，类型限 jpg/jpeg/png/heic。

### 1.8 统一文件接口（/api/files，v21 新增）

跨端（admin/app/mp 任一通道登录态均可）的统一上传下载入口，逐步替代各端分散的上传接口；文件元数据统一登记 `upload_file`（原始文件名 `name`、内容摘要 `md5`、存储驱动 `storage`）。

| 接口 | 说明 |
|---|---|
| `POST /api/files` | 统一上传（multipart：`file` + `scene`）。scene 合集：checkin/workorder/avatar/signature/seal/notice（notice 放宽到办公文档） |
| `POST /api/files/sts` | 直传凭证签发（语义同 §1.7，云模式返回 OSS 凭证，dev 返回本地上传入口） |
| `GET /api/files/{file_key}` | 统一下载/预览。local 驱动流式返回（图片/PDF 默认 inline，`?download=1` 强制附件，文件名为原始名称）；云驱动 302 到对象地址 |

鉴权与权限：

- 认证支持 `Authorization: Bearer` 与 `?token=` 查询参数（后者供 `<img>`、浏览器直连、系统分享面板等无法带请求头的场景）；
- 读权限按 scene：`export/reports` 需 `report:download`，`export/stats` 需 `stats:export`，`export/qrcode` 需 `inspection:point:qrcode`；`signature`/`seal` 限本人或持签章/报告权限点；`checkin`/`workorder`/`avatar`/`notice` 登录即可读；
- 旧的 `/api/admin/system/upload`、`/api/mp/upload/*` 保留兼容（别名期），`/uploads/*` 静态目录在存量 URL 迁移完成前继续提供读服务。

## 二、管理后台接口（/api/admin）

### 2.1 认证

#### 2.1.1 登录

`POST /auth/login` — 后台账号密码登录，下发双令牌。鉴权：免登录。

请求参数（body）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 用户名 |
| password | string | 是 | 密码（明文，传输走 HTTPS） |

请求示例：

```json
{ "username": "admin", "password": "Admin@123" }
```

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token_type": "Bearer",
    "access_token": "eyJhbGciOi...",
    "refresh_token": "d8f2c1...",
    "expires_in": 7200
  }
}
```

业务错误码：40105、40104。

#### 2.1.2 登出

`POST /auth/logout` — 注销当前会话，token 加入 Redis 黑名单。鉴权：登录即可。请求参数：无。

响应示例：

```json
{ "code": 0, "message": "success", "data": null }
```

业务错误码：无。

#### 2.1.3 刷新 token

`POST /auth/refresh` — 用 refresh_token 换取新双令牌（旧 refresh_token 作废，滚动刷新）。鉴权：免登录。

请求参数（body）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| refresh_token | string | 是 | 登录时下发的 refresh_token |

请求示例：

```json
{ "refresh_token": "d8f2c1..." }
```

响应示例：同 2.1.1 的 `data` 结构。

业务错误码：40103、40104。

#### 2.1.4 获取用户信息

`GET /auth/info` — 当前登录用户信息 + 按钮级权限点集合。鉴权：登录即可。请求参数：无。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "username": "admin",
    "name": "系统管理员",
    "phone": "13800000000",
    "avatar": "",
    "roles": [{ "id": 1, "code": "super_admin", "name": "超级管理员" }],
    "community_ids": [],
    "data_scope": "all",
    "perms": ["system:user:list", "system:user:create", "inspection:point:list"],
    "openid": "",
    "created_at": "2026-06-01 10:00:00",
    "last_login_at": "2026-08-05 08:01:22",
    "last_login_ip": "112.10.22.8"
  }
}
```

> `community_ids` 为空 + `data_scope=all` 表示全部小区；前端按钮显隐依据 `perms`。
> `openid` 为空表示未绑定微信小程序；`last_login_ip` 取该用户最近一次 status=success 的登录日志 IP。

业务错误码：40101。

#### 2.1.5 获取动态路由菜单

`GET /auth/routes` — 按当前用户角色下发菜单树（dir/menu 类型），前端动态生成路由与侧边栏。鉴权：登录即可。请求参数：无。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": 10,
      "parent_id": 0,
      "title": "巡检管理",
      "path": "/inspection",
      "icon": "Location",
      "type": "dir",
      "sort": 20,
      "children": [
        {
          "id": 11,
          "parent_id": 10,
          "title": "点位管理",
          "path": "/inspection/points",
          "icon": "MapLocation",
          "type": "menu",
          "sort": 1,
          "children": []
        }
      ]
    }
  ]
}
```

业务错误码：40101。

#### 2.1.6 获取开放注册配置

`GET /auth/register-config` — 查询是否开放自助注册（登录页据此显示注册入口）。鉴权：免登录。请求参数：无。

响应示例：

```json
{ "code": 0, "message": "success", "data": { "enabled": false } }
```

业务错误码：无。

#### 2.1.7 开放注册

`POST /auth/register` — 自助注册后台账号（受系统参数 `auth.register_enabled` 开关控制，后台系统配置页可开启/关闭，修改即时生效）。鉴权：免登录。

请求参数（body）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 登录名，4–20 位字母数字下划线 |
| password | string | 是 | 密码，8–32 位，须含字母与数字 |
| name | string | 是 | 姓名 |
| phone | string | 是 | 手机号（1 开头 11 位，全局唯一） |

请求示例：`{ "username": "zhangsan", "password": "Init@2026", "name": "张三", "phone": "13900001111" }`

响应示例：`{ "code": 0, "message": "success", "data": null }`

> 注册成功的账号**不绑定任何角色**：可正常登录，但 `GET /auth/routes` 返回空菜单、无按钮权限点，仅可访问"登录即可"的接口（如个人中心）；由管理员在后台分配角色后获得功能权限。
> 注册失败（参数/唯一性校验不通过）计入登录同口径的 IP 限流（`limit:login:{ip}`，连续失败达 `security.login_fail_limit` 锁定 10 分钟，返回 42900）。

业务错误码：40303、41001、41008、40001、42900。

#### 2.3.9 导入用户

`POST /system/users/import` — multipart 上传 Excel 批量开通账号。权限点：`system:user:import`。

请求：`Content-Type: multipart/form-data`，表单字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | file | 是 | Excel 文件（.xlsx），≤ 5MB，数据行 ≤ 500 行（不含表头与示例行） |

导入策略：**跳过失败行、导入成功行**，整批不为失败明细而回滚。

服务端逐行校验规则（按序，首个不通过即记为失败行）：

1. 必填校验：姓名、手机号、角色、所属小区均非空；
2. 手机号格式校验（1 开头 11 位）与唯一性校验（库中已存在或本批次内重复均失败）；
3. 角色名称必须存在（多个角色逐一匹配，任一不存在即失败）；
4. 小区名称必须存在（同上，逐一匹配）。

导入成功的用户：`username` 取手机号，初始密码取 E 列或手机号后 6 位，bcrypt 落库，并标记**首次登录强制修改密码**（登录响应 `data.user.must_change_password: true`，前端据此跳转改密页）。

响应示例：

```json
{
  "code": 0,
  "message": "导入完成：成功 47 条，失败 3 条",
  "data": {
    "total": 50,
    "success_count": 47,
    "fail_count": 3,
    "fail_details": [
      { "row": 5, "phone": "13900001111", "reason": "手机号已存在" },
      { "row": 12, "phone": "1371234", "reason": "手机号格式错误" },
      { "row": 23, "phone": "13822223333", "reason": "角色「保安队长」不存在" }
    ]
  }
}
```

> **失败明细的取舍说明**：失败明细由本接口响应直接带回（`fail_details`），**不**再提供单独的"下载失败明细"接口。理由：单次上限 500 行，失败明细体量小，响应直接带回可减少一次往返；同时避免服务端为临时结果引入存储与过期清理。前端可将 `fail_details` 在本地导出为 Excel 供修正后重新导入。

业务错误码：41011（文件格式错误）、41012（空文件/无有效数据行）、41013（超过 500 行上限）、40001、40301。逐行业务原因（41008 手机号重复、41009 角色不存在、41010 小区不存在等）体现在 `fail_details[].reason` 中，不作为整批响应 code。

响应示例：

```json
  "message": "success",
```


#### 2.7.7 地点搜索（地图选点辅助）

`GET /map/search?keyword={关键字}&location={lat,lng}` — PC 后台地图选点弹窗的地点搜索。鉴权：登录即可。后端代理腾讯地点提示 API（`/ws/place/v1/suggestion`），避免前端跨域且 key 不出服务端。`location` 可选，传当前地图中心坐标可让结果偏向附近。

key 读取顺序：`map.tencent_ws_key`（服务端 WebService 专用，需勾选 WebserviceAPI 且不设域名白名单）→ 为空回退 `map.tencent_key`。注意：服务端请求无 Referer，若只对 JS key 设了域名白名单会被腾讯拒绝（status 110），建议单独申请 WebService 专用 key。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    { "title": "翡翠湾", "address": "浙江省杭州市西湖区xx路", "lng": 120.212001, "lat": 30.208112 }
  ]
}
```

业务错误码：40001（keyword 为空 / key 未配置）、50000（腾讯侧错误，message 透传腾讯错误说明）。

审核状态直接落在打卡记录上（`audit_status`：`auto_pass` 默认通过 / `pending` 待审核 / `pass` 人工通过 / `rejected` 已打回），无独立审核表。列表检索复用 2.14.1：`audit_status` 支持逗号多值（如 `pass,rejected` 查"已审核"合集），列表项含 `ai_verdict` / `ai_reason` 大模型结论字段。`GET /inspection/checkins/audit-counts` 返回各审核状态计数（`{"auto_pass","pending","pass","rejected"}`），与列表共用过滤条件但忽略 `audit_status` 参数，用于列表页 tab 数量徽章。

| 接口 | 说明 | 权限点 |
|---|---|---|
| `POST /inspection/review/{id}/pass` | 单条通过（仅 pending 可审） | `inspection:checkin:review` |
| `POST /inspection/review/{id}/reject` | 单条打回，body `{"reason":"..."}`，站内通知巡检员 | `inspection:checkin:review` |
| `POST /inspection/review/batch-pass` | 批量通过，body `{"ids":["uuid"...]}`（1-200 条）；仅 pending 被更新，返回 `{"passed":N,"skipped":M}` | `inspection:checkin:review` |

| `POST /inspection/review/spotcheck` | 发起抽查：body `{"community_id","inspector_id","start_time","end_time","mode":"random|full","ratio","handler":"manual|ai"}`；manual 从 auto_pass/pass 抽转 pending（上限 500），ai 逐条大模型分析（上限 50） | `inspection:checkin:spotcheck` |

### 2.17 检查项模板

> 模板全局共享（不做小区数据权限）。v18 起检查项存独立表 `check_template_item`，打卡时逐项快照进 `checkin_record_item`（复制当时的 name/requirement/photo_required），改模板不影响历史打卡记录。

- `GET /inspection/templates` — 列表（分页，query：`name` / `point_type` / `status`）。权限点：`inspection:template:list`。
- `POST /inspection/templates` — 新增。权限点：`inspection:template:create`。
- `GET /inspection/templates/{id}` — 详情。权限点：`inspection:template:list`。
- `PUT /inspection/templates/{id}` — 修改模板自身字段（检查项由项级接口单独维护）。权限点：`inspection:template:update`。

项级粒度接口（检查项按行增删改，历史打卡记录已快照进 `checkin_record_item`，删/改项不影响记录）：

### 3.3 打卡

#### 3.3.1 打卡提交

`POST /checkin` — 点位打卡（含异常上报，异常时自动生成工单）。鉴权：登录。

请求参数（body）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| task_id | int | 是 | 任务 id |
| point_id | int | 是 | 点位 id |
| checkin_type | string | 是 | `qrcode` 扫码 / `fence` 围栏 |
| qrcode_no | string | 条件必填 | 扫码打卡时必填（`wx.scanCode` 码值），服务端与点位比对 |
| longitude | float | 是 | 打卡时 GCJ-02 经度（防作弊字段） |
| latitude | float | 是 | 打卡时 GCJ-02 纬度（防作弊字段） |
| client_time | string | 是 | 客户端原始时间 `YYYY-MM-DD HH:mm:ss`（防作弊字段，服务端落库仍以服务端时间为准） |
| result | string | 是 | `normal` 正常 / `abnormal` 异常 |
| remark | string | 条件必填 | 异常时必填描述 |
| check_items | object[] | 条件必填 | 逐项检查结果 `[{"name":"保险销完好","pass":true,"note":"","photos":["checkin/202608/12/u3.jpg"]}]`；点位绑定检查项模板时模板每项都必须有提交结果；`photos` 为该项照片 file_key 数组（可选，约束见下） |
| photos | object[] | 是 | 记录级（全景）照片数组 `[{"item":"配电箱","file_key":"checkin/202608/12/u1.jpg"}]`；必拍项缺一不可提交；`file_key` 须经 OSS 回调确认 |

> 逐项照片硬约束：`check_items[].pass=false`（不合格）的项必须带 ≥1 张该项照片；模板中 `photo_required=required` 的项即使合格也必须带 ≥1 张该项照片。缺照片返回 43104 并指明检查项名称。

请求示例：

```json
{
  "task_id": 1024,
  "point_id": 105,
  "checkin_type": "fence",
  "longitude": 120.214001,
  "latitude": 30.207112,
  "client_time": "2026-08-05 09:05:10",
  "result": "abnormal",
  "remark": "消防栓渗水",
  "photos": [
    { "item": "消防栓", "file_key": "checkin/202608/12/u9.jpg" },
    { "item": "现场照片", "file_key": "checkin/202608/12/u10.jpg" }
  ]
}
```

响应示例：

```json
{
  "code": 0,
  "message": "打卡成功",
  "data": {
    "checkin_id": 88003,
    "checkin_time": "2026-08-05 09:05:12",
    "distance_to_point": 126,
    "is_suspect": true,
    "suspect_reason": "距点位 126m，超阈值 100m",
    "work_order": { "id": 88, "order_no": "WX20260805-003" },
    "task_progress": { "total_points": 12, "done_points": 10, "progress": 83, "task_status": "doing" }
  }
}
```

服务端校验逻辑（按序）：

1. 任务归属与状态校验（43105）；
2. 该点位重复打卡校验（43103）；
3. 按点位凭证与围栏配置校验：`credential=qrcode` 校验 `qrcode_no` 匹配（43101），`credential=nfc` 校验 NFC 卡号匹配，`require_fence=true` 校验 Haversine 距离 ≤ `fence_radius`（43102）；同时启用时都须通过；
4. 必拍项完整性校验（43104）与照片回调确认（43106）；逐项照片约束（不合格项 / 模板 required 项 ≥1 张该项照片，43104）；
5. 距离 > 参数 `suspect.distance_threshold` 时标记 `is_suspect`（不阻断提交，仅计入报表）；
6. `result=abnormal` 时自动生成工单（`pending` 状态）并推送主管；不合格项快照（项名+备注+该项照片 file_key）写入工单 `items` 的 `before_photos`。

业务错误码：43101、43102、43103、43104、43105、43106、40001。
