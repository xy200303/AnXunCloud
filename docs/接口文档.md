## 一、通用约定

### 1.1 接口分组与 BaseURL

| 分组 | 前缀 | 使用方 | 认证通道 |
|---|---|---|---|
| 管理后台 | `/api/admin` | PC 管理端（Vue SPA，生产单端口托管于 `/admin` 子路径） | `admin` |
| App 端 | `/api/app` | Android / iOS / 鸿蒙 App | `app` |
| 小程序端 | `/api/mp` | 微信小程序（与 App 共用 `app` 通道会话） | `app` |
| 统一文件层 | `/api/files` | 三端共用（AuthAny 跨通道认证） | `admin`/`app`/`mp` 任一合法会话 |
| 公开接口 | `/api/public`、站点页面 | 官网访客、短链接扫码、一次性 ticket | 免登录 |

App 端与小程序端的任务/打卡/点位/上传/消息/公告业务接口**同形同逻辑**（同一批 Controller/Service），路径前缀按端替换；差异仅在登录方式与 App 端额外挂载的管理功能（见第四章）。

### 1.2 认证与会话

- 登录/刷新签发**双令牌**：`access_token` + `refresh_token`，响应含 `token_type`（Bearer）、`expires_in`（秒）。
- 业务请求携带访问令牌，两种头等价：`Authorization: Bearer <access_token>` 或 `X-Token: <access_token>`。
- 会话存于 Redis，按通道隔离（admin / app 各自独立）；登出、改密、重置密码、停用/删除账号会使对应会话失效。
- 令牌过期返回 `40102`；用 `refresh_token` 调各端 `/refresh` 滚动换新（旧 refresh 即作废）；refresh 失效返回 `40103`，需重新登录。
- 登录失败限流：同一 IP 连续失败达 `security.login_fail_limit`（默认 5）锁定 10 分钟（`42900`）。

### 1.3 多租户与数据权限

- 系统为**多租户**架构（租户 = 物业公司）。登录时用户名命中多个租户且密码相同者多于一个时，返回 `40109` 并在 `data.tenants` 下发候选公司列表，前端选择后带 `tenant_code` 重提。
- 系统管理（租户级）接口按**租户上下文**过滤：非超管固定为本人租户；超管可用 `?tenant_id=` 或 `X-Tenant-Id` 头指定目标租户（缺省默认租户 `default`）。
- 业务数据（小区/点位/计划/任务/打卡/报告等）经 `community`（小区/项目）链路天然按租户隔离；角色数据范围 `data_scope`（all/project/self）由中间件按所辖小区过滤，越界返回 `40302`。
- 租户停用后该租户全部账号无法登录（`40108`）。
- 写操作（POST/PUT/DELETE）大多挂操作日志中间件（`sys_operation_log`），表中不再逐条标注。

### 1.4 统一响应结构

所有 JSON 接口（含错误）统一包装：

```json
{ "code": 0, "message": "success", "data": {} }
```

- `code=0` 成功；非 0 为业务错误码（见 1.7），`message` 为可读提示，`data` 为 `null` 或附加数据（如 40109 的候选租户列表、43107 的重拍次数上限）。
- 文件下载、Excel/zip 导出、SSR 页面、二维码图片等二进制响应不适用该包装。

### 1.5 分页约定

- 请求（query）：`page`（默认 1）、`page_size`（默认 20，上限 100）。
- 响应 `data`：`{ "list": [], "total": 0, "page": 1, "page_size": 20 }`。
- 例外：任务详情的点位时间线使用 `points_page`/`points_page_size`（默认 50，上限 200），见 2.13。

### 1.6 时间与 ID 格式

- 日期时间：`YYYY-MM-DD HH:mm:ss`（本地时区）；日期：`YYYY-MM-DD`；报告期间：月报 `YYYY-MM`（报告生成计划产生的周报/日报 period 为展示串，如 `2026-08-31~09-06`、`2026-09-01`）。
- 主键 ID 为 UUID 字符串；移动端打卡 `id` 支持客户端生成 **UUIDv7** 做幂等（见 4.3）。

### 1.8 文件存储与 scene 约定

- 上传成功即登记 `upload_file` 记录并返回 `file_id`（UUID）；**业务接口只传 `file_id`**（服务端解析为存储路径并校验归属）。存储路径 `file_key`（如 `checkin/202608/<uid>/<uuid>.jpg`）为内部实现，仅 `/api/files/*key` 下载与 OSS 回调链路可见。
- 上传 scene 白名单：`checkin`（打卡照片）、`avatar`（头像）、`signature`（手写签名）、`seal`（公章）、`notice`（公告附件，放宽到 pdf/word/excel/ppt/txt/zip）。`export`（导出包）、`app`（安装包发布物）为服务端生成/专用通道，不经 `/api/files` 上传。
- 读权限按 scene 判定：`export/reports|stats|qrcode` 需对应权限点（report:download / stats:export / inspection:point:qrcode）；`signature`/`seal` 本人或签章/报告相关权限；其余（checkin/avatar/notice）登录即可。
- 本地存储模式下，非敏感内容图也可经 `GET /uploads/*key` 免登录访问；保护前缀（signature/seal/export 等）在该路由返回 404，只能经 `/api/files` 鉴权访问。
- 存储驱动三种模式：本地磁盘（local）、阿里云 OSS（STS 直传 + 服务端回调）、腾讯云 COS（服务端签名直写）。移动端经 `POST {端}/upload/sts` 或 `POST /api/files/sts` 获取上传入口/凭证。
