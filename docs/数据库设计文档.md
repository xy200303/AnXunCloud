# 物业巡检管理系统 数据库设计文档

> 版本：v3.0（多租户/岗位编制重构后全面重写）
> 适用范围：安巡云物业巡检平台 PostgreSQL 数据库
> 本文档以代码为准：`backend/internal/module/*/model/models.go`（模型终态）、`backend/internal/pkg/database/migrations/`（00001–00025 迁移）
> 配套文档：《接口文档》《多租户组织架构与角色权限设计方案》《管理后台信息架构与菜单归位方案》

## 一、总体约定

### 1.1 基本信息

| 项 | 值 |
|---|---|
| 数据库 | PostgreSQL 15 |
| 字符集 | UTF-8 |
| 表数量 | 32 张（含 2 张按月分区主表） |
| 主键 | `id uuid`，**应用层生成 UUIDv7**（`types.UUIDModel` + BeforeCreate 钩子；PG 15 无 uuidv7()，统一走应用层，客户端可自带 ID 实现离线幂等写入） |
| 时区 | 时间列均为 `timestamptz`，应用层按东八区处理 |

### 1.2 通用列与软删除

- 业务表普遍含 `created_at` / `updated_at`；多数主数据表含 `deleted_at`（gorm 软删除，唯一索引普遍带 `WHERE deleted_at IS NULL` 部分条件）。
- 日志类表（sys_login_log / sys_operation_log / work_order_log / sys_message / upload_file / sign_asset / app_release / casbin_rule / duty_binding / project_staff 等）**只增不改或硬删**，无 `deleted_at`。
- `tenant_id` 一律 `uuid` 类型，引用 `tenant.id`（不建物理外键，应用层保证）。

### 1.3 jsonb 数组约定

系统大量使用 `jsonb` 存储数组/对象，对应 `backend/internal/pkg/types/jsonb.go` 的自定义类型，落库统一为非 NULL（空为 `[]` / `{}`）：

| 类型 | 形态 | 用途示例 |
|---|---|---|
| `IDArray` | uuid 字符串数组 | sys_user.role_ids、inspection_plan.point_ids / inspector_ids、project_staff.building_ids、inspection_report.inspector_ids / supervisor_ids / manager_ids |
| `StringArray` | 字符串数组 | project_staff.posts（岗位代码）、duty_binding.post_codes、inspection_point.required_photo_items、checkin_record_item.photos（file_key 数组） |
| `JSONMap` | 对象 | inspection_plan.cycle_config、inspection_report.stats |
| `PhotoArray` | `[{item,url,watermarked_url,exif_time,required}]` | checkin_record.photos、work_order.photos / finish_photos |
| `OrderItemArray` | `[{name,remark,before_photos,after_photos}]` | work_order.items 不合格项快照（photos 存 file_key，before/after 按 name 合并） |
| `SignArray` | `[{user_id,name,signed_at,signature_file_key,asset_id,proxy_by,proxy_name,proxy_reason}]` | inspection_report.inspector_signed 签字留痕（含代签三字段） |
| `AttachmentArray` | `[{name,url}]` | sys_notice.attachments |

### 1.4 多租户行级隔离

租户（`tenant`）= 物业公司，是数据隔离基本单位。隔离策略分三档：

1. **入口表租户必填**：`sys_user`、`community` 的 `tenant_id` 非空，登录账号租户内唯一、业务数据经 community 归属租户。
2. **租户可空 = 平台共享**：`sys_role`（空=内置角色，全平台只读共享）、`post_dict`（空=平台内置模板岗位）；唯一索引用 `COALESCE(tenant_id, 零UUID)` 处理。
3. **冗余列便于过滤**：业务表（building / inspection_point / inspection_plan / inspection_task / checkin_record / work_order / inspection_report / check_template / sys_notice / sys_message / upload_file / sign_asset / sys_login_log / sys_operation_log）带 `tenant_id` 冗余列（=所属小区租户或操作者租户），查询主路径仍按 community/接收人链路隔离，冗余列用于日志过滤与统计。

### 1.5 状态字段约定

- 启停用统一 `status varchar(16)`，取值 `enabled` / `disabled`；接口层以 `1` / `0` 交互（`model.StatusInt` / `StatusStr` 互转）。
- 例外：`sys_notice.status` 为 int（0 草稿 / 1 已发布 / 2 已下线）。
- 业务流程状态（工单、报告、任务、打卡审核等）为字符串枚举，见各表说明与第八章汇总。

### 1.6 分区表（运行期滚动建分区）

`checkin_record` 与 `sys_operation_log` 为**按月 RANGE 分区表**（分区键 `created_at`，主键为 `id + created_at` 复合），各带一个 DEFAULT 分区兜底。应用启动时与巡检调度器每日执行 `database.EnsurePartitions`，自动创建**当月与下月**分区（`CREATE TABLE IF NOT EXISTS ... PARTITION OF ... FOR VALUES FROM ... TO ...`），无需人工干预。因主键含分区键，外键无法仅引用分区表的 `id`（见 checkin_record_item 说明）。

## 二、平台与租户域

### 2.1 tenant（租户）

物业公司，多租户隔离基本单位；`code`（公司代码）用于登录时多租户消歧。私有化部署 = 只有默认租户（`code=default`）的同一套系统。

| id | uuid PK | UUIDv7 |

| name | varchar(128) | 物业公司名称 |
| contact_name / contact_phone | varchar | 联系人/电话 |

## 八、关键设计说明

### 8.1 分区与大表策略

- `checkin_record`、`sys_operation_log` 按月 RANGE 分区 + DEFAULT 分区兜底；应用启动与每日调度自动预建当月/下月分区（`EnsurePartitions`）。
- 分区表主键必须含分区键（id + created_at），因此跨表 FK 只能引用其全部主键列；checkin_record_item 刻意不加 FK，走应用层事务一致性。
- 归档清理可按分区整表 DROP，成本远低于 DELETE。

### 8.2 多租户与有效角色

- 登录链路：`sys_user.tenant_id` + 用户名消歧（tenant_code）；业务链路：community → 各业务表。
- 有效角色 = 用户直挂角色（sys_user.role_ids）∪ 在职编制岗位绑定角色（project_staff → post_dict.role_id），**实时并集**，不物化；数据范围同理取并集最优档，主管级岗位（is_supervisor）自动推导 project 档。

### 8.3 名单制授权

工单分诊/派单/接单、月报主管/经理签字等业务身份一律走 duty_binding 槽位 → 岗位 → 在职编制人员名单，不再从「权限点 + 数据范围」反推；项目级可覆盖租户/平台默认绑定。

### 8.4 快照语义

模板项（checkin_record_item）、不合格项（work_order.items）、报告统计（inspection_report.stats）、签字图与公章（signature_key / seal_file_key）均为**写时快照**，历史数据不随源表变更。

### 8.5 坐标系

经纬度统一 GCJ-02（火星坐标系），与高德地图选点一致；numeric(10,7) 精度约 1cm 级。

### 8.6 编号规则

- 主键 UUIDv7（时间有序，利于索引局部性与客户端幂等）。
- work_order.order_no：应用层按日期 + 序号生成，全局唯一（uk_order_no）。
- 短链接 code = inspection_point.qrcode_no（uk_point_qrcode）。
