# 移动端四端 UI/UX 设计方案（uni-app · Vue3）

> 版本：v2.1 2026-08-11（v2：Flutter → uni-app x；v2.1：定案经典 uni-app（Vue3）。四端：Android/iOS/鸿蒙 NEXT/微信小程序，设计令牌与交互规范不受技术栈调整影响）
> 配套：《移动端四端技术方案》；设计令牌与《UI-UX设计方案》（Web 后台）同源。
> 用户画像：一线巡检员/维修工为主（户外、走动、弱光、单手、可能戴手套），主管/经理为辅（审批签字）。

---

## 一、设计原则

1. **首页即任务**：打开一步到打卡，核心路径 ≤3 次点击（任务 → 扫码 → 提交）。
2. **大目标、强反馈**：触达目标 ≥88px（@750 设计稿基准，约 44pt），主按钮高 104px；打卡成功震动 + 音效 + 全屏结果页。
3. **弱网是常态**：离线是常驻状态而非异常页——全局横幅提示，可离线完成的操作全部放行（入队补传）。
4. **一屏一主操作**：每屏仅一个主色主按钮，次要操作降级为描边/文字按钮。
5. **不用颜色单独表意**：状态 = 色块 + 图标 + 文字三件套（色弱友好，强光下仍可读）。
6. **四端同语言**：色彩/圆角/间距/图标一套令牌；平台差异只在导航习惯与系统能力（NFC 触发方式、权限引导）。

## 二、设计令牌

### 2.1 色彩（与 Web 后台完全一致）

| Token | 值 | 用途 |
|---|---|---|
| `primary` | `#2B5AED` | 主按钮、选中 tab、关键操作 |
| `primary-light` | `#EAEFFF` | 选中底色、标签底色 |
| `success` | `#2BA471` | 已巡/正常/打卡成功/已闭环 |
| `warning` | `#ED7B2F` | 待巡/待复核/临近超时/离线 |
| `danger` | `#D54941` | 异常/逾期/疑似作弊/驳回 |
| `info` | `#909399` | 次要/已关闭 |
| `bg-page` | `#F5F6F8` | 页面底色 |
| `bg-card` | `#FFFFFF` | 卡片 |
| `text-primary` | `#1F2329` | 主文字（对比度 14:1） |
| `text-regular` | `#4E5969` | 正文 |
| `text-secondary` | `#86909C` | 辅助（仅非关键信息） |
| `border` | `#E5E6EB` | 分割线 |

深色模式一期不做（外勤白天场景）；全部颜色走语义 token，后期加暗色零重构。

### 2.2 字号（750 设计稿基准，户外可读优先）

| 样式 | 字号/字重 | 用途 |
|---|---|---|
| Display | 56 / 700 | 打卡结果页大结果（"打卡成功"） |
| Title | 40 / 600 | 页面标题、卡片主标题（点位名） |
| Body-L | 34 / 400 | 正文（检查项、任务信息），不小于 32 |
| Body | 30 / 400 | 次要信息 |
| Caption | 26 / 400 | 辅助说明、时间戳 |
| Number | 48 / 600（等宽数字） | 任务计数、统计数字 |

字体跟随系统（Android 默认黑体、iOS PingFang SC、鸿蒙 HarmonyOS Sans），不内嵌字体包。

### 2.3 间距 / 圆角 / 尺寸（750 基准）

- 间距 8 的倍数：`8 / 16 / 24 / 32 / 48 / 64`；卡片内边距 32、卡片间距 24、区块间距 48。
- 圆角：卡片 24、按钮 20、标签 12、底部弹层 32（顶部两角）。
- 触控目标 ≥88×88px，目标间距 ≥16px；列表行高 ≥128px。
- 主按钮：高 104px、全宽、字号 34/600；固定底部操作栏加 safe-area 内边距。
- 阴影仅一级：`0 4 16 rgba(0,0,0,0.06)`；弹层用 45% 黑遮罩。

## 三、导航架构

### 3.1 一级导航：底部 Tab + 中央打卡主按钮

```
┌─────────────────────────────────┐
│            ╭─────╮              │
│  任务  工单│ 扫码 │ 消息   我的   │
│            │ 打卡 │              │
│            ╰─────╯              │
└─────────────────────────────────┘
```

- 四个 tab 图标 + 文字（禁纯图标）；选中态 = 主色图标 + 文字加粗；未选中 `#86909C`；
- **中央凸起主按钮**：全 App 最高频动作"打卡"钉在导航正中，任何 tab 一拇指即达；主色圆形凸起（直径 ≥112px），**纯扫码图标、无文字**（四个 tab 保持图标+文字，中央按钮以形态和颜色区分，信息层级天然高于 tab；无障碍朗读标签为"打卡"）；它是动作不是页面，不做选中态；
- 中央按钮默认进入扫码页；NFC 不单设入口——扫码页内按平台条件编译给"改用 NFC"（iOS 必须主动触发；Android/鸿蒙支持贴标签被动唤起，无需入口）；
- 消息 tab 未读角标（>99 显示 99+），进入即清已读；
- 工单 tab 对巡检员与维修工都显示，视角不同（后端 `MyOrders` 同一接口，`type` 过滤）：巡检员默认看"**我上报的**"（跟踪异常整改进展），维修工默认看"**待我处理**"；两端都可切换查看全部与自己相关的单。主管/经理不显示该 tab（管理视角在 PC 后台）；
- tabBar 实现：**APP 端**自绘 tabBar 组件按角色动态装配；**小程序端**自定义 tabBar（custom-tab-bar）实现同逻辑（中央按钮两端同构）；
- 返回行为遵循平台习惯：Android 物理返回、iOS 左滑返回、鸿蒙同 Android；一级 tab 页双击退出（Toast"再按一次退出"）。

### 3.2 路由与深链

- 页面路径即深链：`/pages/tasks/today`、`/pages/tasks/detail?id=`、`/pages/workorders/detail?id=`、`/pages/reports/pending`、`/pages/reports/detail?id=`、`/pages/messages/index`、`/pages/profile/index`；扫码无独立页面（midButton 直接调起系统扫码，见 4.3）；
- 消息点击深链直达业务页（待签 → 报告详情；派单 → 工单详情）；
- 登录守卫：无 token 重定向登录页；refresh 失败清栈回登录并提示（过期/他端下线）。

### 4.3 扫码/NFC 打卡（任务定位器）

设计定位：**扫码/NFC 的首要作用是"快速定位任务"，不是可信凭证**（二维码可被拍照代扫，凭证力弱）；可信维度由 GPS 围栏 + 照片水印 + EXIF 承担。因此交互上一律"即扫即达"：

- 中央"打卡"按钮（iOS 在其扫码页手动触发 NFC）→ 识别编号 → **直接落到该点位检查项页**，无中间确认页；
- **NFC 全局前台识别（Android/鸿蒙）**：App 打开的任何页面，贴到今日任务内点位的 NFC 标签即自动弹出对应任务（无需先点任何按钮）；陌生标签静默忽略不误弹；正在打卡表单页时改为顶部提示条（"识别到点位：XXX，是否切换"），不打断当前录入；iOS 受 CoreNFC 限制无此能力，统一走扫码页手动触发；
- 该点位今日多个任务 → 进最近未完成的一个；已完成 → 展示打卡记录（防重复打）；非今日任务 → 底部红条提示、取景不中断；
- 任务详情页内扫码 = 校验 + 定位：扫对直接确认，扫错提示"与当前任务点位不符"；
- 无二维码/NFC 的点位（`credential=none`）：任务列表点入直接打卡，任务行不显示扫码引导；配了围栏的仍受 GPS 约束；
- 不提供手动输入编号（防不到场代输）；二维码污损时由后台重打二维码或临时切换 NFC。

```
（点中央按钮 → 直接拉起系统全屏扫码页，onlyFromCamera 禁相册防照片代扫；
 无任何中间页；iOS 先弹"扫码打卡 / NFC 打卡"选项框）
```

入口：底部导航中央"打卡"按钮（全局，点击即调起扫码）+ 任务页内扫码（校验定位）。识别成功震动 + 短音效，0.2s 内进检查项页；权限被拒给系统设置引导。
实现取舍：扫码用系统全屏扫码页（uni.scanCode + onlyFromCamera 禁相册），不自绘取景页（plus.barcode 自绘在部分基座上挂载不稳定，且 Ba-Scanner 类原生组件需付费+自定义基座，M5 再评估）。

## 五、四端平台差异处理

| 项 | Android | iOS | 鸿蒙 NEXT | 微信小程序 |
|---|---|---|---|---|
| 返回 | 物理返回键 | 左滑手势 + 导航栏返回 | 同 Android | 导航栏返回 + 右滑 |
| NFC | App 内任意页面贴标签自动弹任务；未打开时贴标签唤起 App | 必须点中央"打卡"按钮 → 扫码页手动触发（CoreNFC 系统面板） | 同 Android | 一期不支持 |
| 权限引导 | 运行时权限 | 先预说明页再触发系统授权 | 同 iOS 策略 | 微信授权弹窗 |
| tabBar | 自绘组件（角色动态） | 同左 | 同左 | custom-tab-bar |
| 震动反馈 | uni.vibrateShort | 同 API（内部转 UIImpactFeedback） | 同 API | uni.vibrateShort |
| 分享/PDF | 系统分享 | 系统分享 | 系统分享 | 转发/保存 |

差异统一收在组件/utils 层用条件编译处理，业务页面不写平台判断。

## 六、交互与动效规范

| 项 | 规范 |
|---|---|
| 微交互 | 150–300ms；页面转场 ≤300ms；不用 >500ms 动画 |
| 按压反馈 | 按钮/卡片透明度 + 0.97 缩放，100ms 内响应 |
| 打卡成功 | 震动 + 短音效 + 结果页弹性入场 |
| 加载 | >300ms 骨架屏；按钮内 loading 替换文案并禁用 |
| 转场方向 | 进入下级右进、返回左出；底部弹层自下而上 |
| 列表入场 | 不做动画（工具型应用克制为上） |

## 七、状态设计（每页覆盖四态）

| 状态 | 规范 |
|---|---|
| Loading | 骨架屏模拟真实布局 |
| Empty | 一句话说明 + 一个可执行动作 |
| Error | 原因 + "重试"；网络错误与业务错误文案区分 |
| Offline | 全局橙色横幅（非弹窗）；可离线操作放行；不可离线项置灰说明 |

## 八、可访问性与户外适配

- 正文对比度 ≥4.5:1；`text-secondary` 仅用于非关键辅助信息；
- 支持系统字体放大：200% 时行高自适应、关键按钮不截断（小程序端受微信限制尽力适配）；
- 状态三件套（颜色+图标+文字）；
- 触控目标 ≥88px、间距 ≥16px，戴手套可点；
- 横屏：仅签名板、照片查看、扫码取景优化横屏，其余竖屏锁定；
- 刘海/手势条/鸿蒙胶囊：固定底栏与弹层全部加 safe-area 内边距。
