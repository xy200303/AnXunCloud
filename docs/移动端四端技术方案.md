# 移动端四端技术方案（uni-app · Vue3）

> 版本：v2.1 2026-08-11（v2：Flutter → uni-app x；v2.1：uni-app x → 经典 uni-app（Vue3）。纠偏记录：经典 uni-app 自 HBuilderX 4.27 起即可编译鸿蒙 NEXT HAP（JSVM 逻辑层 + 原生渲染桥接，非 WebView），x 的强类型/生态摩擦对本项目收益不抵成本，故定案经典版。四端覆盖不变。）
> 端：Android APP / iOS APP / 鸿蒙 NEXT APP / 微信小程序，一套代码编译四端。
> 配套文档：《移动端四端UI-UX设计方案》。

---

## 1. 背景与目标

PC 后台（Vue3 + Element Plus）与后端（Gin + Gorm + PostgreSQL + Redis）已上线。移动端面向一线巡检员/维修工（打卡、工单）与主管/经理（月报签字）。公司设备环境为 **Android、iOS、鸿蒙 NEXT 混合**，且后续要出微信小程序，因此采用 **uni-app（Vue3）单代码库四端编译**，不再分端独立开发。

## 2. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | uni-app 经典版（HBuilderX 5.x，Vue3 + Vite） | Android/iOS 为 Webview 渲染（成熟稳定）；鸿蒙 NEXT 出 HAP（逻辑层跑鸿蒙 JSVM，UTS 插件桥接原生能力，非 WebView）；微信小程序为微信标准产物 |
| 开发语言 | Vue3 SFC（.vue）+ TypeScript | 团队已有 Vue3 技术栈，零语言迁移成本 |
| 状态管理 | pinia | HBuilderX 内置，与 Web 后台同构 |
| 网络 | uni.request 自封装（拦截器：token 携带、40102 静默刷新、错误归一化） | 四端统一 API，无平台差异 |
| 路由 | uni-app 原生 pages.json 路由 + 登录守卫 | 框架内置，无需三方路由库 |
| 本地存储 | uni.setStorageSync（配置/离线队列）+ keychain/keystore 类 uts 插件（token） | 离线打卡队列 JSON 结构多变，KV 存储足够 |
| 扫码 | uni.scanCode（内置 API） | 四端均有实现 |
| NFC | 插件市场 NFC 插件（同时支持 uni-app：Android NDEF / iOS ISO14443+15693 / 鸿蒙 ohos.nfc） | 见 §5.4；小程序端可用 wx.getNFCAdapter 单独条件编译（一期不做） |
| 定位 | uni.getLocation（内置 API） | GPS 围栏判定 |
| 相机/相册 | uni.chooseImage / camera 组件 | 拍照后 canvas 烧录水印 |
| 手写签名 | canvas 2d 自绘签名板组件 | 与 PC 端 signature_pad 同思路：绘制 → 导出 PNG → 上传 |
| 推送 | 后期：APP 端厂商通道/UniPush；小程序端订阅消息 | 一期端内轮询消息接口 |

样式说明：经典版支持标准 CSS/SCSS（设计令牌落 SCSS 变量 + JS 常量双轨）。组件走"内置组件 + 自研组件库"，不引三方 UI 库（uni-ui 风格与企业定制令牌冲突，自研成本低且可控）。

## 3. 项目结构

uni-app 一套工程编译四端，**不再需要独立的 miniprogram 目录**；四端工程落在 `app/`：

```
app/
├── manifest.json               # 应用配置（各端 appid/权限/模块）
├── pages.json                  # 路由表 + tabBar + 导航样式
├── main.ts / App.vue
├── pages/                      # 页面（按业务分目录）
│   ├── login/
│   ├── tasks/                  # 今日任务、任务明细
│   ├── checkin/                # 扫码、检查项录入、结果页
│   ├── workorders/             # 工单列表/详情/完工
│   ├── reports/                # 待我签、报告详情、签名板页
│   ├── messages/
│   └── profile/                # 我的、签名管理、改密
├── components/                 # 自研组件（SignaturePad、水印相机、状态标签等）
├── services/                   # API 层：request 封装 + 按业务的 api 模块（与后端 DTO 对齐）
├── stores/                     # pinia：auth、offline、message 角标
├── static/                     # 图标/插画（SVG/PNG，禁 emoji 充当图标）
├── utils/                      # 时间、距离、水印、条件编译封装
└── unpackage/                  # 编译产物（gitignore）
```

分层约定：页面（pages）只管渲染交互；业务编排在 stores/services；`services/` 与后端接口一一对应，TS 类型对齐后端 DTO。

条件编译：四端差异统一用 `// #ifdef APP-ANDROID / APP-IOS / APP-HARMONY / MP-WEIXIN` 包裹，集中在 utils/组件层，禁止散落在业务代码里。

## 4. 后端配套（已定稿，不再变更）

- **`/api/app`**（APP 三端共用）：账号密码登录，`ChannelApp` 会话；微信开放平台移动应用登录（code 换 unionid）+ 微信绑定接口（`POST /auth/bind-wechat`，账号密码校验后写入绑定）；注册（`GET /auth/register-config`、`POST /auth/register`，复用 AuthService，手机号必填）；业务路由复用既有 Service（任务/打卡/离线补传/上传/工单/消息/公告）+ 月报签字接口 + 签名配置接口 + `GET /points/by-code/:code`（扫码定位任务：按点位编号查点位与今日任务上下文）。
- **`/api/mp`**（微信小程序）：微信 code 登录（未绑定返回 `ErrWxUnbound` 引导自助绑定）；账号密码登录；注册（同 app 组）；业务接口与 app 组同形同逻辑。
- 两端业务规则（打卡校验/围栏/签字名单/职责分离/一次性签名）零差异，全部在后端既有 Service 内。

## 5. 核心功能设计

### 5.1 登录与注册

**APP 三端（Android/iOS/鸿蒙，`/api/app`）：**
- 账号密码登录为主（`POST /api/app/login`），双令牌自动刷新；
- **微信登录**：走微信开放平台移动应用授权（拉起微信确认 → code 换 unionid）；首次微信登录未绑定系统账号时进入**绑定页**（输账号密码完成绑定，此后微信一键直达）；无微信/未安装时回退账号密码；
- 前置：需微信开放平台"移动应用"AppID（加入发布前清单）。

**微信小程序（`/api/mp`）：**
- **微信一键登录**：`wx.login` code → code2session；已绑定 openid 直接进；未绑定（`ErrWxUnbound`）进入**绑定页**输账号密码自助绑定（不再依赖管理员手工开通）；
- **账号密码登录**：与一键登录并存在登录页（未绑微信/帮他人代登等场景兜底）。

**注册（两端对齐 PC 已有能力）：**
- 登录页展示"注册账号"入口与否由后端开关决定：`GET /api/{app|mp}/auth/register-config`（匿名可读，复用 `auth.register_enabled` 配置）；
- 注册字段：用户名/密码/姓名/**手机号（必填）**，复用 `AuthService.Register` 同一校验（用户名 4–20 位、密码 8–32 位含字母数字、手机号全局唯一）；
- 注册用户无角色无小区，登录后提示"请联系管理员分配角色与所辖小区"（与 PC 注册口径一致）；
- 登录失败限流/账号停用/密码错误提示复用后端错误码。

### 5.2 今日任务（首页）
`GET /api/{app|mp}/tasks/today`；计划卡片 + 点位列表（待巡/已巡/异常三态），下拉刷新，骨架屏加载，逾期标签。

### 5.3 扫码打卡（任务定位器）

扫码/NFC 的首要作用是**快速定位任务**而非可信凭证（可信维度 = 围栏 + 水印照片 + EXIF）。`uni.scanCode` 识别点位裸编号（如 `P000015`）→ 新增 `GET /api/{app|mp}/points/by-code/{code}` 按编号查点位 + 今日任务上下文（防本地缓存过期）→ 直接落到该点位检查项页，无中间确认页。任务详情页内扫码 = 校验 + 定位。无码点位（credential=none）从任务列表直接进入打卡。不提供手动输入编号（防不到场代输）；二维码污损由后台重打或临时切 NFC。扫码统一走系统扫码页（uni.scanCode + onlyFromCamera 禁相册，防照片代扫）；不自绘取景页（plus.barcode 在部分基座挂载不稳定；Ba-Scanner 类付费原生组件 M5 再评估）。

### 5.4 NFC 打卡
- 标签写 **NDEF 文本记录**（内容 = 点位编号），三端均可读；不依赖芯片 UID（iOS 限制 + 部分芯片 UID 随机化）；
- **Android/鸿蒙：全局前台识别**——App 打开期间任何页面贴标签即自动弹对应任务（前台调度监听）；陌生标签静默忽略；打卡表单页改为顶部提示条防打断；App 未打开时贴标签经 NDEF + AAR 直接唤起 App 落到任务页；
- **iOS**：CoreNFC 限制，必须用户点中央"打卡"按钮进扫码页 → 点"改用 NFC 打卡"→ 系统扫描面板 → 贴近读取（苹果安全设计，无法常驻监听，也无法全局识别）；
- 小程序：一期不支持（wx.getNFCAdapter 为微信私有 API，后期按需条件编译）；
- 优先级：NFC 触碰 > 扫码；点位 `credential` 配置决定启用哪些通道，围栏校验照常叠加。

### 5.5 检查项录入 + 拍照水印
按模板逐项录入（正常/异常 + 必拍照片）；拍照后 canvas 烧录水印（时间/点位/GPS/巡检员），上传保留 EXIF 供后端疑似作弊判定；选"异常"备注转必填，提交自动生成异常工单（后端既有逻辑）。

### 5.6 围栏校验
`uni.getLocation` 取定位算距点位距离，超 `fence_radius` 禁提交并提示；弱 GPS 环境（地下车库）配合 NFC/扫码主通道 + 离线补传。

### 5.7 离线打卡（APP 端）
无网时打卡数据（含压缩照片 base64/本地路径）写入本地队列；网络监听恢复后自动 `POST /api/app/checkin/offline-sync`；队列条目带状态（待同步/同步中/失败可重试）。小程序端受微信存储限制（约 10MB），离线只保文字结果、照片受限——一期小程序不承诺离线打卡。

### 5.8 工单
列表（待接单/处理中/已闭环）→ 接单 → 完工上传整改照片 → 后端复核闭环。

### 5.9 月报签字
待我签列表 → 报告详情（汇总 + 三级进度）→ 审批/驳回；未配置签名弹 canvas 签名板现场手写（可选"保存下次使用"），规则与 PC 完全一致（后端同一组接口保证）。

### 5.10 消息与公告
待签/派单/驳回提醒；进入 App 与下拉刷新拉取；角标清除逻辑。推送后期接。

## 7. 打包与发布

| 端 | 工具链 | 分发 | 前置条件 |
|---|---|---|---|
| Android | HBuilderX 云打包/本地打包 APK | 内部群/二维码直接安装 | 自有 keystore 签名，妥善保管 |
| iOS | HBuilderX + Mac/Xcode | TestFlight 或企业证书 | Apple 开发者账号（$99/年）或企业证书 + 一台 Mac（或云构建） |
| 鸿蒙 | HBuilderX + DevEco Studio | 华为应用市场/企业内分发 | 华为开发者账号 + 签名证书 |
| 微信小程序 | HBuilderX 编译 + 微信开发者工具/CI 上传 | 微信公众平台审核发布 | 小程序主体认证（企业） |

微信侧账号体系两类不要混淆：**小程序**用小程序 AppID/Secret（code2session）；**APP 微信登录**用微信开放平台"移动应用"AppID（oauth2 授权换 unionid），两者都需提前申请，且靠 unionid 打通"同人"识别。

环境区分：`services/request` 读取编译期注入的 API 地址（dev 指向 8090，prod 指向正式域名，HTTPS 强制）；按条件编译区分，不打错包。

## 9. 风险与决策记录

- **鸿蒙性能上限**：经典版鸿蒙端为 JSVM + 桥接，性能低于原生编译，但本应用为列表+表单+相机场景，实测余量充足；若未来出现性能瓶颈页面，可单页用 uts 插件下沉原生。
- **鸿蒙插件缺口**：NFC 等插件选已覆盖鸿蒙的插件（插件市场有同时支持 uni-app/鸿蒙的 NFC 插件）；无现成则自写 uts/ArkTS 桥接（工作量可控，点在插件不在框架）。
- **二维码裸编号沿用**（标牌已印制）；代扫风险靠"点位属于当前任务"校验 + 围栏叠加控制；如需更强，后期改动态令牌二维码。
- **推送一期轮询**：待签/派单非秒级需求；厂商推送/订阅消息 M5 后评估。
- **小程序不做离线打卡**：微信存储限制，一期明确不支持并在 UI 上提示。
- **老鸿蒙（HarmonyOS 2-4）**：无需单独处理，直接装 Android APK。
