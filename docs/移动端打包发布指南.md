# 移动端打包发布指南

面向「非专业打包人员」的四端（Android / iOS / 鸿蒙 HarmonyOS NEXT / 微信小程序）打包与发布操作手册。
工程目录：`app/`（uni-app 经典版 Vue3）。所有打包动作都在 **HBuilderX 图形界面**里完成，不需要命令行编译。

> 相关文档：技术方案见《移动端四端技术方案.md》；接口见《接口文档.md》。

---

## 1. 前置准备（只做一次）

### 1.1 DCloud 账号与 HBuilderX

1. 注册 [DCloud 开发者中心](https://dev.dcloud.net.cn/) 账号并完成**实名认证**（云端打包必需）。
2. 安装 **HBuilderX 4.61 及以上**（鸿蒙签名、uni-app 最新基座都需要；App 端建议用最新正式版）。
3. 用 DCloud 账号登录 HBuilderX（菜单：文件 → 登录）。

### 1.2 获取 uni-app appid

1. 打开 <https://dev.dcloud.net.cn/> → 应用管理 → 创建应用，得到 **uni-app AppID**（形如 `__UNI__XXXXXXX`）。
2. 把 appid 填入 `app/manifest.json` 根节点的 `"appid"` 字段（当前为空，不填无法云端打包）。
3. 各端应用标识（建议一次定好，之后不要改）：
   - Android 包名：如 `com.anxuncloud.xunjian`
   - iOS Bundle ID：同上
   - 鸿蒙 bundleName：同上

### 1.3 应用图标与启动图

- 准备 **1024×1024 PNG 图标**（无圆角、无透明通道问题）。
- HBuilderX 中打开 `app/manifest.json` → 可视化界面 →「App 图标配置」→ 选 1024 图自动生成所有尺寸。
- 启动图在同界面「App 启动图配置」；微信小程序的图标在小程序后台设置，与本工程无关。

## 2. Android

### 2.1 生成签名证书（keystore）

电脑装好 JDK 后执行（Windows 用 Git Bash / macOS 用终端）：

```bash
keytool -genkeypair -alias anxun -keyalg RSA -keysize 2048 -validity 36500 \
  -keystore anxun-release.keystore
```

- 按提示输入**证书密码**（务必牢记并备份，丢失=无法更新已上架应用）、姓名、单位、城市等。
- 把 `anxun-release.keystore` 放到安全位置（不要提交进 git 仓库）。

### 2.2 打包

两种方式：

| 方式 | 说明 | 何时用 |
|---|---|---|
| 云端打包（发行 → 原生 App-云打包） | 选「使用自有证书」，填 keystore 别名/密码 | 正式发布 |
| 自定义基座（运行 → 运行到手机 → 制作自定义基座） | 把 NFC 等原生插件编进基座 | 真机调试 NFC |

> **注意：接了 NFC 插件后，标准基座不含该插件，必须打自定义基座或用自有证书云端打包才能用 NFC。**

云打包页面填写：Android 包名、证书别名（`anxun`）、keystore 文件、密码。打出的 APK 直接发测试群安装即可。

### 2.3 安装测试

- APK 传到安卓手机直接安装（首次需允许「安装未知来源应用」）。
- NFC 验证：见 §6.6。

## 3. iOS

### 3.1 账号与证书

1. 注册 **Apple 开发者账号**（99 美元/年，公司主体建议邓白氏编码提前办）。
2. 证书两文件：
   - **p12 私钥证书**：在 Mac 钥匙串/开发者后台生成 `.cer` 后导出 p12；无 Mac 可用 HBuilderX 云打包引导的第三方工具生成（搜「uni-app iOS 证书 无 Mac」按 DCloud 官方教程操作）。
   - **mobileprovision 描述文件**：在 Apple Developer 后台创建 App ID（**务必勾选 NFC Tag Reading 能力**）→ 创建描述文件下载。
3. App Store Connect 里创建应用（Bundle ID 与上面一致）。

### 3.2 打包

HBuilderX → 发行 → 原生 App-云打包 → iOS，填 Bundle ID、上传 p12 与 mobileprovision、输入证书密码。
打出 IPA 后：

- **TestFlight 内测**（推荐先用）：App Store Connect → TestFlight → 上传 IPA → 添加内测人员邮箱，对方装 TestFlight 即可安装。
- **正式上架**：App Store Connect 提交审核。注意：
  - 隐私清单（Privacy Manifest）：新版本 Xcode 打包已由 HBuilderX 处理，如有告警按其提示在 manifest 补充；
  - 权限用途文案（审核必查，本工程已在 manifest 配好）：相机=拍照打卡、定位=打卡围栏校验、NFC=读取点位标签；
  - NFC 能力要求 Apple 后台 App ID 开启 NFC Tag Reading，否则审核/运行会失败。

## 4. 鸿蒙 HarmonyOS NEXT

1. 注册**华为开发者账号**并实名（企业建议企业认证）。
2. 安装 **DevEco Studio 5.1.0.849+**（HBuilderX 4.61+ 配套要求），在 HBuilderX「工具 → 设置 → 运行配置」里填 DevEco Studio 安装路径。
3. 签名（HBuilderX 4.61+ 可直接配置）：
   - 调试：在 DevEco Studio 里登录华为账号**自动申请调试证书**即可；
   - 发布：到 [AGC（AppGallery Connect）](https://developer.huawei.com/consumer/cn/service/josp/agc/) 创建应用 → 生成 **p12 私钥 + csr** → 申请**发布证书 (.cer)** 与 **Profile (.p7b)** → 在 HBuilderX 鸿蒙签名配置里填入。
4. 打包：发行 → 原生 App-云打包/鸿蒙打包，产物为 **HAP/App 包**。
5. 上架华为应用市场：AGC 后台提交审核（同样要填权限用途说明；NFC 权限 `ohos.permission.NFC_TAG` 已在 manifest 声明，NFC 插件自身也带该声明）。

> 鸿蒙工程目录路径不能含中文/特殊字符且不能太长——本仓库路径若过深，可在 `app/.hbuilderx/launch.json` 配 `distPathBuild` 改到短路径（见 uni-app 鸿蒙运行发行文档）。

## 5. 微信小程序

1. **企业主体**注册小程序（个人主体无法商用；认证费 300 元/年）。
2. 拿到小程序 **AppID** 填入 `app/manifest.json` 的 `mp-weixin.appid`（当前为空）。
3. **服务器域名白名单**（小程序后台 → 开发管理 → 服务器域名）：
   - `request 合法域名`：`https://pi.hbuer.com`
   - `uploadFile 合法域名`：同上（照片上传）
   - `downloadFile 合法域名`：同上（图片下载）
   - 只支持 HTTPS、不支持 IP 和端口。
4. 发布流程：HBuilderX → 发行 → 小程序-微信 → 自动调起微信开发者工具 →「上传」→ 小程序后台设为**体验版**给内部试用 → **提交审核** → 审核通过点**发布**。
5. **一期小程序不含 NFC**（wx.getNFCAdapter 为微信私有 API，后期按需单独条件编译）；小程序端中央按钮只有扫码打卡。

## 6. 发版前 Checklist（每次发版逐项过）

- [ ] **6.1 确认 API 域名**：开发/测试与正式包当前均使用 `https://pi.hbuer.com`；App 端为 `https://pi.hbuer.com/api/app`，微信小程序端为 `https://pi.hbuer.com/api/mp`。
- [ ] **6.2 HTTPS 强制**：正式域名必须 HTTPS（iOS ATS 与微信小程序都要求）；后端 `backend/.env.prod` 检查数据库/Redis/密钥/域名等配置。
- [ ] **6.3 版本号递增**：`app/manifest.json` 的 `versionName`（如 1.0.1）与 `versionCode`（整数，如 101）都递增；应用市场靠 versionCode 判新旧。
- [ ] **6.4 隐私政策**：应用市场与小程序后台均需挂隐私政策链接，权限用途（相机/定位/NFC/相册）与 manifest 里文案一致。
- [ ] **6.5 NFC 插件接入**（要用 NFC 打卡时必做）：
  1. HBuilderX 打开本工程 → 插件市场找到「hl-nfccase-uts」（[插件页](https://ext.dcloud.net.cn/plugin?id=26771)）→ **使用 HBuilderX 导入插件**（导入到 `app/uni_modules/`）；试用满意后购买普通授权（29.9 元，一次性买断，绑定正式 appid+包名）；
  2. 接入层 `app/utils/nfc.ts` 已按该插件 API 封装好，**导入即用、无需改代码**；
  3. 运行 → 运行到手机或模拟器 → **制作自定义基座**（Android/iOS 各打一次；鸿蒙直接发行包）；
  4. 真机验证：Android 亮屏任意页面贴近写有点位编号（如 `P000015`）的 NFC 标签 → 自动跳打卡表单；iOS 点中央按钮选「NFC 打卡」→ 系统面板贴近读取。
- [ ] **6.6 NFC 标签与后台数据**：标签用 NDEF 文本写入**点位编号**；后台点位档案的「NFC 卡号」须填该标签的**卡片 UID**（后端按卡号校验，见技术方案 §5.4 与后端 checkin_service.go）。两者录入错一个，NFC 打卡都过不了校验。
- [ ] **6.7 回归四端核心链路**：登录 → 今日任务 → 扫码/NFC 打卡（拍照水印+围栏）→ 异常工单 → 月报签字 → 消息中心。

## 7. 四端功能差异表（与技术方案 §6 对齐）

| 能力 | Android | iOS | 鸿蒙 NEXT | 微信小程序 |
|---|---|---|---|---|
| 账号密码登录 | ✅ | ✅ | ✅ | ✅ |
| 扫码打卡（onlyFromCamera 禁相册） | ✅ | ✅ | ✅ | ✅ |
| NFC 打卡 | ✅ 全局前台识别（贴标签自动弹任务） | ✅ 须用户点按钮触发系统扫描面板 | ✅ 全局前台识别 | ❌ 一期不支持 |
| GPS 围栏 | ✅ | ✅ | ✅ | ✅（精度受微信限制） |
| 相机+水印 | ✅ | ✅ | ✅ | ✅ |
| 离线打卡队列 | ✅ | ✅ | ✅ | ❌ 一期不支持 |
| 手写签名 | ✅ | ✅ | ✅ | ✅（canvas） |
| 打包形态 | APK（keystore 签名） | IPA（p12+mobileprovision） | HAP（p12+csr+profile） | 微信开发者工具上传 |

> iOS 的 NFC 无全局监听是 CoreNFC 平台限制（苹果安全设计），不是实现缺失；Android/鸿蒙「App 未打开时贴标签唤起 App」需要 NDEF+AAR/系统配置，一期未做，App 打开期间的前台识别已覆盖主要场景。
