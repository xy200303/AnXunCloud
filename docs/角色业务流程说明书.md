# 安巡云角色业务流程说明书

> 版本：v1.1.1（2026-09）｜口径：甲方三岗位极简模型 —— **物业经理 / 安全主管 / 巡检员**
> 本文覆盖三个岗位在 PC 管理后台与 App 端的全部业务链条与边界规则，供实施、培训与验收使用。

---

## 一、角色总览

| 角色 | 岗位编码 | 主要端 | 核心职责 |
|---|---|---|---|
| 巡检员 | `field_staff` | App | 执行巡检任务、扫码/定位打卡、逐项检查拍照、异常上报、设备维保登记 |
| 安全主管 | （汇报线槽位 `patrol_report_line`） | App + PC | 审核打卡记录、抽查复核、报告链「主管审核」签字 |
| 物业经理 | `project_admin`（复核槽位 `project_review`） | PC + App | 点位/计划/模板/人员配置、维保确认、报告生成与复核、台账处置 |
| 租户管理员 | `tenant_admin` | PC | 租户级用户/角色/字典/公告（一般由物业经理兼任） |
| 平台管理员 | 内置超管 | PC | 租户开通与平台级配置（运营方使用，甲方不感知） |

**关键机制——职责槽位**：审批链不绑定具体人，而是绑定「槽位」（如汇报线、项目复核），候选人由小区岗位编制实时推导。一人多岗（如严勇既是主管又是经理）自动出现在多个环节，互不影响。

**数据权限总原则**：
- 巡检员（self 档）只能看/办「与自己相关」的数据：自己的任务、自己的打卡、自己需签的报告。
- 主管/经理按小区数据范围可见；**可见 ≠ 可审**——能否审核由审批链环节名单决定。
- 配置审批链时系统会逐人校验数据可见性，不可见的人在配置界面标红「（不可见）」并给出警示，从源头杜绝「能审看不到、看到不能审」。
- 在途单自愈：审核中环节的候选人名单被改空时，自动回落到汇报线名单，不会出现「没人能审」的死单。

## 二、巡检员（App 端）

### 2.1 登录与首页

- 手机号 + 密码登录（App/小程序共用一套会话，token 两端通用）；连续失败 10 次锁 10 分钟。
- 登录后进入「今日任务」：列出今天名下的全部巡检任务（待办/进行中/已完成）。
- 底部主要入口：今日任务、消息、我的；右上角扫码直达打卡。

### 2.2 领取与执行巡检任务

任务由「计划任务」按周期自动生成（无需巡检员手工领单）。任务卡片显示：点位总数、已完成数、任务状态。

**状态机**：`待开始 → 进行中 → 已完成`；过期未完成的标记「已逾期」，逾期任务仍可打卡补做（不阻断）。

### 2.3 打卡（核心链路）

进入任务详情 → 逐点位打卡。每个点位支持三种凭证方式，按点位配置决定：

| 方式 | 操作 | 边界规则 |
|---|---|---|
| 扫码 `qrcode` | 扫点位二维码 | 码值须与点位档案精确匹配 |
| NFC `nfc` | 手机贴 NFC 标签 | UID 精确匹配 |
| 围栏 `fence` | 到达点位附近直接打卡 | 仅「强制围栏」点位要求有效定位；**坐标可选机制**：点位未录坐标或手机定位失败（0,0）时跳过距离校验，不阻断打卡 |

**打卡提交的服务端处理顺序**（全部自动，巡检员无感知）：
1. **防重与幂等**：5 秒防双击锁 + 客户端 UUID 幂等——弱网重试/重复点击不会产生重复记录；同一任务同一点位未锁定时再次提交 = **覆盖修改**（旧记录标记被替代，进度不重复计数）。
2. **归属校验**：任务必须是本人的、点位必须在任务路线快照内，否则拒绝。
3. **逐项检查项**：按点位绑定的检查项模板逐项给结果；必拍项必须拍照；不合格项至少 1 张处置照片。照片服务端校验 EXIF 拍摄时间（默认偏差 ≤300 秒），超偏差记入「疑似作弊」（不阻断，供审核参考）。
4. **设备合成项**（点位绑定了设备台账时自动追加，无需手填）：
   - 临期（默认 30 天内到期）→ 提示正常；
   - **首次逾期 → 判异常**；持续逾期 → 标「催办中」不再重复产异常；
   - **已过报废日 → 每次都判异常**（使用报废设备即违规）；
   - **标签缺失 → 判异常转维保处置**（甲方口径：算异常维保）。
5. **AI 审核**（开启时）：照片质量不达标 → 直接拒绝并提示重拍（默认上限 3 次，用尽后可「强制提交」转人工）；内容识别结论分为通过/存疑/不通过。
6. **审批链路由**：见 §五。
7. **落库与后置**：记录+逐项照片+维保流水同一事务写入；成功后自动给照片烧录水印（点位/时间/坐标/姓名）。

**异常打卡**：结果选「异常」时**必须填写异常描述**；任一检查项选「上报待处理」→ 记录强制转人工审核并通知审核人。

### 2.4 离线打卡

- 弱网/无网时打卡数据存入本地离线队列，网络恢复后自动补传（补传记录类型统一记 `offline`）。
- 离线已暂存的点位在任务列表标「**离线待补传**」，补传完成前不允许重复进入打卡（防止覆盖混乱）。
- 离线补传不走同步 AI（记录标「未经 AI 识别，待复核」转人工）。

### 2.5 被打回（驳回）后

- 消息中心收到驳回通知（含驳回理由）→ 点进「打卡记录」→ **可直接修改重报**（重新拍照/改结论再次提交，走覆盖修改）。
- 已归档锁定的记录（报告归档后）不可再改，服务端返回明确提示。

### 2.6 设备维保登记（巡检员发起）

入口：点位打卡页的设备项、设备台账页、「+」快捷入口。

- 到期/临期设备项上直接出现「已完成维保？登记」入口；
- 操作：**拍新标签照片** → 系统自动 AI 核验（识别标签日期与台账比对）→ 可信的直接生效，存疑/失败的转物业经理确认；
- **标签磨损无法辨认**：勾选「标签缺失」免填日期，拍设备本体照片提交 → 经理确认后设备打上「标签缺失」标，此后每次打卡该设备自动判异常，直到补签完成；
- 「我的提交」页可查看自己提交过的全部维保登记及处理状态。

### 2.7 巡检员边界速查

- 看不到别人的任务和打卡；报告列表的「全部」tab 也只含与自己相关的报告。
- 任务未完成不影响第二天任务生成；逾期任务会出现在任务监控里被主管看到。
- 修改个人资料时手机号可留空（留空 = 不修改）。

## 三、安全主管（App 为主，PC 可查）

### 3.1 打卡审核（汇报线职责）

入口：App「审核」待办 / 消息中心审核通知深链。

- 待审核列表只显示**当前环节轮到且名单含自己**的记录；
- 详情页可见：逐项检查结果+照片、AI 审核结论、疑似作弊标记、设备合成项判定；
- 操作：**通过 / 驳回**（驳回须填理由，巡检员收到通知并可修改重报）；
- 「已通过 / 已驳回」tab 可回看自己的审核历史。

**边界**：
- 名单为空的环节系统已自动跳过或回落汇报线，主管不会遇到"点了审核却提示无权限"的死单；
- 若某条记录能看到但没有审核按钮（显示「待授权人处理」），说明当前环节名单不含自己——这是「可见≠可审」的正常表现；
- 主管一人多岗时（兼经理），不同环节的审核都汇在同一个待办里，逐条处理即可。

### 3.2 抽查复核

- 设备日期标签抽查（默认每月按 2% 确定性哈希抽取，长期未验证的设备概率翻倍）命中的异常项，与打卡审核同一待办入口处理；
- 抽查比例/开关由经理在系统参数配置（`equipment.spotcheck_ratio` 等），主管无需配置。

### 3.3 报告签字

- 月度报告到达「主管审核」节点时出现在 App「月度报告 → 等待签字」；
- 点开可看审核链全貌与「查看完整报告 PDF」；
- 签字 = 通过；驳回则报告退回生成环节。

### 3.4 PC 端

巡检记录、任务监控、统计分析对主管开放（按小区数据范围），用于日常督查与月底核对，无配置类操作。

## 四、物业经理（PC 为主，App 审批）

### 4.1 基础配置（开业一次性 + 日常维护）

**① 点位设置**（PC 巡检管理 → 点位管理；App 管理端也可编辑）：
- 新建点位：名称、所属小区/楼栋、巡查类型（消防/设备/环境等）、**检查项模板（必选）**、打卡方式（二维码/NFC/围栏半径）、坐标（地图拾取，可选）；
- 二维码/NFC：系统生成二维码可打印张贴；NFC 录 UID；
- **边界**：坐标可不录（不录则该点位不参与距离校验）；模板更换只影响之后的打卡，历史记录按当时快照保留。

**② 检查项模板**（巡检管理 → 检查项模板）：逐项定义名称、要求、是否必拍。设备台账合成项由系统自动追加，无需进模板。

**③ 计划任务**（巡检管理 → 计划任务）：
- 按周期（每日/每周/每月）+ 点位范围 + 执行人生成任务；
- 月度周期性抽查计划同样在此配置（抽查比例等参数与巡检报告计划同套配置体验）；
- 设备类计划按比例抽取设备合成抽查项。

**④ 岗位编制与审批链**（小区管理 → 岗位编制）：
- 编制名单：把用户挂到小区的岗位（巡检员/主管/经理），一人可多岗；
- 三条流程可视化编排：**打卡审批流程 / 维保审核流程 / 报告签字流程**；
- 每个环节可设「任一签署」或「全部签署」；空环节保存即自动跳过；
- **配置时校验**：候选人数据权限不可见会标红警示——保证「能审的一定能看到」；
- 空流程 = 该类单据默认直接通过/归档。

### 4.2 维保确认（经理核心日常）

入口：App 消息/待办 或 PC 设备台账。

- 巡检员提交的维保登记到达经理：看新标签照片 + AI 核验结论 → **确认**（台账有效期自动更新，设备恢复正常）或 **驳回**（退回巡检员重新登记）；
- **标签缺失处置**：确认后设备打标「标签缺失」→ 该设备退出到期催办，但每次打卡自动判异常（异常维保口径），直到巡检员完成补签登记、经理再次确认后清除；
- 设备报废：台账登记报废日期，过期后打卡每次判异常强制更换。

### 4.3 报告生成与复核

- **手动生成**（App/PC「生成报告」）：选小区 + 月份 + 报告类型（综合/单类型）+ 明细范围（全部点位/仅异常点位），审核链按小区配置自动带出，生成时可微调候选人；
- **自动生成**：报告计划按周期自动生成并进入签字流程；
- 报告链默认三环节：巡检员确认（全部签署）→ 主管审核（任一）→ 项目复核（任一，经理在此签字）；
- 全部签完 → 自动归档并生成正式 PDF；**归档后关联打卡记录锁定，不可再改**；
- App 报告页四个 tab：等待签字 / 进行中 / 已完成 / **全部**（数据权限内全部报告，含在途——解决"生成人不在审核链时看不到在途报告"）。

### 4.4 台账与监控

- 设备台账：按状态筛选（正常/临期/逾期/标签缺失/报废），支持导入导出；
- 任务监控：实时看各任务进度、逾期任务、漏检点位；
- 巡检记录：全部打卡记录查询/导出，待审核记录按权限显示操作按钮；
- 统计分析：巡查完成率、异常分布、人员绩效。

### 4.5 经理边界速查

- 审批链改动只影响**新产生的单据**，在途单按提交时的流程快照审完（快照固化）；
- 把某环节候选人改空 → 该环节自动跳过并通知在途单的当前审核人；改空在途单当前环节 → 自动回落汇报线，不死单；
- 系统参数（AI 开关、抽查比例、到期阈值等）在 系统管理 → 参数配置，低频生效，无需重启。

## 五、审批链统一模型（三类单据共用）

| 流程 | 编码 | 默认配置 | 说明 |
|---|---|---|---|
| 打卡审批 | `checkin_review` | 空流程（默认通过） | 配了环节才人工审；可插 AI 环节做闸门 |
| 维保审核 | `maint_review` | 看 `equipment.ai_auto_confirm`：开=AI 闸门，关=经理确认 | 甲方当前口径：一律经理确认 |
| 报告签字 | `report_review` | 巡检员确认（全部）→ 主管审核（任一）→ 项目复核（任一） | 签完自动归档出 PDF |

**通用规则**：
1. **环节模式**：任一签署（名单任一人签即过）/ 全部签署（全员签完才过）；
2. **AI 闸门**：AI 环节按结论三分支——通过直接流转、存疑转人工、不通过打回；AI 不可用（超时/未配置）自动降级转人工，绝不卡单；
3. **空名单跳过**：候选人解析为空的环节自动跳过并通知相关人员；
4. **流程快照**：单据提交时固化流程，中途改配置不影响在途单；
5. **在途自愈**：当前人工环节名单被改空 → 从该环节起回落汇报线继续走；
6. **通知**：到节点通知候选人、驳回通知提交人、跳过环节通知知会人——均走消息中心（App 红点 + 个推）。

## 六、设备到期判定状态机

```
正常(normal) ──到期前 warn_days 天内──> 临期(warning,提示+出现维保登记入口)
临期/正常 ──到期日已过──> 逾期(overdue)
    ├─ 首次逾期打卡：判异常，转审核
    ├─ 持续逾期：标「催办中」，不重复产异常
    └─ 登记维保待确认：标「待确认」，暂停催办
任意状态 ──经理确认标签缺失──> 标签缺失(label_missing)
    ├─ 豁免到期催办
    └─ 每次打卡判异常（异常维保口径）直至补签确认清除
任意状态 ──报废日已过──> 视同逾期，且每次打卡都判异常（不去重）
无日期数据(no_data) ──> 打卡提示「台账缺失待补录」，不判异常
```

相关参数：`equipment.expire_warn_days`(30)、`equipment.expire_check_time`(08:00 每日扫描提醒)、`equipment.overdue_remind_interval_days`(7)、`equipment.spotcheck_enabled` / `spotcheck_ratio`(2%) / `spotcheck_salt`。

## 七、异常与边界速查表

| 场景 | 系统行为 |
|---|---|
| 弱网双击/重试打卡 | UUID 幂等返回已有记录，不产生重复 |
| 同点位未锁定再次提交 | 覆盖修改，旧记录留痕（superseded_by） |
| 报告归档后想改打卡 | 拒绝（记录已锁定），提示联系经理 |
| 手机定位失败/点位无坐标 | 跳过距离校验，可正常打卡（强制围栏点位除外） |
| AI 服务超时/未配置 | 自动降级：记录转人工审核，不卡单 |
| 审批环节候选人全部被删 | 在途单自动回落汇报线；新单该环节自动跳过 |
| 能看到记录但无审核按钮 | 正常：当前环节名单不含你（可见≠可审） |
| 审核人看不到自己名下的单 | 不可能出现：配置时已做可见性校验并标红拦截 |
| 离线打卡后又在别处提交 | 离线点位标「待补传」拦截重复进入；补传按到达顺序幂等落库 |
| 强制提交（AI 重拍超限） | 落库转人工复核，记录标「强制提交」 |
| 账号停用/租户停用 | 登录拒绝并给出明确文案 |
