## 11. 重构实施记录：触发模型与聚合方式（v1.6，2026-09 完成）

用户拍板重构一期已完成的检查项集成（重构前未提交 git、无生产数据）。§10 中「检查项集成」小节的模板项触发与取最差聚合口径已被本节取代。

**变化一：触发模型「模板内置项」→「绑定即启用」**

- 任务详情组装直接按点位查绑定在用设备注入合成检查项，模板是否配置完全无关（mp_service.injectEquipmentItems）
- 后台模板编辑器撤下「台账有效期」「日期标签抽查（二期）」两个选项；template_service 保存/编辑模板项时拒绝这两种类型（40001 明确提示）；NormalizeJudgeType 白名单保留（历史打卡快照识别用）

**变化二：一点多具「取最差聚合」→「逐台独立」**

- eqsvc 新增逐台纯函数 JudgeDevice/JudgeDevices/DeviceJudgeSubmit/SyntheticItemName（AggregateAutoJudge/AutoJudgeSubmit 已删除），每台设备独立状态（normal/warning/overdue/no_data + has_pending_register 展示态）
- 任务详情逐台注入合成项：name=「设备维保·名称(编号)」、judge_config 携 {equipment_id, equipment_no} 快照、photo_required=none、auto_judge 挂单设备判定
- 打卡提交：客户端不提交合成项（App 只读），服务端按点位实时逐台判定自动追加快照（每台一条 checkin_record_item）；任何一台首次逾期 → 该项异常 + 记录级强制 abnormal 转人工审核
- 逾期去重改按 equipment_id 键控（OverdueReportedSet：查该设备既有的逾期异常快照）：首次产异常、持续逾期只标「催办中」、pending 登记标「已登记维保待确认」，不同设备互不影响
- 登记入口逐台（临期/逾期/缺数据各自的合成项带登记/补录按钮）
- App 端 form.vue / quick.vue / QuickItemCard / api.ts / checkinWizard.ts 同步适配（合成项只读渲染 + 提交时跳过 + 一键全合格不覆盖）

| 场景 | 结果 |

| 一点两具：A 逾期 39 天 + B 正常 | 任务详情两条独立合成项（A overdue/show_register=true、B normal/false）；提交后 checkin_record_item 两条独立快照（A pass=false、B pass=true），记录 result=abnormal + audit_status=pending，remark 自动带逾期备注 |
